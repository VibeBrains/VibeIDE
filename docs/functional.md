# Возможности VibeIDE

Полный каталог функциональности VibeIDE — что умеет редактор и его AI-ядро. Документ
организован по темам, без привязки к номерам версий: здесь — «что есть», а история
изменений по релизам живёт в [GitHub Releases](https://github.com/VibeBrains/VibeIDE/releases).

> Новое в каждом релизе попадает сюда автоматически — при сборке ченджлога секция «✨ Новое»
> сливается в соответствующую тему этого файла (см. `CLAUDE.md` → «Версионирование»).

---

## 🧠 AI-ядро

- **Роутер LLM-провайдеров** — OpenAI, Anthropic, Gemini, Mistral, Ollama и другие. Разные модели для разных задач (чат, автокомплит, inline-правки).
- **Свои LLM-провайдеры через `.vibe/providers.json`** — добавить, переопределить или выключить провайдера и модели **без пересборки IDE**. Работают как встроенные: карточка в «Облачных провайдерах», проверка валидности ключа (✓/✗), источник ключа (`.vibe/.env` или введён в IDE), живой каталог моделей из `<baseURL>/v1/models`, вкладка «Модели» с тумблерами. Возможности модели (vision, reasoning, формат инструментов, размер контекста) берутся из базы знаний так же, как у встроенных. Патч встроенных по `id`, клон через `extends`, порядок через `order` + IntelliSense и диагностика в редакторе.
- **Локальные модели (Ollama, LM Studio)** — автодетект и онбординг встроены.
- **Автокомплит FIM (Fill-in-the-Middle)** — встроенный, без дополнительных расширений.
- **Инлайн-редактирование кода** (Ctrl+K), детекция ошибок и код-ревью силами выбранной модели. Ctrl+K понимает слэш-команды `/doc`, `/refactor`, `/tests`, `/explain`, `/fix`.
- **Индексация кодовой базы и семантический поиск (RAG)** по всему репозиторию.
- **Image QA** — анализ скриншотов и диаграмм как часть контекста (с privacy-гейтом и лимитом размера).

## 🤖 Агенты и автопилот

- **Мультиагентная оркестрация** с территориальными блокировками — агенты не мешают друг другу.
- **Персистентные планы** — план агента переживает перезапуск IDE и продолжается с места остановки; финал плана записывается на диск, без ложного «Continue Plan» на каждом старте. **План не паузится на синонимах инструментов:** `edit_file` ↔ `rewrite_file` и `run_terminal_command` ↔ `run_command` считаются одним классом («правки» / «терминал»), а при включённом автопилоте план продолжает выполнение даже при инструменте вне списка шага (с инфо-уведомлением; строгость настраивается `vibeide.plans.toolDriftPause`: always / manual-only / never). Если шаг всё же на паузе — у поля ввода появляется чип «⏸ План на паузе — возобновить» (плюс кнопка-стрелка к карточке плана) — не нужно листать чат вверх.
- **Skills system** — переиспользуемые AI-поведения на уровне проекта; `/skill:NAME` выгружается в контекст целиком.
- **Автопилот** — агент доводит шаг до конца сам, без выпрашивания «продолжить»; на длинной серии шагов делает чекпоинт-вопрос «продолжать?». Завершает ход через `vibe_complete` вместо текстового «готово» в цикле.
- **Детектор петель** — автоматически останавливает зациклившегося агента.
- **Dead man's switch** — защитный механизм для долгих автономных задач.
- **Самовосстановление** — IDE пережидает лимиты провайдера, перезапускает зависшие ходы и переключает формат инструментов (native ↔ XML) на лету.
- **Роли-субагенты (Vibe Agents)** — набор ролей (планировщик, дизайнер, фронтенд/бэкенд, ревьюер, QA, security) с правами на роль: ревьюер и security работают только на чтение, без записи. Каждая роль исполняется настоящим изолированным агентом: свой транскрипт, **независимый токен-бюджет и своё контекстное окно** (настройка `vibeide.subagent.maxTokens`, не зависит от расхода основной сессии; учёт — по реальным данным провайдера, кэшированная история повторно не тарифицируется; токены и контекст роли считаются отдельно и НЕ приписываются к индикаторам «Сессия»/«Контекст» основного треда), инструменты строго по списку роли, а перед записью файлов или запуском команд роль спрашивает разрешение — молча ничего не меняет (гейты одобрения **наследуются от основного агента, ровно те же**: при включённом автопилоте роль выполняет инструменты без запроса, как и основной агент; иначе — по per-type авто-одобрению или с диалогом); родитель получает только компактный итог; отменённая роль немедленно прекращает работу, включая уже отправленный запрос к модели. **Модель на роль:** в настройках (секция «Роли агентов») каждой роли можно назначить свою модель — read-only роли выгодно сажать на лёгкую (дешевле и быстрее, а писать код им всё равно запрещено); по умолчанию роли работают на модели чата. Запустить команду ролей можно прямо из чата — кнопкой **🎭 в панели инпута** (между скрепкой-прикрепить и «продолжить»): она открывает модальное окно с полем «Промпт для субагента» (а не тонкое поле палитры), **инпутами переопределения лимитов на этот прогон** — шаги, токены, время (с), авто-резюм — и кнопкой **«🎭 Роли»**, открывающей выбор модели на каждую роль прямо из этого окна (то же, что секция «Роли агентов» в настройках); дефолты подтягиваются из конфига, изменённое поле переопределяет только текущий запуск (под автопилотом лимиты всё равно авто-продлеваются — оверрайд задаёт базу). Команда «Показать маршрут ролей» подсказывает, кто и в каком порядке возьмётся за задачу, а «Выполнить маршрут ролей» — запускает команду ролей по задаче: этапы идут по порядку (роли внутри этапа — параллельно), прогресс виден в статус-баре субагентов (клик — отменить роль) **и прямо в чате**: пока роль работает, в треде крутится живой индикатор «🧩 Роль «…» работает… (шаг 12/60 · ~24k / 400k · ⏱ 2:34)» — показывает все три лимита роли: шаги, токены (оба против своей квоты) и обратный отсчёт времени; рядом кнопка ⚙ открывает настройки субагентов, а по завершении остаётся компактный итог роли (успех/остановка/пропуск с токенами и ≈$); всё это включается настройкой `vibeide.subagent.chatNotices`; по завершении **сводный отчёт приходит сообщением в чат запуска** — с итогами каждой роли, токенами, моделью и примерной стоимостью в $; security подключается автоматически на чувствительных темах (OAuth, платежи, секреты). **Лимиты на прогон** роли настраиваются: шаги — `vibeide.subagent.maxSteps` (дефолт 60), время — `vibeide.subagent.maxWallClockSec` (дефолт 300 с), токены — `vibeide.subagent.maxTokens`; для слабых моделей, жгущих шаги/время на чтении, поднимайте. **Под автопилотом ресурсные лимиты роли (шаги/время/токены) авто-продлеваются**, и роль НЕ встаёт на паузу — идёт до готовности или отмены, как основной агент под автопилотом (никаких новых стопов от субагентов); лимиты снова вступают в силу, если выключить автопилот. **Сохранение прогресса (durable handoff)** действует в ручном режиме: роль, упёршаяся в лимит, не проваливается — частичный результат сохраняется (переживает даже перезапуск IDE), и роль автоматически продолжается с места остановки с увеличенным бюджетом; число авто-продолжений задаётся пилюлей **«субпин.»** прямо в тулбаре чата (рядом с «подпин.», ключ `vibeide.subagent.maxResumes`; субагентный аналог авто-нуджа основного агента), плюс `vibeide.subagent.resumeBudgetFactor` для роста бюджета; когда авто-продолжения исчерпаны, **в самом чате** появляется кнопка **«Продолжить роль»** (там же, где чатовская «Продолжить») со счётчиком ожидающих ролей — клик открывает выбор роли и продолжает её вручную с сохранённого места; отказы пользователя уважаются: отменённая роль и роль с многократно отклонёнными инструментами автоматически не перезапускаются. **Разбор по картинке (vision-маршрутизация):** если к маршруту ролей приложено изображение (скрепка «Прикрепить» в окне маршрута принимает картинки и PDF — плюс перетаскивание и вставка из буфера), маршрут получает ведущий vision-этап — картинка уходит роли-аналитику (по умолчанию дизайнеру), а её текстовый разбор передаётся кодерам по хендоффу; если у роли-получателя выбрана модель без vision — раннер автоматически подставляет vision-совместимую из включённых и предупреждает (жёсткая гарантия), а дизайнер по умолчанию тянет модель из vision-совместимых (флаг `receivesImages` на пресете, бейдж «🖼 картинки» в окне «Роли»). **Авто-разведчик на «продолжи»:** на continuation-запросах («продолжи»/«дальше»/«доделай») перед основным ходом запускается read-only разведчик (роль explore) — он смотрит последние правки (чекпоинты) и незакрытый план и постит в чат карточку с зацепками (файл — что недоделано) и гипотезой задачи, а вы подтверждаете «Продолжить / Уточнить / Отмена»; при высокой уверенности (`vibeide.subagent.scoutAutoProceedConfidence`) гейт пропускается и ход идёт сразу; если в треде уже есть живой незакрытый план — разведка пропускается (контекст уже есть); включается настройкой `vibeide.subagent.autoScout` (по умолчанию вкл), а кнопка-тумблер «следы» у поля ввода форсит разведку для любого запроса.
- **Упрощённый / полный вид панели чата** — иконка-переключатель в шапке (Command Center, рядом с тумблером неона; глаз = полный, перечёркнутый глаз = упрощённый; настройка `vibeide.chat.simplifiedControls`, по умолчанию упрощённый). В упрощённом виде под полем ввода остаются только «Режим» и «Модель», а остальные ручки (обучение, автопилот, рекурсия ссылок, сброс сессии, лимиты итераций/нуджей/подтверждений/резюмов, рассуждение), строка контекста и панель быстрых действий скрыты (значения сохраняются), при этом автопилот и рекурсия по ссылкам принудительно включены — чтобы простого пользователя не пугало обилие настроек. Кнопки маршрута ролей и разведки живут рядом с выбором модели и остаются доступны в обоих видах.
- **Дисциплина минимализма кода** — режимы `off`/`лайт`/`фулл`/`ультра` (настройка «Минимализм агента» в разделе «Инструкции для ИИ» или ключ `vibeide.global.minimalismMode`). Лайт — «сначала переиспользуй»: существующий код → stdlib → платформа → установленные зависимости, без спекулятивных абстракций (YAGNI). Фулл — полная лестница из 7 ступеней перед написанием любого нового кода. Ультра — плюс требование минимального ревьюабельного диффа: агент оспаривает избыточные требования и явно перечисляет, что сознательно не реализовал. Валидация, обработка ошибок, безопасность и доступность не урезаются ни в одном режиме; правила проекта (`.vibe/rules`, `AGENTS.md`) приоритетнее дисциплины. Меньше кода — меньше токенов и быстрее ход.
- **Делит-лист и леджер упрощений** — слэш-команда `/simplify` в чате прогоняет текущий git diff по лестнице минимализма и возвращает делит-лист (файл:строка, что удалить/упростить, почему, экономия строк), ничего не меняя в файлах. Сознательно отложенные упрощения помечаются в коде комментарием `vibe-later: <что и почему>` (агент делает это сам в режимах фулл/ультра); команда палитры «Леджер отложенных упрощений (vibe-later)» собирает все маркеры воркспейса в markdown-отчёт с кликабельными `путь:строка`.
- **Spec-First и панель «Спеки»** — существенная фича описывается спекой до кода: `docs/specs/<id>/PRODUCT.md` (поведение нумерованными инвариантами) и `TECH.md` (реализация, заземлённая в коде). Процесс ведут засеянные скиллы (`spec-driven-implementation` → `write-product-spec` → `write-tech-spec` → `implement-specs`), а правило-триггер `spec-first.mdc` включает его рефлекторно для крупных задач (мелочь — без церемонии; не блокирует, приоритет запроса пользователя выше). Отдельная **панель «Спеки»** в activity bar показывает все спеки воркспейса (каталог `docs/specs/`, настраивается ключом `vibeide.specsPanel.root`). Строка спеки — **одна линия**: имя + компактный ряд пилюль **`[P][T][S]`** (`P`, `T`, затем `S`) (фиксированной ширины, выровнены по всем строкам). **`S`** — статус, передаётся **цветом** (серый = черновик, синий = утверждена, зелёный = реализована; при наведении — тултип с названием, задержка 1 с). Статус читается из фронтматтера `status:` в PRODUCT.md и проходит жизненный цикл `черновик` (`draft`, спека пишется) → `утверждена` (`approved`, согласована — только тогда доступны «Реализовать спеку» и дрейф-контроль) → `реализована` (`implemented`, фича собрана и проверена; ставит скилл `implement-specs`). Сменить статус — **правым кликом по пилюле `S`**: выпадающий список «Черновик / Утверждена / Реализована», текущий помечен галочкой, каждый пункт окрашен в цвет своего статуса (та же азбука, что у пилюли). Переходы не ограничены, включая откат — это ваш документ, а не машина состояний. Тот же результат даёт правка строки `status:` руками (и её же ведут скиллы). **`P`** = PRODUCT.md (поведение), **`T`** = TECH.md (реализация): заполненная пилюля = файл есть (клик открывает), тусклая пунктирная `T` = TECH ещё нет (клик **создаёт** его). У всех пилюль — тултипы с задержкой 1 с. Клик по строке открывает PRODUCT (или TECH). Контекст-меню (ПКМ) — открыть PRODUCT/TECH, создать TECH.md, реализовать спеку (для `approved`), показать в проводнике, удалить спеку (в корзину, с подтверждением). Панель обновляется на изменения файлов. Создать спеку можно двумя путями: **«Спека из задачи»** — открывает брендовую модалку (не строку-поиск) с многострочным полем и скрепкой (📎): можно приложить макеты/скриншоты (картинки уходят в vision-разбор) и ТЗ (PDF — текст инлайнится в промпт); агент пишет `PRODUCT.md` по скиллу `write-product-spec` в `docs/specs/<id>/`. Эта же команда продублирована в **меню «мозга»** (иконка VibeIDE в командном центре заголовка) — модалку можно вызвать из любого места, не переключаясь на панель «Спеки». Кнопка **«?»** в заголовке панели (и ссылка «Как это работает» на пустой панели) открывает встроенное руководство — весь маршрут работы со спеками: создать → агент пишет PRODUCT.md → **вы проверяете и ставите `approved`** → при необходимости TECH.md → «Реализовать спеку» → агент доводит до `implemented`; там же легенда пилюль и настройка дрейфа. Справка не дублирует документацию, а **собирается из неё при сборке** (`docs/manuals/specsWorkflow.md`) — то есть всегда описывает актуальное поведение и не может разойтись с репозиторием. **«Новая спека (пустая)»** — модалка с одним полем (id + валидатор) → создаёт `docs/specs/<id>/PRODUCT.md` (со `status: draft`) из минимальной заготовки. Для утверждённой спеки (`status: approved`) в контекст-меню появляется **«Реализовать спеку»**: привязывает тред к спеке и запускает `implement-specs` в чате. **Дрейф-от-спеки:** пока привязанный тред реализует спеку, правка файла вне объявленной во фронтматтере области `scope:` (globs) ставит реализацию на паузу — тем же чипом «⏸ На паузе», что и дрейф плана (настройка `vibeide.specs.driftPause`: always / manual-only / never; по умолчанию не мешает под автопилотом). Срабатывает только при явной привязке и только для правок; спека без `scope` границ не задаёт.
- **Окружение агентов `.vibe` и его обновление из релиза** — правила, скиллы, промпты и примеры конфигов засеваются в `.vibe/` при открытии проекта из набора, встроенного в релиз. Файлы принадлежат пользователю: существующий файл IDE **никогда не перезаписывает** сама, недостающие — дописывает. Отсюда следствие: файл, изменённый в новом релизе, остаётся у вас в старой редакции. Две команды (меню «мозга» и палитра) закрывают это: **«Показать новое в окружении из релиза»** — отчёт без единой правки, и **«Обновить окружение из релиза»** — отчёт плюс действия. Отчёт различает **новое в релизе**, **релиз обновил** (вы файл не трогали → обновление безопасно), **разошлись обе стороны** (правили и вы, и релиз), **не сверялось** (окружение старше учёта) и **ваши файлы** (отличаются по вашему решению, релиз их не менял). Действия: **«Обновить безопасно»** (добавить новое + обновить незатронутое, потерять правки невозможно), **«Показать различия»** (дифф «версия релиза ⇄ ваша» в штатном редакторе — слияние руками), **«Оставить своё»** (зафиксировать свою версию как желаемую) и **«Заменить всё»** (сброс к релизу с подтверждением; единственный путь починить файл, который правили и вы, и релиз). Состояние считается по `.vibe/.defaults.lock.json` — точке последней сверки, — поэтому IDE отличает «релиз обновился» от «вы правили», а **уведомление при открытии приходит только когда сдвинулся релиз**: настроенные вами файлы поводом не считаются (иначе напоминало бы о ваших же правках каждый запуск). Отключается ключом `vibeide.environment.notifyOnRelease`. Руководство — `docs/manuals/vibeEnvironment.md`.

## 🌐 Vibe Server — локальный предпросмотр

- **Панель «Vibe Server»** поднимает локальный сервер и показывает результат прямо в IDE (встроенный браузер) или во внешнем браузере — на выбор.
- **Три режима под проект:** статический сайт (HTML/CSS/JS), **dev-сервер фреймворка** (Vite/Next/React/Vue/Angular — запускается ваш `npm run dev` и берётся его URL) и **Docker-окружение** (`docker compose` / Dockerfile — кнопкой «Поднять окружение»).
- **Живая перезагрузка:** правка файла сразу обновляет превью; CSS применяется без перезагрузки страницы (состояние и прокрутка сохраняются).
- **Встроенный браузер** с адресной строкой, навигацией, размерами под телефон/планшет/десктоп и поворотом; несколько вкладок и синхронизация прокрутки. **Cookie-логин на превью работает:** пока вкладка показывает localhost-сайт, его куки автоматически дополняются `SameSite=None; Secure` — иначе браузер отбрасывал бы их в cross-site iframe и авторизация молча ломалась; действует только на loopback и только при открытом превью, отключается `vibeide.vibeServer.cookieCompat`.
- **Превью на телефоне** — адрес в локальной сети (LAN) и **QR-код** для быстрого открытия.
- **Ошибки превью в чат** — ошибки консоли и проваленные сетевые запросы одной командой уходят агенту; счётчик ошибок виден в строке состояния.
- **Клик по элементу превью → правка в чат** — кнопка «⌖ Выбрать элемент» в тулбаре встроенного браузера: наведение подсвечивает элементы страницы, клик отправляет в чат заготовку правки — CSS-селектор, фрагмент HTML и файл-кандидат в workspace со строкой (Alt+клик — выбрать родителя, Esc — отмена). Заготовка появляется жёлтой заметкой над полем ввода: опишите правку своими словами и отправьте — контекст подмешается автоматически. Работает в статическом режиме превью (в dev-сервер/Docker кнопка неактивна: там страница собрана фреймворком и исходник по селектору не определить).
- **Без зомби-процессов** — dev-сервер корректно гасится при закрытии IDE (kill по владельцу порта), а осиротевший от прошлого запуска выметается на старте; новый сервер не уезжает на чужой порт.
- **Занятый порт проекта — под контролем.** Если порт из конфигурации проекта занят (dev-сервер ушёл на соседний порт или упал с EADDRINUSE), IDE показывает модальное окно: **освободить порт** (завершить занявший его процесс и перезапустить dev-сервер), **работать на подменённом порту** (только на эту сессию — порт в конфигурации проекта не меняется никогда, деплой ждёт именно его) или **отмена** (разрулить самому). Если порт держит dev-сервер другого проекта, запущенного в этой же VibeIDE, окно называет проект и по умолчанию предлагает сосуществование, а не убийство соседа. Работа на подменённом порту помечается в статус-баре: `3001 (вместо 3000)`. Отключается настройкой `vibeide.vibeServer.portConflictPrompt`.

## 💬 Чат и контекст

- **Подмешивание контекста на ходу** — пока агент работает, набранный текст по Enter встаёт в очередь и учитывается на следующем шаге, без остановки хода. Очередь видна **закреплённой полоской над полем ввода**, любую заметку можно убрать крестиком.
- **Закрепление сообщений булавкой** — важное в чате не вырезается при обрезке истории.
- **Динамическая фильтрация контекста** — промежуточные результаты инструментов сжимаются до попадания в основной контекст (режимы `auto`/`raw`/`aggregate`/`off`), с явным маркером усечения — без тихого удаления.
- **Кеширование промпта** — повторные большие префиксы контекста стоят кратно дешевле.
- **Таймлайн чата** — видно, где ход «задумался», без копания в консоли; у инструментов виден `start`/`done` и длительность.
- **Правила проекта** — дерево `.cursor/rules/` и legacy `.cursorrules` подхватываются и ходят по ссылкам (`@rule`), как в Cursor.
- **Экспорт чата в Markdown** — скопировать переписку в буфер обмена (tool-результаты усечены для компактности) или сохранить **полный** лог в `.md`-файл через диалог сохранения; свёрнутые блоки рассуждений сериализуются независимо от состояния UI.
- **Автоскролл и кнопка «вниз»** — пока агент стримит, чат сам держится у низа (с запасом, без отрыва на мелком отставании); если отлистал вверх читать историю — внизу появляется кнопка прокрутки к последнему сообщению.

### Лимиты сессии и контекстного окна

- **Панель «Документы»** — боковая панель показывает markdown-файлы (`.md`/`.mdx`) из настраиваемой папки воркспейса (по умолчанию `docs`, рекурсивно; ключ `vibeide.docsPanel.root`) деревом (папки + файлы, как Explorer, но только markdown); панель обновляется на изменения файлов. **Расширение в дереве не показывается** — панель markdown-только, и `.md` в каждой строке был бы шумом: файл `russianFirst.md` отображается как `russianFirst` (полное имя — в тултипе). Редкий `.mdx` при этом не теряется: его иконка помечена значком «x», иначе `guide.md` и `guide.mdx` выглядели бы одинаково. Клик открывает файл **в режиме просмотра** (отрендеренный markdown), а ПКМ → «Открыть исходник» — на правку.
  **Управление файлами прямо из панели.** В шапке — «Создать файл», «Создать папку», «Обновить», «Свернуть все». По ПКМ на строке — «Открыть превью», «Открыть исходник», «Создать файл», «Создать папку», «Вырезать» (Ctrl+X), «Копировать» (Ctrl+C), «Вставить» (Ctrl+V), «Переименовать» (F2), «Удалить» (Delete), «Копировать путь», «Копировать относительный путь», «Показать в системном проводнике». Имя вводится **прямо в дереве**, как в Проводнике, с проверкой на лету (пустое имя, недопустимые символы, занятое имя). При создании файла расширение `.md` подставляется автоматически — вводится только имя; созданный файл сразу открывается на редактирование. Переименование тоже идёт по имени без расширения, исходное расширение сохраняется. Создание и вставка целятся в выделенную папку (или в папку выделенного файла), при пустом выделении — в корень. Удаление уходит в системную корзину; удаление непустой папки требует подтверждения. Буфер вырезания/копирования — свой, замкнут внутри панели; при вставке в папку с таким же именем добавляется суффикс `copy`.
  **Визуальный граф связей.** Кнопка «Граф документов» в шапке панели (и команда `VibeIDE: Документы: Граф документов`) открывает **вкладкой редактора** граф всех документов и ссылок между ними — как в Obsidian, но вкладкой: резиновый размер, split-view рядом с самим доком, переживает перезапуск. Связями считаются и обычные ссылки `[текст](путь.md)`, и obsidian-стиль `[[запись]]` (с алиасом `[[запись|имя]]` и якорем `[[запись#раздел]]`); ссылки внутри код-блоков не считаются. Узлы раскрашены **по домену** (`ui/`, `architecture/`, `i18n/` и т.д.), размер узла — по числу связей. Мышь: колесо — зум к курсору, перетаскивание фона — панорама, перетаскивание узла — раскладка подстраивается, наведение — подсвечивает соседей и гасит остальное, клик — открывает документ. Есть поиск по имени (совпавшее светится, прочее гаснет) и «Вписать в экран». В шапке — живой счётчик: сколько документов, связей, недостижимых и битых ссылок.
  **Чего нет у Obsidian:** граф красит **недостижимые** от `README.md` документы (обводка) и рисует **битые ссылки** пунктиром в никуда — это те же дефекты, которые гейтит `npm run docs-graph-check`, только видно глазами, а не списком. В боковой панели есть отдельная секция **«Связи документа»** — локальный граф соседей открытого документа (глубина 2), свёрнутая по умолчанию; ПКМ на файле → «Показать в графе» открывает полный граф с наведением на этот документ.
  Папки показываются **все, включая пустые** — панель ими управляет, и папка, исчезающая сразу после создания, была бы багом. Файлы из дерева **перетаскиваются мышью (drag-n-drop)**: бросок в чат прикрепляет док к сообщению как файл-контекст (на разбор агенту), бросок в область редакторов открывает его — привычный жест, как из Проводника (папки не перетаскиваются). Поскольку спеки живут в `docs/specs/`, они естественно видны и в этом дереве. Markdown-фокус вместо полного дерева Explorer — быстрый доступ к докам/спекам/базе знаний проекта.
- **Session token limit** — потолок input+output токенов на чат-сессию (по умолчанию 2 000 000). Warning на 80%, блокировка на 100% до reset; при включённом автопилоте — авто-сброс с записью в лог (rate-limited).
- **Context window guard** — следит за заполнением окна модели в реальном времени: non-blocking warning на 75%, blocking-диалог *compact / continue / cancel* на 90%.
- **Индикатор в статус-баре** — текущее заполнение контекста, цвет зелёный → жёлтый → красный; по клику открывается status-pane. Показывает реальные токены провайдера.
- **Per-task split (опционально)** — делит session-budget между задачами очереди агентов пропорционально.
- **Сжатие вывода команд и инструментов (экономия токенов)** — вывод `run_command` и MCP-инструментов сжимается ДО попадания в контекст модели, экономя input-токены на шумных прогонах. Общий конденсер (`vibeide.terminal.condenseOutput`) схлопывает повторяющиеся строки (`[× N]`) и серии прогресс-шума тест-раннеров/сборщиков (прогресс-бары, «ok»-маркеры, Downloading/Compiling) в маркер `[… +N similar lines condensed]`. Поверх него — **command-aware профили** (`vibeide.terminal.compressProfiles`): по типу команды (`git`, тест-раннеры `npm/yarn/pnpm test`, `jest`, `pytest`, `cargo test`, `ls`, `docker`) применяется профильная свёртка — списки файлов `git status`, «зелёные» прохождения тестов, длинные листинги `ls`, layer-progress `docker`. Вывод **MCP-инструментов** (часто самый шумный — JSON-дампы) сжимается общим конденсером через `vibeide.tools.compressMcpOutput`. Во всех случаях строки ошибок/провалов/конфликтов и итоговые summary сохраняются дословно, а размерный кламп head+tail (`vibeide.tools.maxTerminalOutputChars`) остаётся страховкой. Срабатывает только на длинном выводе. Всё отключаемо. Команда **«VibeIDE: Экономия на сжатии вывода»** показывает, сколько символов/≈токенов сжатие сэкономило за сессию (раздельно терминал и MCP).

## 🎙️ Голосовой ввод (диктовка)

- **Локальное распознавание речи, без сети** — движок sherpa-onnx работает на компьютере пользователя, звук никуда не отправляется. Русский — основной язык: гибрид из стриминговой модели T-one (живой interim-текст «печатается пока говоришь») и GigaAM v3 (финальная расшифровка каждой фразы, лучший открытый WER для русского); английский — стриминговая NeMo fast-conformer. Язык берётся из `accessibility.voice.speechLanguage` (`auto` — язык интерфейса). Текст распознаётся строчными без пунктуации (ограничение открытых моделей).
- **Кнопка микрофона в чате** — во всех поверхностях ввода (композер, правка сообщения, Ctrl+K): interim-текст вставляется в позицию курсора и заменяется финальным; повторный клик — стоп с дожимом последней фразы, Esc — отмена без вставки; кнопка пульсирует от уровня микрофона.
- **Диктовка в редакторе и терминале** — штатные механизмы VS Code оживают с нашим провайдером: `Ctrl/Cmd+Alt+V` в редакторе (ghost-превью, hold-режим «пока держишь», Esc), «Start Dictation in Terminal» из палитры.
- **Модели скачиваются один раз при первом использовании** (~278 МБ для русского, ~98 МБ для английского) с прогрессом и проверкой SHA256; хранятся в данных пользователя. Для офлайн-машин — настройка `vibeide.voice.modelsPath` (перенести каталог с другой машины). Прочие ручки: `vibeide.voice.enabled`, `threads`, `endpointSilenceMs`, `keepAliveSec` (выгрузка движка из памяти после простоя).

## 🎬 Просмотр видео в чате (/watch)

- **Команда `/watch <ссылка или путь> [вопрос]`** — модель «смотрит» видео целиком, а не пересказывает субтитры: yt-dlp скачивает ролик (YouTube и сотни других площадок, а также прямые ссылки и локальные файлы), ffmpeg режет кадры **по сменам сцен** (не по таймеру — графика, демо и монтаж не проскакивают между тиками), каждый кадр привязан к тайм-коду из `showinfo`, и всё это уходит выбранной vision-модели одним запросом: кадры вложениями + транскрипт текстом. Без вопроса — полный разбор (TL;DR, ключевые моменты с тайм-кодами, что показано на экране, но не проговорено); с вопросом — ответ по содержимому ролика.
- **Чисто аудио той же командой** — подкаст, mp3/wav, голосовое сообщение (локальный файл или прямая ссылка) разбираются без стадии кадров: тип входа определяется автоматически (по фактическим потокам файла — обложка-картинка не считается видео; расширение — лишь подсказка), при готовых субтитрах медиа даже не скачивается, разбор — темы и тезисы с тайм-кодами, спикеры по контексту, цитаты. Vision-модель для аудио не нужна: файл или прямая ссылка с аудио-расширением работает и на текстовой модели чата (страница платформы без расширения пока требует vision-модель — тип входа до запуска пайплайна неизвестен).
- **Транскрипт по цепочке «бесплатно → локально»** — сначала субтитры с площадки (`vibeide.video.subtitleLanguages`, по умолчанию `ru,en`); если их нет — звук расшифровывается локальными STT-моделями (русский — GigaAM, английский — компактная NeMo-модель; по фрагментам с тайм-кодами, ничего не уходит в сеть); нет и звука — видео разбирается только по кадрам, а чисто аудио-разбор без транскрипта честно останавливается с уведомлением. Для английского можно выбрать модель по точности/размеру настройкой `vibeide.voice.englishBatchModel` (`small` по умолчанию — легче и быстрее, `medium` — точнее).
- **Инструменты скачиваются один раз при первом использовании** (~50–70 МБ: yt-dlp + статический ffmpeg с нашего зеркала-релиза `video-tools-v1`) с согласием, прогрессом и проверкой SHA256; в дистрибутив не входят. При протухании yt-dlp (YouTube регулярно ломает старые версии) — кнопка «Обновить yt-dlp» прямо в уведомлении об ошибке. Для офлайн-переноса — `vibeide.video.toolsPath`.
- **Пайплайн под контролем** — прогресс по стадиям (метаданные → субтитры → скачивание → кадры → звук) в уведомлении с отменой; несовместимая (не-vision) модель чата отсекается до начала работы; количество и размер кадров ограничены (`vibeide.video.maxFrames`, `frameHeight`, порог сцен `sceneThreshold` с автоповтором на статичных роликах); временные файлы вычищаются после отправки.
- **Автокомплит команд** — `/` в начале сообщения открывает меню команд чата (`/watch`, `/commit`, переход в `/skill:`), команды подсвечиваются пилюлей в поле ввода.

## ✏️ Надёжные правки файлов

- **Простой формат `edit_file`** — «что заменить» (`old_string`) и «на что» (`new_string`), два обычных поля. Слабые модели (MiniMax и др. через агрегаторы) больше не сваливаются в десятки одноразовых скриптов.
- **Терпимый поиск** заменяемого текста — правка применяется, даже если модель чуть ошиблась в отступах/пробелах или слегка перефразировала середину (line-trimmed + block-anchor).
- **Выравнивание отступа** блока по файлу, если модель скопировала якорь без отступа.
- **Без потери кода** — незавершённый блок правки отклоняется с подсказкой, а не применяется как удаление.
- **Режим «Обзор»** (read-only) не зацикливается — агент прямо предлагает переключиться на «Агента» для применения правок.
- **Рефактор-инструменты** (rename/extract/generate_tests) — под тем же подтверждением, что и обычные правки.

## 🔔 Уведомления о фоновой активности агента

Когда агент завершил работу, остановился или ждёт вашего ответа, а IDE свёрнута или в фоне:

- **Звук** — короткий сигнал на завершение / остановку / ожидание ответа. Раздел «Уведомления» в настройках: выбор звука с прослушиванием, свой файл через «Обзор…» (mp3/ogg/wav, до 1 МБ и 5 секунд — проверяется при выборе), громкость, «молчать, когда окно в фокусе», тумблеры событий.
- **Редактор «VibeIDE Звуки»** — загрузить свой трек, обрезать окно до 5 секунд по звуковой волне, прослушать и сохранить (в папку `sounds` рядом с данными IDE).
- **Мигание иконки в панели задач** (на macOS — прыжок в Dock) — не отвлекает, но забыть не даёт; клик возвращает к IDE и переключает на её рабочий стол.
- **Системный тоаст** с тем же сообщением; клик по нему тоже возвращает к VibeIDE.

Всё срабатывает только когда окно не в фокусе. Отключается тумблером.

## 🔌 Провайдеры: диагностика и надёжность

- **Модалка «Проверка провайдеров»** — показывает активные провайдеры (у кого прописан ключ) и послойно проверяет связь: конфиг → сеть → авторизация → каталог моделей, с задержкой ответа. Пятый слой — **сквозной тест запроса (L5)**: по кнопке (никогда автоматически — тратит токены) уходит настоящий мини-запрос к модели через тот же путь, что и чат; меряется время первого токена и полного ответа — ловит «залипший транспорт», который послойная проверка не видит. Если слои зелёные, а сквозной тест падает, модалка сама предлагает «Сбросить клиентов». Тумблер «Авто» перепроверяет слои каждые 30 секунд, пока окно открыто (L5 не трогает); кнопка «⧉» на карточке копирует отчёт по одному провайдеру. Отчёт выгружается в Markdown вместе с журналом событий отправки (синк провайдеров, кэш клиентов, пересоздание соединения, первый токен, ошибки; секреты вычищаются). Индикатор здоровья провайдера в статус-баре при деградации открывает эту модалку по клику.
- **«Починить связь»** — иконка-ключ в статус-баре лечит «токены вдруг перестали приходить у всех провайдеров» **без перезапуска IDE**: пересоздаёт сетевое соединение и сбрасывает кэши клиентов. Плюс **автолечение**: если сетевые сбои идут сразу у двух и более провайдеров в одном окне (сигнатура залипшего общего пула соединений), IDE пересоздаёт транспорт сама — с уведомлением и кнопкой «Проверка провайдеров»; не чаще раза в 10 минут, отключается `vibeide.llm.autoResetTransport`. Смена настроек провайдера (включая заголовки в `.vibe/providers.json`) теперь подхватывается без перезапуска — клиент пересоздаётся автоматически.
- **Failover провайдеров** — переключение при недоступности.
- **Внешний каталог квирков моделей** — таблица особенностей моделей (пустой ответ при стандартной `temperature`, требование `reasoning_content`, XML-режим вместо native function-calling) берётся из самого свежего источника (рядом с exe / из сборки / с CDN, по дате). Новая «странная» модель — это PR на один файл, а не релиз IDE. **Каталог сам просится пополниться:** если модель из сессии в сессию уезжает в авто-даунгрейд из-за сломанных native tool-call, IDE один раз предложит закрепить XML-режим насовсем (кнопка в уведомлении) и скопировать готовое правило для PR в каталог — квирк станет дефолтом для всех. Порог и выключатель — `vibeide.modelQuirks.autoSuggest*`.
- **Нормализация вызовов инструментов** — имена `file_read`/`FileRead`/`ReadFile` сводятся к одному концепту; аргументы от чужого тула чинятся на лету; self-closing-теги (`<read_file path="..." />`) распознаются. В настройках (Безопасность → «Нормализация tool-call») — **живые счётчики слоёв защиты**: видно, какая форма «нестандартных» вызовов у текущей модели и какой слой её тащит; кнопки «Обновить» и «Сбросить счётчики» для А/Б-проверки конкретной модели.
- **Нативные режимы рассуждений моделей** — слайдер «мышления» в чате говорит с моделью на её родном языке: для MiniMax-M3 это `adaptive` (модель сама решает, думать ли — дефолт, экономит токены на тривиальных шагах) / `enabled` (думать всегда) / выключено; для Anthropic — бюджет токенов; для OpenAI-совместимых — уровни усилия.

## 🔗 MCP (Model Context Protocol)

- **Официальный SDK** — подключение MCP-серверов.
- **OAuth / token manager** — единое место для OAuth-токенов MCP (ротация, отзыв, индикатор истечения), секреты через шифрование.
- **Sampling / Elicitation** — паттерны «модель запрашивает уточнение у пользователя» с единым UX подтверждения.

## ⌨️ Команды проекта

- Описываются один раз в `.vibe/commands.json` — едут в репозитории вместе с проектом, у коллег появляются автоматически.
- Закреплённые (`pinned: true`) — отдельное меню **Команды** в шапке IDE: inline pin / edit / delete без перехода в настройки.
- Топ-9 закреплённых — горячие клавиши `Ctrl+Shift+Alt+1..9` автоматически (пере-биндятся при изменении набора).
- Импорт из `.vscode/tasks.json` через палитру одним кликом.
- Sanitizer режет shell-метасимволы и zero-width injection; первый запуск и любая правка команды требуют явного approve (hash в `.vibe/commands.trust.json`).
- Секреты через `${secret:KEY}` — реальные значения не попадают в audit-лог и не уходят в облачные индексаторы.
- Редактор: форма с валидацией или прямой JSON-режим.

## 🔒 Безопасность и приватность

- **Нет телеметрии Microsoft** — поле `enableTelemetry` убрано из `product.json`. Локальное хранение телеметрии с явным opt-in для облака.
- **API-ключи через Electron `safeStorage`** (macOS Keychain, Windows DPAPI, Linux libsecret).
- **Детекция секретов** перед отправкой контекста в любой LLM.
- **Config Guard** — проверяет `.vibe/providers.json` и `mcp.json` при загрузке: незашифрованные endpoint-ы, секреты в открытом виде, запуск удалённых скриптов в MCP. Команда «Config Guard — показать находки».
- **`.vibe/ignore`** — файлы из него агент не читает и не ищет (например минифицированные бандлы в одну строку, раздувающие контекст).
- **Офлайн-гейт приватности** — embedding и контекстный пайплайн уважают офлайн-режим.
- **Аудит-лог** — `.vibe/audit.jsonl`, одна служебная папка в проекте.
- **First-run security wizard** и анализ разрешений расширений.

## 🩺 Диагностика и стабильность

- **Watchdog памяти** — следит за ростом каждые несколько минут, предупреждает до OOM (pre-OOM detector), умеет собрать crash-report и снять heap snapshot.
- **Восстановление после краша** ext-host и stale execution lease — баннер «взять управление / отменить» вместо немого зависания.
- **OTLP-трейсы агентного цикла** — spans на tool-calls, latency провайдера, размер контекста (локальный экспорт, не облако по умолчанию).
- **Сырые XML-теги в чате** прячутся в лаконичный плейсхолдер вместо протечки в UI.
- **Копирование логов одной кнопкой** — диагностические/агентские логи берутся в буфер без выковыривания из файлов.
- **Единое управление логированием** — настройки `vibeide.logging.*` (уровень, категории с wildcard, per-category уровни, схлопывание повторов) действуют живьём на **все процессы**, включая main; редакция секретов работает во всех приёмниках лога каждого процесса (консоль, ring-buffer → буфер обмена, Output-канал, файл).

## 📦 Установка и сборка

- **Установщик `VibeIDESetup.exe`** (издатель VibeBrains) + portable `.zip`.
- **macOS (Apple Silicon, arm64)** — `.dmg` (перетаскиванием в Applications) + портативный `.zip`. Сборка пока не нотаризована Apple: при первом запуске Gatekeeper требует «Open Anyway» (System Settings → Privacy & Security) либо `xattr -cr /Applications/VibeIDE.app`; SHA-256 артефактов публикуются в release notes. Intel-маки не поддерживаются.
- **Доступен в winget** — `winget install VibeBrains.VibeIDE` (Windows).
- **Портативный режим** — папка `data/` рядом с исполняемым файлом.
- **Двухфазный релиз-поток** (сборка → ручная проверка → публикация) — для самого проекта, на обеих платформах (`release-windows.ps1` / `release-macos.sh`).
