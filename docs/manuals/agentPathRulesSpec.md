# Спека правил на пути агента — `.vibe/constraints.json`, `.vibe/permissions.json`, `.vibe/ignore`

← [Дерево документации](../README.md)

> **Как этим пользоваться:** скопируйте этот файл целиком своей LLM и попросите собрать
> `.vibe/constraints.json`, `.vibe/permissions.json` или `.vibe/ignore` для вашего проекта. Здесь
> есть всё: форматы, как сопоставляется путь, порядок решения и рабочие примеры. Выходить в интернет
> и читать исходники VibeIDE не нужно.

## Три файла и когда какой

| Файл | Что делает | Когда брать |
|---|---|---|
| `.vibe/ignore` | Файлы, которые агент **не читает и не ищет** | Шум (сборка, минифицированные бандлы, зависимости) и секреты, которым не место в контексте |
| `.vibe/constraints.json` | **Запреты с объяснением:** `deny_write`, `deny_read` | Договорённость команды — «миграции и секреты агент не трогает»; обычно лежит в git |
| `.vibe/permissions.json` | **Белые и чёрные списки:** `allow_*` сужает, `deny_*` закрывает | «Агенту можно писать только в `src/` и `docs/`» |

Все три файла действуют на **файловые инструменты агента**: чтение, листинг папок, поиск, правку,
перезапись, создание и удаление файлов. На команды, которые агент запускает в терминале, они не
распространяются — запуск команд разрешается отдельно.

Это не просьба к модели. Правила проверяет IDE до того, как инструмент коснётся диска, и модель их
не обходит. Файлы перечитываются сразу после сохранения — перезапускать окно не нужно.

## Как проверяется путь

1. **Путь разворачивается.** Убираются `.` и `..`, символические ссылки разворачиваются по диску.
   Файл за ссылкой отзывается на несколько имён: как его назвали, где он лежит на диске и как это
   место называется внутри проекта.
2. **Запрет проверяется для каждого имени.** Совпало хоть одно — действие отклоняется. Ссылка
   `docs/keys → ../secrets` не открывает того, что закрыто в `secrets/`.
3. **Разрешение проверяется для места, где файл лежит на самом деле**, а не для имени ссылки.
4. **Висячая ссылка — отказ:** неизвестно, какой файл затронула бы операция.
5. **Поиск агента по ссылкам не ходит**, а его результаты проходят те же правила чтения: поиск не
   отдаёт того, что не отдало бы чтение.

**Порядок решения.** Запись: `deny_write` из `constraints.json` → `deny_write` из `permissions.json`
→ белый список `allow_write`. Чтение: `deny_read` из `constraints.json` → `deny_read` из
`permissions.json` → белый список `allow_read` → `.vibe/ignore`. **Разрешение из `permissions.json`
не отменяет запрет из `constraints.json`:** путь должны пропустить оба файла.

Кроме этих файлов запись ограничивают граница рабочей области (настройка
`vibeide.agent.allowWriteOutsideWorkspace`; по умолчанию запись вне проекта запрещена) и папки-источники
базы знаний. Они настраиваются не здесь.

## Шаблоны в `constraints.json` и `permissions.json`

- `*` — любые символы внутри одной папки; `**` — через папки (`**/` — ноль и больше папок); `?` —
  ровно один символ; `\` читается как `/`.
- **Шаблон без `/` в начале ищется внутри проекта на любой глубине, по границам папок.**
  `secrets/**` совпадает с `secrets/key.pem` и с `app/secrets/x`, `.env` — с файлом `.env` в любой
  папке проекта, `*.pem` — с любым `.pem`. Папки **над** корнем проекта в сравнении не участвуют:
  проект, лежащий в `~/src/app`, не делает `src/**` совпадающим со всем подряд.
- **Шаблон с `/` в начале привязан к корню проекта**, как в `.gitignore`: `/dist/**` — только `dist`
  в корне. Полный путь на диске (`/Users/me/shared/**`, `C:/data/**`) тоже понимается — так
  закрывают или открывают места вне проекта.
- **Файл вне проекта** (если агенту разрешено туда ходить). Запрет без `/` проверяется по полному
  пути: `**/.ssh/**` закроет `~/.ssh`, где бы тот ни лежал. Разрешение без `/` вне проекта не
  срабатывает — правило проекта не выдаёт доступ к чужим местам; для этого пишите полный путь.
- **Регистр.** Запрет регистр не различает: `Secrets/**` поймает и `secrets/`, на любой ОС.
  Разрешение совпадает только точно.
- Буквы сравниваются в NFC: `й`, записанная одной или двумя кодовыми точками, — одна и та же буква.

## `.vibe/constraints.json`

JSON; комментарии `//` и висячие запятые допустимы.

```jsonc
{
  "vibeVersion": "…",   // необязательно
  "rules": [
    { "type": "deny_write", "pattern": "**/.env*", "message": "Секреты — только вручную" },
    { "type": "deny_write", "pattern": "migrations/**", "message": "Миграции пишет человек" },
    { "type": "deny_read", "pattern": "internal-audit/**", "message": "Внутренний аудит агенту не читать" }
  ]
}
```

| Поле правила | Тип | Смысл |
|---|---|---|
| `type` | `"deny_write"` или `"deny_read"` | Что закрыто: любая запись (правка, перезапись, создание, удаление) или чтение вместе с поиском |
| `pattern` | строка | Шаблон пути по правилам выше. Правило без шаблона пропускается |
| `message` | строка, необязательно | Что сказать, когда правило сработало. Пишите причину, а не «запрещено»: агент перескажет её в чате |

Типы `max_lines_per_function` (поле `value`) и `deny_age` (поле `older_than_months`) разбираются, но
**пока не применяются** — не рассчитывайте на них. Лишние поля игнорируются: `_comment` удобен для
пояснений.

Где ещё действуют запреты записи: проверка хода отмечает запись в закрытый путь, а рабочая папка
проектных команд (`cwd`) проверяется при их загрузке. Отчёт «VibeIDE: Проверить запуск» показывает
закрытые пути до того, как агент начнёт.

## `.vibe/permissions.json`

```jsonc
{
  "vibeVersion": "…",
  "allow_write": ["src/**", "docs/**", "tests/**"],  // писать можно только сюда
  "deny_write": ["src/generated/**", "**/*.lock"],    // закрыто для записи
  "allow_read": [],                                   // пусто — чтение не ограничено
  "deny_read": ["**/fixtures/private/**"]             // закрыто для чтения
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `allow_write` | массив шаблонов | Непустой — белый список: писать можно только сюда. Пустой или отсутствует — ограничения нет |
| `deny_write` | массив шаблонов | Запись закрыта. Сильнее `allow_write` |
| `allow_read` | массив шаблонов | То же, что `allow_write`, для чтения |
| `deny_read` | массив шаблонов | То же, что `deny_write`, для чтения |

В шаблонах этого файла `*` и `?` не переходят ни через `/`, ни через `\`. Если JSON повреждён,
VibeIDE покажет уведомление и будет работать так, будто файла нет. По умолчанию файл **не** исключён
из git; если это ваши личные исключения, добавьте `permissions.json` в `.vibe/.gitignore`.

## `.vibe/ignore`

Синтаксис — подмножество `.gitignore`, пути от корня проекта:

- `#` — комментарий; пустые строки пропускаются;
- `!шаблон` возвращает исключённое; побеждает **последнее** совпавшее правило;
- `/` в начале или внутри шаблона привязывает его к корню, иначе он действует на любой глубине;
- `/` в конце — папка со всем содержимым;
- `*` — внутри папки, `**` — через папки, `?` — один символ.

Действует на чтение содержимого и на результаты поиска; регистр не важен. На запись не действует —
для этого есть `deny_write`.

Основное из файла, который VibeIDE кладёт при инициализации `.vibe`:

```gitignore
# Секреты и учётные данные
.env
.env.*
*.key
*.pem
*.p12
secrets/
credentials/

# Сборка и тяжёлые артефакты
dist/
build/
out/
*.min.js
*.bundle.js

# Зависимости
node_modules/
vendor/
```

## Рабочие примеры

**Агент пишет код, тесты и документацию; миграции и секреты — только руками.**

`.vibe/permissions.json`:

```json
{ "allow_write": ["src/**", "tests/**", "docs/**"] }
```

`.vibe/constraints.json`:

```json
{
  "rules": [
    { "type": "deny_write", "pattern": "src/db/migrations/**", "message": "Миграции пишет человек" },
    { "type": "deny_write", "pattern": "**/.env*", "message": "Секреты — только вручную" },
    { "type": "deny_read", "pattern": "**/.env*", "message": "Значения секретов агенту не нужны: работайте с именами переменных" }
  ]
}
```

**Монорепозиторий: чужой пакет только для чтения, приватные фикстуры закрыты целиком.**

`.vibe/permissions.json`:

```json
{
  "deny_write": ["packages/billing/**"],
  "deny_read": ["**/fixtures/private/**"]
}
```

**Шаблон от корня против шаблона на любой глубине.** `/build/**` закрывает только `build` в корне
проекта, а `build/**` — любую папку `build` внутри проекта.

## Как проверить

- Команда **«VibeIDE: Проверить запуск»** показывает закрытые для записи и чтения пути до запуска
  агента.
- Отказ инструмента называет файл и сработавшее правило: текст из `message`, шаблон или имя списка в
  `permissions.json`. Агент перескажет это в чате.
