# Инструмент `extract_structured` — данные со страницы по JSON-схеме

← [Документация](../README.md)

> **Как этим пользоваться.** Скопируйте этот файл целиком своей LLM и попросите:
> *«По этой спецификации составь JSON-схему, чтобы извлечь со страницы …»*.
> Здесь есть всё: как включить инструмент, какую модель взять, как устроен вызов и как выглядит
> хорошая схема. Выходить в интернет и читать исходники VibeIDE не нужно.

---

## 1. Что это

Инструмент агента, который берёт адрес страницы и JSON-схему и возвращает данные **строго по схеме**:
цены, характеристики, списки, контакты. Для чтения страницы как текста есть `browse_url`; этот
инструмент нужен, когда нужны поля, а не пересказ.

Работает через отдельную **модель извлечения**, а не через модель чата.

---

## 2. Как включить

1. Выберите модель и задайте её в настройке `vibeide.extract.model` в форме `провайдер/модель`:
   - через OpenRouter: `openRouter/inference-net/schematron-v2-turbo`
   - напрямую у inference.net: `inference-net/inference-net/schematron-v2-turbo` — провайдер
     `inference-net` засевается в `.vibe/providers/`, ключ `INFERENCE_API_KEY` в `.vibe/.env`
2. Пустая настройка — инструмент выключен и сообщает агенту об этом при вызове.

**Какую модель брать.** Schematron V2 Turbo быстрее и дешевле, V2 Small точнее. Окно у обеих 128K
токенов. Подойдёт и другая модель, которая умеет `response_format` с JSON-схемой, — но у Schematron
это её единственная работа.

**Модель может быть скрыта из выбора в чате.** В засеянном `inference-net` модели Schematron стоят с
`"active": false`: в чате им делать нечего. Извлечению это не мешает — инструмент берёт модель прямо
из настройки и на скрытость не смотрит.

---

## 3. Как устроен вызов

- Страница загружается целиком, с проверкой сетевого фильтра агента, как у `browse_url`.
- Из HTML вырезаются скрипты, стили, комментарии, метатеги и вложенные SVG и фреймы. Страница
  длиннее 300 000 символов обрезается — в результате это отмечено.
- Модели уходит **одно сообщение пользователя со страницей, без системного промпта**. Schematron
  инструкций не принимает вовсе: всё, что ей нужно знать, — в схеме.
- Схема уходит в `response_format` (`json_schema`, `strict: true`), температура — 0.
- Ответ разбирается как JSON; ответ прозой — ошибка.

---

## 4. Параметры

| Параметр | Тип | Обяз. | Смысл |
|---|---|---|---|
| `url` | строка | **да** | Полный адрес страницы, с `http://` или `https://`. |
| `schema` | объект JSON Schema | **да** | Форма результата. Должна содержать `type` или `properties`. |

---

## 5. Хорошая схема

Схема — единственная инструкция, поэтому пишите её как задание:

- называйте поля так, как их назвал бы человек (`price`, а не `p1`);
- добавляйте `description`, если смысл не очевиден из имени: «цена со скидкой, в рублях»;
- ставьте `required` для полей, без которых результат бесполезен;
- для списков — `type: "array"` и схему элемента в `items`.

```json
{
  "type": "object",
  "properties": {
    "title": { "type": "string" },
    "price": { "type": "number", "description": "итоговая цена со скидкой" },
    "inStock": { "type": "boolean" },
    "specs": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": { "name": { "type": "string" }, "value": { "type": "string" } },
        "required": ["name", "value"]
      }
    }
  },
  "required": ["title", "price"]
}
```

---

## 6. Ограничения

- Страница, которую строит JavaScript, придёт пустой: загружается HTML ответа сервера.
- Инструмент виден и в режимах только на чтение (сбор, план), как `browse_url`: он не пишет файлы,
  но ходит в сеть и тратит запрос к модели.
- Цены Schematron у вендора и у OpenRouter различаются — сверяйте у того, через кого ходите.
