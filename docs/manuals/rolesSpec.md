# Спецификация формата `.vibe/roles.json` (VibeIDE)

← [Документация](../README.md)

> **Как этим пользоваться.** Скопируйте этот файл целиком своей LLM и попросите:
> *«По этой спецификации поправь мне `.vibe/roles.json`: тесты в проекте лежат в …»*.
> Модель вернёт готовый JSONC. Здесь есть всё, что нужно для валидного файла. Выходить в интернет
> и читать исходники VibeIDE не нужно.

Канонический источник — разбор в
`src/vs/workbench/contrib/vibeide/common/pipeline/vibeRolesFile.ts`. Этот файл описывает тот же
формат человеческим языком.

---

## 1. Что это и зачем

`roles.json` — умолчания ролей агента. Файл **общий для VibeIDE и VibeIDEA**: оба продукта читают
его одинаково, поэтому пайплайн из общего набора ведёт себя в них одинаково.

Сейчас в файле одно умолчание — **куда пишет роль `qa`**. Тестировщик без права записи не оставит
теста, а с правом писать всюду «заодно чинит» проверяемый код, и тест с исправлением становятся одним
действием, которое никто не проверил. Поэтому `qa` по умолчанию пишет только в тесты.

- Формат — **JSONC**: комментарии и висячие запятые разрешены.
- Файл живёт в рабочей папке: `<проект>/.vibe/roles.json`. Засевается вместе с остальным набором.
- Умолчание действует и в пайплайне, и когда `qa` зовёт оркестратор.

---

## 2. Структура

```jsonc
{
  "version": 1,
  "roles": {
    "qa": {
      // Куда пишет шаг qa, если у шага нет своих "paths".
      "writePaths": ["**/test/**", "**/tests/**", "*.test.ts"]
    }
  }
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `version` | число | Версия формата. Сейчас `1`. |
| `roles.qa.writePaths` | список строк | Куда роли `qa` можно писать. Синтаксис `.gitignore`, пути от корня проекта. |

**Синтаксис путей:** `*` не переходит через `/`, `**` переходит, шаблон без `/` (`*Test.kt`)
действует на любой глубине.

---

## 3. Как список взаимодействует с шагом пайплайна

- Свои `paths` шага **заменяют** `writePaths`. Проект с необычной раскладкой тестов называет её
  шагу прямо.
- Одни `denyPaths` шага список **не снимают**, а сужают.

---

## 4. Ошибка никогда не расширяет границу

| Что в файле | Что действует |
|---|---|
| Файла нет | Встроенный список |
| JSON не разобрать | Встроенный список, предупреждение в журнале |
| Нет записи `qa` или `writePaths` | Встроенный список |
| `writePaths` не список, или внутри пустая строка или не строка | Встроенный список, предупреждение |
| `writePaths: []` | Роли `qa` запись **запрещена целиком** |

Пустой список — это запрет, а не «без ограничений»: иначе опечатка снимала бы границу.

---

## 5. Когда читается

- **Пайплайн** читает файл один раз в начале прогона: правка файла посреди прогона не сдвигает
  границу между шагами.
- **Делегирование от оркестратора** читает файл при запуске роли.

---

## 6. Встроенный список

Совпадает с засеянным файлом дословно — это проверяет тест:

```
**/test/**  **/tests/**  **/testSrc/**  **/testData/**  **/__tests__/**  **/spec/**
*Test.kt  *Test.java  *Tests.kt  *Test.php  *.test.ts  *.test.tsx  *.test.js
*.spec.ts  *.spec.tsx  *.spec.js  test_*.py  *_test.py  *_test.go
```

## 7. Чек-лист

- [ ] Корень — объект, `roles.qa.writePaths` — список непустых строк.
- [ ] Пути от корня проекта, синтаксис `.gitignore`.
- [ ] Хотите запретить `qa` запись совсем — `"writePaths": []`.
- [ ] Отдельному шагу нужны другие пути — `paths` у шага в `.vibe/pipelines.json`, а не здесь.
