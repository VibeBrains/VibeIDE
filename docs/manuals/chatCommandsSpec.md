# Команды чата: встроенные, `/my:` и `/workflow:`

> Скопируйте этот файл целиком своей LLM и попросите собрать `.vibe/prompts/<имя>.md` или
> `.vibe/workflows/<имя>.json` для вашей задачи. Всё, что нужно, — здесь: ни в интернете, ни в
> исходниках искать не придётся.

## Что это

Команда — слово с косой чертой в **начале** сообщения чата; остаток сообщения — её аргументы.
Команды бывают двух видов:

| Вид | Команды | Что происходит |
|---|---|---|
| Выполняет IDE | `/watch`, `/shot` | IDE делает действие сама, модель команду не получает |
| Промпт для модели | встроенные (ниже), `/my:<имя>`, `/workflow:<имя>` | в чате остаётся набранное, а модель получает развёрнутый запрос |

`/skill:<имя>` — навыки агента; они работают в любом месте сообщения, формат — в
[skillSpec.md](skillSpec.md).

Меню открывается, если набрать `/` в начале сообщения: в нём команды IDE, встроенные промпты, ваши
`/my:` и `/workflow:` и переход к навыкам. Набранное дальше фильтрует список.

## Встроенные команды-промпты

| Команда | Что просит у модели | Без аргументов — про что |
|---|---|---|
| `/fix [что]` | исправить проблему и объяснить, что было не так | все ошибки текущего файла |
| `/tests [что]` | написать тесты: основной путь, граничные случаи, ошибки | текущий файл |
| `/explain [что]` | объяснить код: что делает, как устроен, важные приёмы | текущий файл |
| `/refactor [что]` | рефакторинг для ясности, производительности и поддерживаемости | этот код |
| `/review [что]` | ревью: баги, безопасность, производительность, стиль | этот код |
| `/docs [что]` | документация и комментарии в формате языка | этот код |
| `/simplify [что]` | делит-лист по диффу: что удалить или упростить, ничего не меняя | текущий `git diff` |
| `/commit [--push] [пояснение]` | закоммитить застейдженное сообщением по Conventional Commits в стиле репозитория; с `--push` — и запушить | — |

`/commit` сам ничего не стейджит: если застейдженного нет, агент скажет об этом и остановится.
Команды git идут через обычное подтверждение команд терминала.

## `/my:<имя>` — свой промпт

Файл `.vibe/prompts/<имя>.md`. Имя файла без `.md` — имя команды: буквы любого алфавита, цифры, `_`,
`.`, `-` и **без пробелов** — команду с пробелом не набрать, и меню её не предложит.

- Первая строка файла (без `#` в начале) — описание в меню.
- Всё содержимое файла уходит модели как запрос.
- `$ARGS` заменяется остатком сообщения после команды. Заменяется только целое слово: `$ARGUMENTS`
  или `$ARGS_X` останутся как есть.
- Другие `$ИМЯ` (латиница, цифры, `_`) IDE не заполняет — они уходят модели как есть. Пишите шаблон
  так, чтобы из текста было ясно, что на их месте, или обходитесь `$ARGS`.

Пример `.vibe/prompts/review-security.md`:

```markdown
# Ревью безопасности

Проверь $ARGS на уязвимости: инъекции, утечки секретов, лишние права доступа.
Для каждой находки — файл:строка, риск и как исправить. Ничего не меняй.
```

Вызов `/my:review-security src/auth` — модель получает этот текст с `src/auth` на месте `$ARGS`.

## `/workflow:<имя>` — сценарий из нескольких шагов

Файл `.vibe/workflows/<имя>.json`, только JSON: файлы `.yaml` не читаются, в журнале будет
предупреждение. Имя файла без `.json` — имя команды, правила те же, что у `/my:`.

| Поле | Обязательно | Что это |
|---|---|---|
| `steps` | да | массив шагов, хотя бы один |
| `steps[].name` | да | название шага |
| `steps[].description` | нет | что сделать на шаге |
| `steps[].prompt` | нет | подробная инструкция агенту для этого шага |
| `steps[].requiresApproval` | нет | `true` — перед шагом агент остановится и спросит разрешения |
| `name` | нет | заголовок сценария; по умолчанию — имя файла |
| `description` | нет | описание: в меню команд и в запросе модели |
| `vibeVersion` | нет | служебная версия формата, IDE его не читает |

Пример `.vibe/workflows/release.json`:

```json
{
	"name": "Выпуск",
	"description": "От зелёной ветки до тега",
	"steps": [
		{ "name": "Проверки", "description": "Прогнать гейты и тесты, собрать список падений." },
		{ "name": "Ченджлог", "prompt": "Собери изменения с последнего тега по git log, сгруппируй по разделам." },
		{ "name": "Тег", "description": "Поставить тег vX.Y.Z и запушить.", "requiresApproval": true }
	]
}
```

Модель получает сценарий целиком — все шаги, их инструкции и места, где нужно спросить разрешения, —
и проходит шаги по порядку в одном разговоре. Файл с ошибкой (не JSON, нет `steps`, шаг без `name`,
`requiresApproval` не `true`/`false`) не читается, а причина пишется в журнал.

Чего у сценария нет: ограничений шагов по роли, инструментам или модели — это пайплайны,
[pipelinesSpec.md](pipelinesSpec.md). Поля `toolConstraints` и `allowedModels` из старых файлов IDE
не читает.

Сценарий запускается и кнопкой «Команды проекта»: поле `workflowId` — имя файла сценария, IDE
отправит `/workflow:<имя>` в текущий чат.

## Как команда доходит до модели

IDE разворачивает команду при каждом запросе к модели и ставит текст блоком `<command_invocation>` в
начало вашего сообщения — туда же, куда тело навыка при `/skill:`. Если файла для `/my:` или
`/workflow:` нет, модель получит пометку сказать вам об этом, а не угадывать.

Команда работает только в начале сообщения: `/docs` посреди фразы — это путь, а не команда.

## Проверка

1. Положите файл и наберите `/` в начале сообщения — команда должна появиться в меню.
2. Её нет — проверьте имя файла (без пробелов), расширение (`.md` для промптов, `.json` для
   сценариев) и журнал: у сценариев там написано, почему файл не прочитан.
