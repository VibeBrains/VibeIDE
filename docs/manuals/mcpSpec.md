# Спецификация формата `mcp.json` (VibeIDE)

← [Документация](../README.md)

> **Как этим пользоваться.** Скопируйте этот файл целиком своей LLM и попросите:
> *«По этой спецификации собери мне `mcp.json` для VibeIDE: я хочу подключить сервер …»*.
> Модель вернёт готовый JSON. Здесь есть всё: где лежит файл, поля записи, как выбирается
> транспорт, что проверяется при загрузке и чего формат не умеет. Выходить в интернет и читать
> исходники VibeIDE не нужно.

Канонический источник схемы — тип `MCPConfigFileEntryJSON` в
`src/vs/workbench/contrib/vibeide/common/mcpServiceTypes.ts`. Этот файл описывает тот же формат
человеческим языком.

---

## 1. Что это и где лежит

`mcp.json` — список MCP-серверов, инструменты которых получает агент VibeIDE.

- Файл **один на пользователя**, а не на проект: `~/.vibeide/mcp.json`.
- Нет файла — IDE создаёт его сама с пустым списком `{ "mcpServers": {} }`.
- Правка подхватывается на лету, перезапуск не нужен.
- Формат — **строгий JSON**: комментарии и висячие запятые файл не прочитают.
- Один процесс каждого сервера обслуживает **все окна** IDE сразу.

---

## 2. Структура файла

```json
{
  "mcpServers": {
    "имя-сервера": { /* запись */ }
  }
}
```

Имя сервера — ключ. Под ним сервер виден в настройках и в журнале.

---

## 3. Сервер-команда (stdio)

IDE запускает программу и говорит с ней через стандартный ввод-вывод.

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `command` | строка | **да** | Исполняемый файл. Запускается напрямую, без оболочки. |
| `args` | список строк | нет | Аргументы, по одному на элемент. |
| `env` | объект «строка: строка» | нет | Переменные окружения процесса. Сильнее окружения IDE, кроме опасных имён — см. ниже. |
| `cwd` | строка | нет | Рабочий каталог процесса. Не указан — наследуется каталог самой IDE. |

**Про `env`.** Процесс получает окружение IDE, а переменные из записи ложатся **поверх** него:
ключ, записанный для сервера, сильнее ключа, выставленного в системе.

Исключение — имена, через которые подменяют сам процесс: `PATH`, `LD_PRELOAD`, `LD_LIBRARY_PATH`,
`DYLD_INSERT_LIBRARIES`, `DYLD_LIBRARY_PATH`, `NODE_OPTIONS`, `PYTHONPATH`, в любом регистре. Из
записи они **не применяются никогда**, в журнал пишется строка с именем. Нужен другой `PATH` —
укажите полный путь в `command`.

**Про `cwd`.** Указывайте его, если сервер решает что-то по месту запуска. Процесс один на все
окна, поэтому каталог «открытого проекта» задать ему нельзя. Без `cwd` сервер стартует в каталоге
IDE, а это не каталог вашего проекта.

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-filesystem@2026.9.1", "/Users/me/notes"]
    }
  }
}
```

## 4. Сервер по адресу (HTTP или SSE)

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `url` | строка | **да** | Адрес сервера. |
| `type` | `"http"` или `"sse"` | нет | Транспорт. Не указан — см. ниже. |
| `headers` | объект «строка: строка» | нет | Заголовки запросов, например `Authorization`. Уходят и в поток SSE, и в отправку сообщений. |
| `headersHelper` | объект | нет | Программа, которая печатает заголовки. Запускается при каждом подключении, без оболочки. Поля: `command` — абсолютный путь; `args` — массив строк; `env` — переменные процесса, как у сервера-команды (опасные имена не применяются); `revision` — строка, смена которой переподключает сервер. |

**Как выбирается транспорт:**
- `"type": "sse"` — только SSE.
- `"type": "http"` — только Streamable HTTP.
- Без `type`, но в адресе есть `/sse` — SSE.
- Без `type` в остальных случаях — сначала HTTP, при ошибке SSE.

**Про `headers`.** Секрет в заголовке лежит в файле открытым текстом: `mcp.json` — в домашнем
каталоге, но в резервные копии и синхронизацию он уходит вместе с ним. Config Guard называет такой заголовок.

**Про `headersHelper`.** Токен остаётся у программы, которая его хранит, а в файле лежит только её путь.
Программа печатает в stdout один JSON-объект «строка: строка» и больше ничего; её заголовки ложатся поверх `headers`.
Ответ живёт только в памяти подключённого клиента: он не попадает ни в файл, ни в журнал, ни к гостевому агенту ACP.
Срок на ответ — 10 секунд. Не ответила, упала или напечатала не объект строк — сервер не подключается, и причина названа
без вывода программы: в выводе мог быть токен.
Сервер отвечает 401 на такой заголовок — это отозванный токен, и ошибка говорит, где взять новый.

```json
{
  "mcpServers": {
    "tracker": {
      "type": "http",
      "url": "https://mcp.tracker.example/mcp",
      "headersHelper": { "command": "/usr/local/bin/tracker-token", "args": ["--print-headers"] }
    }
  }
}
```

```json
{
  "mcpServers": {
    "docs": { "url": "https://mcp.example.com/mcp", "type": "http" }
  }
}
```

## 5. Что проверяется при загрузке

**Адрес:**
- Только `https://` или локальный адрес (`localhost`, `127.0.0.1`, `::1`). Иначе сервер не
  запустится с ошибкой.
- Две записи с одинаковым запуском (адрес, заголовки, помощник, команда) — ошибка: сервер работал бы дважды.
  Разные серверы на одном адресе допустимы — так живут, например, памяти разных команд.

**Команда:** `curl`, `wget`, `bash`, `sh`, `python`, `node` и подобные запускаются, но с
предупреждением в журнале.

**Config Guard** (`vibeide.configGuard.enabled`, по умолчанию включён) ищет в записях:
- запуск скачанного скрипта (`curl … | sh`) — критично;
- обёртку оболочки (`sh -c`) — высоко;
- отключённую песочницу (`--no-sandbox` и подобные) — критично;
- `npx` или `uvx` без точной версии пакета — средне;
- перекрытие опасных переменных (`PATH`, `LD_PRELOAD`, `NODE_OPTIONS` …) — критично;
- секрет прямо в `env` — критично;
- метасимволы оболочки в аргументах — средне;
- адрес не по HTTPS — высоко;
- логин и пароль в адресе (`user:pass@`) — высоко;
- секрет в `headers` открытым текстом — высоко;
- команда `headersHelper` — теми же правилами, что команда сервера.

Режим `vibeide.configGuard.mode`: `warn` (по умолчанию) — предупредить и запустить; `block` — не
запускать сервер с критичной находкой.

## 6. Сервер памяти VibeMemory

Если установлен VibeMemory (`~/.vibememory/bin/vibememory-mcp`), сервер `vibememory` подключается
**сам**, писать запись не нужно. Он запускается из домашнего каталога: запись в память без явного
проекта сервер отклоняет, а не кладёт в чужой.

Своя запись с именем `vibememory` сильнее найденной — например, чтобы указать другой путь.

**Каталог движка.** Здесь и ниже `~/.vibememory` — каталог по умолчанию.
Если в окружении оболочки задана `VIBEMEMORY_DIR`, IDE ищет сервер, помощник и токены команд там, как и сам CLI VibeMemory.
Пустая переменная считается незаданной, относительный путь IDE раскрывает от домашнего каталога и передаёт программам уже абсолютным.
Серверу и помощнику IDE передаёт эту переменную в `env`: IDE, запущенная из Dock, окружения оболочки не наследует.

**Имя проекта для записи называет сам сервер.**
IDE спрашивает его инструментом `project_resolve` про каждую открытую папку и пишет ответ в системную подсказку агента.
Что видит агент:
- проект есть — его имя и указание передавать его в `project`
- папка исключена владельцем или проекта в сторе нет — указание не писать в память для этой папки
- сервер не ответил за 3 секунды — строки нет, подсказка прежняя

По имени папки проект не угадывается: репозиторий называется по корню git, а владелец может переименовать или исключить папку правилом.

**Память команды по HTTPS.** Машина, подключённая к команде командой `vibememory connect --agent vibeide`, получает
в `~/.vibememory/tokens/<команда>/` файл токена, сайдкар `vibeide.json` без токена и готовый фрагмент конфигурации.
IDE читает только сайдкар и сама добавляет сервер `vibememory-<команда>`:
- `type: "http"`, адрес — `mcpUrl` из сайдкара (только https, http — лишь для этой машины)
- заголовок — через `headersHelper`: `~/.vibememory/bin/vibememory mcp-headers <команда> vibeide`
- `revision` — `tokenId` из сайдкара: новый токен из кабинета переподключает сервер сам

Файл токена и фрагмент с токеном IDE не открывает. `connect` и отключение команды подхватываются без перезапуска.
Своя запись с тем же именем сильнее найденной.
Сервер команды не видит ваш диск, поэтому на `project_resolve` отвечает списком проектов, доступных токену.
Агент получает этот список в подсказке и передаёт проект явно при каждой записи.
Инструменты модель видит как `vibememory-<команда>_<инструмент>`; сервер с именем инструмента длиннее 64 символов
модели не предлагается, и уведомление называет причину.

## 5.1. Только разрешённые инструменты — `tools`

Поле записи сервера `tools` — список имён инструментов, которые агент может видеть и вызывать.

```json
{
  "mcpServers": {
    "confluence": {
      "url": "https://mcp.example.com/mcp",
      "tools": ["search", "fetch_page"]
    }
  }
}
```

- **Нет поля** — все инструменты сервера, как раньше.
- **Пустой список** — ни одного: запись явно ничего не предлагает.
- Инструмента не из списка модель не видит, а вызов такого инструмента (в том числе из приложения MCP)
  отклоняется **до обращения к серверу** и пишется в журнал аудита как `mcp_tool_refused`.
- Имена — точно как их называет сервер, с учётом регистра.
- **Почему список, а не `readOnlyHint`:** спека MCP велит считать аннотации инструментов недоверенными, если сервер
  не доверенный. Профиль «только чтение» — это список, написанный вами, а не обещание сервера.

### 5.2. Инструмент, изменившийся после одобрения

Список `tools` закрепляет, **какие** инструменты есть, но не **что они говорят**. Описание инструмента уходит модели
дословно, поэтому сервер, переписавший описание уже одобренного инструмента, даёт модели указание, которого никто не
видел. Так работала кампания Deadbugz (август 2026): два безобидных инструмента, а после трёх вызовов — указание искать
SSH-ключи и учётки облаков.

- **Первое подключение сервера запоминается молча.** Добавить запись в `mcp.json` — и есть согласие.
- **Изменённый или новый инструмент скрывается от модели**, а его вызов отклоняется до обращения к серверу и пишется в
  аудит как `mcp_tool_refused` с причиной `changedAfterApproval`. Приходит уведомление с кнопками «Показать изменения»
  (редактор сравнения: одобрено ↔ сейчас, уведомление после него не закрывается) и «Принять». Решить можно и позже:
  карточка сервера в настройках VibeIDE → MCP перечисляет ожидающие инструменты, зачёркивает их и несёт те же две
  кнопки. Изменение и принятие пишутся в аудит (`mcp_tool_drift`, `mcp_tool_drift_approved`).
- **Удалённый инструмент не требует просмотра** — отсутствующий инструмент никому ничего не велит.
- **Сравнивается всё, что читает модель или на что опирается IDE:** имя, заголовок, описание, обе схемы, аннотации и
  блок приложения MCP, решающий видимость.
- **Правка команды или адреса записи — новый сервер**, он запоминается заново. Самообновление пакета под той же
  командой (`npx some-server` без версии) — нет: ровно для этого случая проверка и существует.
- **Проверка идёт сразу, а не при следующем запуске**, если сервер объявил `tools.listChanged`: список перечитывается по
  его сообщению. Иначе — при переподключении и по истечении срока годности списка.
- Выключается настройкой `vibeide.mcp.requireToolReapproval` (область — приложение: репозиторий выключить её не может).
  Выключенная проверка принимает изменения молча.
- **Чего проверка не ловит:** сервер, оставивший определения прежними и изменивший то, что возвращают вызовы. Вывод
  инструментов приходит модели в рамке «это данные, а не указания».

## 6.1. Приложения MCP (MCP Apps)

Запись в `mcp.json` для приложения не нужна: это возможность самого сервера.
Сервер объявляет у инструмента интерфейс, и после вызова инструмента чат показывает его окно
прямо под результатом.

**Как сервер это объявляет:**
- у инструмента `_meta.ui.resourceUri` — адрес ресурса со схемой `ui://`
- ресурс отдаёт HTML с типом `text/html;profile=mcp-app`
- `_meta.ui.visibility` — кто может вызывать инструмент: `["model"]`, `["app"]` или оба (по умолчанию оба)

**Что делает VibeIDE:**
- при подключении объявляет серверу расширение `io.modelcontextprotocol/ui`
- инструмент с видимостью только `["app"]` модели не показывает
- окно приложения изолировано: отдельный webview, политика безопасности из `_meta.ui.csp` ресурса
- показ только встроенный в чат; сэмплинг, скачивание файлов и правка контекста модели не предлагаются

**Что спрашивает у человека:**
- вызов инструмента из приложения — один раз на открытое окно, и только инструмент того же сервера с `app` в видимости
- открытие ссылки — каждый раз, и только `http` или `https`
- текст от приложения (`ui/message`) ложится в поле ввода и не отправляется; уже набранный вами черновик не перезаписывается

**Выключить:** настройка `chat.mcp.apps.enabled` = `false`.
Серверы переподключатся и перестанут получать объявление, окна в чате пропадут.

## 7. Чек-лист валидного файла

- [ ] Строгий JSON, без комментариев и висячих запятых.
- [ ] Корень — объект с полем `mcpServers`.
- [ ] У каждой записи есть либо `command`, либо `url`.
- [ ] `args` — список строк, а не одна строка с пробелами.
- [ ] Адрес — `https://` или локальный.
- [ ] Пакеты `npx` и `uvx` — с точной версией (`пакет@1.2.3`).
- [ ] Секреты — в окружении системы, а не в `env` файла: Config Guard считает секрет в `env` критичным.
- [ ] `PATH`, `LD_PRELOAD`, `NODE_OPTIONS` и родственные в `env` не пишите — они не применятся.
