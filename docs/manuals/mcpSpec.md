# Спецификация формата `mcp.json` (VibeIDE)

← [Документация](../README.md)

> **Как этим пользоваться.** Скопируйте этот файл целиком своей LLM и попросите:
> *«По этой спецификации собери мне `mcp.json` для VibeIDE: я хочу подключить сервер …»*.
> Модель вернёт готовый JSON. Здесь есть всё: где лежит файл, поля записи, как выбирается
> транспорт, что проверяется при загрузке и чего формат не умеет. Выходить в интернет и читать
> исходники VibeIDE не нужно.

Канонический источник схемы — тип `MCPConfigFileEntryJSON` в
`src/vs/workbench/contrib/vibeide/common/mcpServiceTypes.ts`. Этот файл описывает тот же формат
человеческим языком.

---

## 1. Что это и где лежит

`mcp.json` — список MCP-серверов, инструменты которых получает агент VibeIDE.

- Файл **один на пользователя**, а не на проект: `~/.vibeide/mcp.json`.
- Нет файла — IDE создаёт его сама с пустым списком `{ "mcpServers": {} }`.
- Правка подхватывается на лету, перезапуск не нужен.
- Формат — **строгий JSON**: комментарии и висячие запятые файл не прочитают.
- Один процесс каждого сервера обслуживает **все окна** IDE сразу.

---

## 2. Структура файла

```json
{
  "mcpServers": {
    "имя-сервера": { /* запись */ }
  }
}
```

Имя сервера — ключ. Под ним сервер виден в настройках и в журнале.

---

## 3. Сервер-команда (stdio)

IDE запускает программу и говорит с ней через стандартный ввод-вывод.

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `command` | строка | **да** | Исполняемый файл. Запускается напрямую, без оболочки. |
| `args` | список строк | нет | Аргументы, по одному на элемент. |
| `env` | объект «строка: строка» | нет | Переменные окружения процесса. **См. оговорку ниже.** |
| `cwd` | строка | нет | Рабочий каталог процесса. Не указан — наследуется каталог самой IDE. |

**Про `env`.** Переменные из файла кладутся первыми, а окружение IDE — поверх них. Значит,
переменную, которая уже есть в окружении IDE (например `PATH` или ключ, выставленный в системе),
из `mcp.json` **не переопределить** — победит значение окружения.

**Про `cwd`.** Указывайте его, если сервер решает что-то по месту запуска. Процесс один на все
окна, поэтому каталог «открытого проекта» задать ему нельзя. Без `cwd` сервер стартует в каталоге
IDE, а это не каталог вашего проекта.

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["@modelcontextprotocol/server-filesystem@2026.9.1", "/Users/me/notes"]
    }
  }
}
```

## 4. Сервер по адресу (HTTP или SSE)

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `url` | строка | **да** | Адрес сервера. |
| `type` | `"http"` или `"sse"` | нет | Транспорт. Не указан — см. ниже. |
| `headers` | объект «строка: строка» | нет | **Сейчас не отправляются** — см. оговорку. |

**Как выбирается транспорт:**
- `"type": "sse"` — только SSE.
- `"type": "http"` — только Streamable HTTP.
- Без `type`, но в адресе есть `/sse` — SSE.
- Без `type` в остальных случаях — сначала HTTP, при ошибке SSE.

**Про `headers`.** Поле принимается, но в запрос к серверу **не уходит** — ни при HTTP, ни при SSE.
Сервер, которому нужен заголовок авторизации, так не подключить. Это известный дефект, а не
особенность формата.

```json
{
  "mcpServers": {
    "docs": { "url": "https://mcp.example.com/mcp", "type": "http" }
  }
}
```

---

## 5. Что проверяется при загрузке

**Адрес:**
- Только `https://` или локальный адрес (`localhost`, `127.0.0.1`, `::1`). Иначе сервер не
  запустится с ошибкой.
- Два активных сервера на одном хосте и порту — ошибка конфликта портов.

**Команда:** `curl`, `wget`, `bash`, `sh`, `python`, `node` и подобные запускаются, но с
предупреждением в журнале.

**Config Guard** (`vibeide.configGuard.enabled`, по умолчанию включён) ищет в записях:
- запуск скачанного скрипта (`curl … | sh`) — критично;
- обёртку оболочки (`sh -c`) — высоко;
- отключённую песочницу (`--no-sandbox` и подобные) — критично;
- `npx` или `uvx` без точной версии пакета — средне;
- перекрытие опасных переменных (`PATH`, `LD_PRELOAD`, `NODE_OPTIONS` …) — критично;
- секрет прямо в `env` — критично;
- метасимволы оболочки в аргументах — средне;
- адрес не по HTTPS — высоко;
- логин и пароль в адресе (`user:pass@`) — высоко.

Режим `vibeide.configGuard.mode`: `warn` (по умолчанию) — предупредить и запустить; `block` — не
запускать сервер с критичной находкой.

---

## 6. Сервер памяти VibeMemory

Если установлен VibeMemory (`~/.vibememory/bin/vibememory-mcp`), сервер `vibememory` подключается
**сам**, писать запись не нужно. Он запускается из домашнего каталога: запись в память без явного
проекта сервер отклоняет, а не кладёт в чужой.

Своя запись с именем `vibememory` сильнее найденной — например, чтобы указать другой путь.

---

## 7. Чек-лист валидного файла

- [ ] Строгий JSON, без комментариев и висячих запятых.
- [ ] Корень — объект с полем `mcpServers`.
- [ ] У каждой записи есть либо `command`, либо `url`.
- [ ] `args` — список строк, а не одна строка с пробелами.
- [ ] Адрес — `https://` или локальный.
- [ ] Пакеты `npx` и `uvx` — с точной версией (`пакет@1.2.3`).
- [ ] Секреты — не в `env` файла, а в окружении системы.
- [ ] На `headers` для авторизации не рассчитывайте — они сейчас не отправляются.
