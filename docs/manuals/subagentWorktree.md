# Изоляция роли в рабочем дереве git — как начать

← [Документация](../README.md)

Роль-исполнитель («implement-step») по умолчанию правит файлы прямо в открытой папке: её
незаконченная работа сразу видна вам, вашей сборке и соседнему прогону. Изоляция уводит такой
прогон в отдельное рабочее дерево git, и до слияния его правок в проекте нет.

---

## 1. Предусловия

- Открытая папка — **репозиторий git**. Без репозитория дерево создавать негде, и прогон с
  запрошенной изоляцией не начнётся.
- В репозитории задана личность коммитов (`user.name`, `user.email`). Коммит в ветке дерева и
  слияние делаются от вашего имени, а не служебного.
- Свободное имя ветки. Имя выводится из идентификатора прогона (`vibe-agent-…`); занятое имя —
  отказ, а не молчаливое переиспользование чужой ветки.

## 2. Включение

Настройка: `vibeide.subagent.worktree` → `true` (по умолчанию выключено).

Изоляция не включается сама нигде: дерево меняет то, где окажется работа, и решать это за вас
нельзя.

## 3. Что происходит дальше

1. Перед запуском роли создаётся дерево `.vibe-worktrees/<ветка>` и ветка от текущего `HEAD`.
   Папка дерева прячется от `git status` через `.git/info/exclude` — ваш `.gitignore` не трогается.
2. Роль работает **целиком внутри дерева**: правки, чтения и команды оболочки. Попытка выйти из
   дерева (`cd ..`, `git -C …`) отклоняется с объяснением.
3. По окончании прогона — **коммит в ветке дерева, всегда**, чем бы прогон ни кончился.
4. Слияние — **только под автопилотом и только при успехе**. В обычном режиме ветка остаётся вам.

## 4. Где искать работу роли

Ответ роли называет ветку и путь дерева, а счётчик `W:` в строке состояния показывает, сколько
деревьев ждёт решения — включая оставшиеся от прошлых запусков IDE.

**Из IDE — команда «VibeIDE: Деревья агентов»** (она же по щелчку на счётчике): выбираете дерево и действие —
влить в проект, открыть папку или выбросить вместе с работой. Слияние идёт в том же порядке, что и вручную
(сначала слить, потом убрать), а «выбросить» спрашивает подтверждение: отменить его нечем.

То же самое руками, если вы предпочитаете терминал:

```bash
git log --oneline vibe-agent-<имя>
git diff HEAD...vibe-agent-<имя>
```

Влить самому:

```bash
git merge --no-ff vibe-agent-<имя>
git worktree remove .vibe-worktrees/vibe-agent-<имя>
git branch -d vibe-agent-<имя>
```

Порядок обратный — потеря работы при конфликте: удалив дерево первым, чинить конфликт было бы
уже нечем.

Отказаться от работы роли целиком:

```bash
git worktree remove --force .vibe-worktrees/vibe-agent-<имя>
git branch -D vibe-agent-<имя>
```

## 5. Чего ожидать

- **«Роль ничего не записала»** — дерево пустое, коммитить было нечего. Обычный исход для прогона,
  который только читал.
- **«Слить ветку не удалось»** — вероятен конфликт. Работа при этом не потеряна: и дерево, и ветка
  на месте, разобрать конфликт поможет команда «Разрешить конфликты слияния».
- **Деревья переживают перезапуск IDE** — они перечисляются по данным git, а не по памяти окна.
  Оставшиеся от упавших прогонов деревья видны в `git worktree list`.
- Изоляция действует только на роль-исполнителя. Читающие роли (разведка, ревью) ничего не пишут,
  и отдельное дерево им не нужно.
