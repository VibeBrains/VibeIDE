# Как работать со спеками

← [Дерево документации](../README.md)

> **Единственный источник правды для справки в IDE.** Текст между маркерами `specs-help` ниже
> подставляется в модалку по кнопке «?» в заголовке панели «Спеки» — генератором
> `scripts/gen-specs-help.mjs` на каждой сборке. Правим здесь, и только здесь.

<!-- specs-help:start -->
Спека описывает фичу **до кода**: сначала договариваемся о поведении, потом пишем реализацию. Мелочь спекой не оформляют — это для задач, где цена недопонимания выше цены документа.

Спеки живут в `docs/specs/<id>/` (папка настраивается ключом `vibeide.specsPanel.root`):

- **PRODUCT.md** — *что* делает фича: поведение нумерованными проверяемыми инвариантами, без деталей реализации.
- **TECH.md** — *как* она сделана: реализация, заземлённая в коде.

## 1. Создать

Две кнопки в заголовке панели:

- **✨ Спека из задачи** — опишите фичу своими словами, можно приложить макеты и скриншоты (уходят в vision-разбор) или ТЗ в PDF (текст подмешивается в запрос). Агент напишет `PRODUCT.md` по скиллу `write-product-spec`, задав уточняющие вопросы, если контекста не хватает.
- **＋ Новая спека (пустая)** — только идентификатор; создаст `PRODUCT.md` из минимальной заготовки со `status: draft`.

Обе команды доступны и из меню «мозга» в заголовке окна — панель для этого открывать не нужно.

## 2. Проверить и утвердить

Это ваш шаг, агент его не делает. Прочитайте `PRODUCT.md`: инварианты должны быть **проверяемыми** («кнопка недоступна, пока поле пустое»), а не пожеланиями («удобный экспорт»).

Согласны — **правый клик по пилюле S** и выберите «Утверждена». Пилюля посинеет.

То же самое руками: во фронтматтере `status: draft` → `status: approved`, то есть первые строки файла должны выглядеть так:

```yaml
---
status: approved
---
```

До этого момента «Реализовать спеку» недоступна — это защита от кодирования по несогласованному описанию.

## 3. TECH.md — по потребности

Пилюля **T** тусклая пунктирная = файла нет. Клик по ней создаст заготовку. Нужен, когда реализация неочевидна и решения стоит зафиксировать до кода; для простой фичи можно обойтись одним `PRODUCT.md`.

## 4. Реализовать

Правый клик по спеке → **«Реализовать спеку»** (пункт появляется только у `approved`). Тред чата привяжется к спеке, и агент начнёт работу по скиллу `implement-specs`. Он же переведёт статус в `implemented`, когда фича собрана и проверена.

## 5. Дрейф — необязательная страховка

Можно объявить область, которой фича ограничена:

```yaml
---
status: approved
scope:
  - src/vs/workbench/contrib/myFeature/**
---
```

Если привязанный тред полезет править файл **вне** `scope`, реализация встанет на паузу с чипом «⏸ На паузе» — сигнал, что агент ушёл не туда. Спека без `scope` границ не задаёт, дрейфа нет.

Поведение настраивается ключом `vibeide.specs.driftPause`:

| Значение | Когда паузит |
|---|---|
| `always` | при любой правке вне `scope` |
| `manual-only` *(по умолчанию)* | только когда автопилот выключен; под автопилотом — просто уведомление |
| `never` | никогда, только уведомление |

## Пилюли в строке

| | Значение |
|---|---|
| **P** | `PRODUCT.md` — клик открывает |
| **T** | `TECH.md` — заполненная открывает, тусклая пунктирная **создаёт** |
| **S** | статус: ⬜ серый — `draft`, 🟦 синий — `approved`, 🟩 зелёный — `implemented`. **ПКМ — сменить** |

Наведите на любую пилюлю — через секунду появится подсказка.

## Правый клик по спеке

Открыть `PRODUCT.md` / `TECH.md`, создать `TECH.md`, **реализовать спеку** (только `approved`), показать в проводнике, удалить спеку (в корзину, с подтверждением).

## Весь маршрут одной строкой

**Создать** → агент пишет `PRODUCT.md` (`draft`) → **вы проверяете и ставите `approved`** → при желании `TECH.md` → «Реализовать спеку» → агент кодит и ставит `implemented`.
