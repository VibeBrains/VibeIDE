# Спека формата `SKILL.md` — навыки агента

← [Дерево документации](../README.md)

> **Как этим пользоваться:** скопируйте этот файл целиком своей LLM и попросите собрать
> `SKILL.md` для вашей задачи. Здесь есть всё: обязательные и необязательные поля, ограничения,
> раскладка папки, наши расширения и рабочие примеры. Выходить в интернет и читать исходники
> VibeIDE не нужно.

## Что такое навык

Навык — папка с файлом `SKILL.md`, в котором записано, **как делать** повторяющуюся работу:
порядок шагов, договорённости проекта, грабли, формат результата. Агент подхватывает навык, когда
задача совпадает с его описанием, или когда вы вызываете его явно: `/skill:<имя>`.

Отличие от правил проекта (`.vibe/rules`, `AGENTS.md`): правила действуют **всегда** и описывают,
как вести себя вообще. Навык подключается **под задачу** и описывает конкретную процедуру. Правило
«комментарии в коде — по-английски» действует постоянно; навык «разобрать merge-конфликты» нужен
раз в неделю и в остальное время только занимал бы контекст.

## Где лежит

```
.vibe/skills/<имя-навыка>/
├── SKILL.md          # обязательный
├── scripts/          # необязательно: скрипты-помощники
├── references/       # необязательно: подробности, которые агент читает по требованию
└── assets/           # необязательно: шаблоны, образцы
```

**Имя папки должно совпадать с полем `name`.** Расхождение ломает вызов молча: в списке одно,
обращение идёт по другому. Наша проверка `vibe skills validate` это ловит.

## Минимальный файл

```markdown
---
name: release-notes
description: Сборка заметок к релизу из истории коммитов. Использовать, когда просят подготовить changelog, описать что вошло в версию или собрать release notes перед публикацией.
---

# Заметки к релизу

1. Определить базлайн: последний опубликованный тег (`git tag --list "v*"`).
2. Собрать коммиты после него, сгруппировать по типу.
3. Писать от лица пользователя: что он теперь может, а не какие файлы изменились.
4. Чисто внутренние правки не упоминать.
```

Двух полей достаточно. Всё остальное — по необходимости.

## Поля верхнего уровня

Список **закрытый**: формат `SKILL.md` — открытый стандарт (Agent Skills), и сторонние
проверяющие отвергают неизвестные поля верхнего уровня. Свои данные кладите в `metadata`.

| Поле | Обяз. | Ограничения | Смысл |
|---|---|---|---|
| `name` | да | ≤ 64 символа, строчные латинские буквы, цифры и одиночные дефисы (не по краям); **совпадает с именем папки** | Идентификатор. По нему навык вызывается: `/skill:release-notes` |
| `description` | да | ≤ 1024 символа | Когда навык применять. От качества этого поля зависит, подхватится ли он вообще — см. ниже |
| `compatibility` | нет | ≤ 500 символов | Что нужно для работы: внешние программы, доступ в сеть. Читается **до** раскрытия навыка |
| `allowed-tools` | нет | список через пробел | Инструменты, которые навыку нужны |
| `license` | нет | строка | Лицензия навыка, если вы его распространяете |
| `metadata` | нет | ключ-значение | Всё остальное, включая наши расширения |

## Описание решает, подхватится ли навык

Из всего файла агент сначала видит только `name` и `description` — тело подгружается, если
описание совпало с задачей. Поэтому описание пишется не про устройство навыка, а про **ситуацию
пользователя**, и включает случаи, когда предметная область не названа прямо.

Плохо:

```yaml
description: Работа с CSV.
```

Хорошо:

```yaml
description: Разбор табличных данных — сводные показатели, производные столбцы, графики, чистка мусора. Использовать, когда у пользователя есть CSV, TSV или Excel и он хочет посмотреть, преобразовать или показать данные, даже если слова «CSV» и «анализ» не прозвучали.
```

Формулируйте повелительно и перечисляйте ситуации, а не возможности.

## Наши расширения — внутри `metadata`

Они работают только в VibeIDE; в другом клиенте просто игнорируются.

```yaml
---
name: deploy-staging
description: Выкладка на стенд по регламенту проекта. Использовать при просьбах выкатить, задеплоить или обновить staging.
compatibility: >
  Нужны docker и доступ к внутреннему реестру. Требуется сеть.
allowed-tools: Bash Read
metadata:
  vibeVersion: "1.0.0"        # версия формата пакета навыка
  min-vibeide: "1.12.0"       # минимальная версия IDE
  depends:                    # навыки, которые раскрываются перед этим (без циклов)
    - check-migrations
  triggers:                   # фразы для неявного подхвата, сверх description
    - выкати на стенд
    - задеплой staging
  glob: "deploy/**"           # навык уместен, когда правки идут в этих файлах
  keywords: [деплой, стенд, выкатка]
  precheck: scripts/check.sh  # путь проверки готовности внутри папки навыка
  tags: [ops]                 # ПЕРВЫЙ тег — раздел в списке выбора навыков (см. ниже)
  locale: ru
---
```

## Разделы в списке выбора

**Первый тег из `tags` — это раздел**, под которым навык встанет в списке «Навыки — выбрать для
сессии». Остальные теги остаются в поиске.

- Регистр и пробелы не важны: `Ops`, `ops` и `  ops  ` — один раздел.
- Тега нет — навык попадает в раздел «Без раздела», а не исчезает между заголовками.
- Разделы идут по алфавиту, «Без раздела» последним, навыки внутри — тоже по алфавиту. Порядок
  фиксированный: список, который переставляет себя между открытиями, стоит дороже, чем экономит —
  привычка перестаёт работать, и человек перечитывает то, что уже знал.
- Разделы появляются, только когда их больше одного и навыков хотя бы восемь. Один заголовок над
  всем списком — не структура, а лишняя строка.

Отдельного поля `domain` намеренно нет: два способа сказать одно и то же означали бы, что у половины
уже написанных навыков нет ни одного из них.

## Тело файла

**До 500 строк.** Не запрет, а бюджет внимания: тело целиком попадает в контекст, когда навык
активируется, и конкурирует там со всем остальным. Подробности выносите в `references/` и
ссылайтесь на них относительным путём — агент прочитает, когда понадобится.

Что писать:

- **порядок шагов** — то, чего агент не угадает: последовательность, предусловия, чем проверить;
- **договорённости вашего проекта** — куда класть, как называть, что запрещено;
- **грабли** — то, что противоречит здравым ожиданиям. Без явного предупреждения агент наступит;
- **шаблон результата** — конкретная структура работает лучше описания словами.

Чего не писать: объяснений того, что модель и так знает («PDF — это формат документов…»), и
перечня равнозначных вариантов («можно взять любую из четырёх библиотек»). Выберите одну и
назовите остальные одной строкой.

## Проверка

```bash
npx vibe skills validate
```

Проверяются: наличие и форма полей, совпадение имени с папкой, длины, отсутствие выходов за
пределы папки навыка, циклы в `depends`. Про слишком длинное тело — предупреждение.

## Локализация

Рядом с `SKILL.md` можно положить `SKILL.<локаль>.md` (например `SKILL.ru.md`). Выбирается файл
по языку интерфейса, с откатом на базовый.
