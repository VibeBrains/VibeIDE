# Claude Code с телефона: мост в Telegram

Мануал «как начать». Про мост для собственного агента VibeIDE — [telegramBridge.md](telegramBridge.md);
здесь только вторая половина: запуск **Claude Code** с телефона, с кнопками подтверждения.

## Что это даёт

Вы пишете боту задачу, Claude Code выполняет её **на вашей машине**, а когда собирается сделать
что-то существенное — запустить команду, переписать файл — присылает карточку с тремя кнопками:

- **Разрешить** — действие выполняется;
- **Отклонить** — действие не выполняется, агент узнаёт об отказе;
- **Поправить** — действие отменяется, а следующее ваше сообщение уходит агенту как указание,
  что сделать вместо этого. Это не отказ, а перенаправление: не нужно заново набирать всю задачу.

## Чего мост НЕ умеет

**Вклиниться в сессию Claude Code, уже открытую у вас на компьютере.** Он запускает свои сессии
и продолжает их по идентификатору. Это ограничение самого SDK, а не нашей реализации; попросить
телефон «дописать вон в тот терминал» нельзя.

## Шаг 1. Мост в Telegram

Если бот ещё не привязан — сделайте это по [telegramBridge.md](telegramBridge.md): токен, привязка
чата, при необходимости прокси. Claude Code использует **тот же бот и тот же чат**, отдельного
заводить не нужно.

## Шаг 2. Первый запуск

В привязанном чате:

```
/cc посмотри, почему падает сборка, и почини
```

При самом первом вызове мост доустановит Claude Agent SDK — разовая операция на минуту, о ней
придёт сообщение. **SDK везёт с собой собственную копию Claude Code** и не использует ту, что
стоит у вас в системе: так устроен пакет. Поэтому вес не исчезает, а переезжает в служебную папку
VibeIDE, где обновляется отдельно от релизов IDE. Нужен работающий `npm`.

Дальше:

| Команда | Что делает |
|---|---|
| `/cc <задача>` | поставить задачу; следующая `/cc` продолжит ту же сессию |
| `/cc_stop` | прервать прогон |
| `/cc_status` | состояние моста и установки SDK |

Обычный текст без слэша по-прежнему идёт **агенту VibeIDE**, а не Claude Code — два исполнителя
в одном чате различаются именно командой.

## Шаг 3. Рабочая папка

Claude Code работает в папке, открытой в том окне, к которому привязан чат. Переключить окно —
`/use <проект>`, посмотреть список — `/projects`. Если папка не открыта, мост откажется запускать
задачу, а не выберет что-нибудь сам: «он работал не в той папке» — самый дорогой сюрприз здесь.

## Настройки

| Настройка | Смысл |
|---|---|
| `vibeide.claudeCode.permissionMode` | `default` — спрашивать; `plan` — только изучать и предлагать план; `acceptEdits` — правки файлов без вопроса, команды по-прежнему спрашиваются |
| `vibeide.claudeCode.allowedTools` | инструменты без подтверждения, например `Read`, `Grep` |
| `vibeide.claudeCode.disallowedTools` | запрещённые полностью; запись вида `Bash(rm *)` запрещает только совпадающие вызовы |
| `vibeide.claudeCode.mirrorReadOnly` | присылать подтверждения и на чтение (по умолчанию нет) |

**Режим `bypassPermissions` намеренно недоступен.** Он снимает подтверждения целиком, а ради них
мост и сделан.

**Про `allowedTools` стоит знать одно:** имя без уточнения (`Bash`) разрешает **все** вызовы
инструмента, и подтверждение по нему не придёт больше никогда. Уточнённая запись
(`Bash(npm test)`) разрешает только совпадающее, остальное продолжает спрашиваться.

## Что происходит, если вы не ответили

**Ничего.** Прогон стоит и ждёт вашего касания хоть сутки — так решено сознательно. Отказ по
таймауту выглядел бы аккуратнее, но означал бы, что агент пошёл обходным путём в момент, когда вы
просто были за рулём, и узнали бы вы об этом постфактум.

Снять ожидание можно только остановкой: `/cc_stop`. Незакрытые запросы прерванного прогона
считаются **отклонёнными** — молчание никогда не превращается в согласие.

## Безопасность

Claude Code получает те же права на файлы, что и вы. Мост отвечает только привязанному чату
(чужой чат отсекается до всякой обработки), но за самим агентом стоит следить теми же настройками,
что и в терминале: `disallowedTools` для того, чего он не должен трогать никогда, и `plan` для
задач, где вы хотите сперва увидеть замысел.

## Проверить, что работает

1. `/cc_status` — должен ответить состоянием SDK.
2. `/cc покажи, что в этой папке` — придёт ответ без единого подтверждения (чтение не спрашивается).
3. `/cc создай файл hello.txt со словом привет` — должна прийти карточка с кнопками.
