# Спецификация формата `.vibe/agents.json` (VibeIDE)

← [Документация](../README.md)

> **Как этим пользоваться.** Скопируйте весь этот файл целиком своей LLM и попросите:
> *«По этой спецификации собери мне `.vibe/agents.json`: я хочу звать в проект Claude Code»*.
> Модель вернёт готовый JSONC, который кладётся в `.vibe/agents.json` в корне рабочей папки.
> Это самодостаточный документ: всё, что нужно для генерации валидного файла, — ниже.

Канонический источник схемы — TypeScript-типы в
`src/vs/workbench/contrib/vibeide/common/acp/vibeAgentsFile.ts`. Этот файл описывает тот же формат человеческим языком.

---

## 1. Что это и зачем

`agents.json` — реестр **внешних агентов**, которых можно позвать в эту рабочую папку помимо собственного агента VibeIDE. Кладётся в репозиторий: набор агентов у команды общий, как дев-стек.

Внешний агент — отдельный процесс, говорящий с IDE по **ACP** (Agent Client Protocol, JSON-RPC 2.0 поверх stdio). Смысл протокола в том, что агент перестаёт быть соседом по папке:

- перед правкой он **спрашивает разрешение**, и вопрос уходит человеку;
- вместе с вопросом приезжает **дифф** — «было → стало» ещё до записи на диск;
- по этому диффу IDE снимает **чекпоинт** (откатить чужую правку можно так же, как свою) и пишет правку в **журнал активности** (View → Output → «Активность агента VibeIDE»).

- Формат — **JSONC**: допускаются `//`-комментарии и висячие запятые.
- **Файлов два, формат у них один:**
  - `<проект>/.vibe/agents.json` — агенты проекта, едет в репозитории, общий для команды;
  - `~/.vibe/agents.json` — агенты этой машины, во всех проектах. Сюда ложится агент, скачанный из реестра ACP
    бинарём: абсолютный путь к нему в общем файле команды был бы бессмыслен.
- **При совпадении `id` проектная запись сильнее машинной.** Список показывает агентов проекта первыми, машинные — следом.
- **Отсутствие файлов = сегодняшнее поведение.** Без них внешних агентов просто нет.
- **Одна опечатка не роняет реестр:** битая запись пропускается с предупреждением, остальные работают. Проблема верхнего уровня (не JSON, нет массива `agents`) отключает файл целиком.

## 2. Структура файла

```jsonc
{
  "version": 1,
  "agents": [
    { /* запись */ }
  ]
}
```

---

## 3. Поля записи

| Поле | Тип | Обяз. | Умолчание | Смысл |
|---|---|---|---|---|
| `id` | строка | **да** | — | Уникальный ключ в пределах файла. По нему агента зовут и находят в логах. |
| `command` | строка | **да** | — | Исполняемый файл. Запускается **напрямую, без оболочки**. |
| `args` | список строк | нет | `[]` | Аргументы, **по одному на элемент**. |
| `name` | строка | нет | значение `id` | Имя для человека: видно в чате и в ошибках. |
| `env` | объект «строка: строка» | нет | `{}` | Переменные окружения поверх унаследованных. |
| `dir` | строка | нет | корень проекта | Рабочая папка агента относительно корня. |
| `active` | булево | нет | `true` | `false` оставляет запись документированной, но вне списка. |
| `mcpServers` | список строк | нет | `[]` | Имена MCP-серверов из `~/.vibeide/mcp.json`, которые получит этот гость. Пусто — ни одного. |
| `registry` | объект `{ "id", "version" }` | нет | — | Откуда запись: id агента в реестре ACP и версия, которую она запускает. Ставит импорт из реестра (§4.2); по нему вкладка предлагает обновление. Руками писать не нужно; запись без него обновление не трогает никогда. |

### Почему `args` — список, а не строка

Команда запускается без оболочки. `"command": "npx -y пакет"` означает поиск файла с именем `npx -y пакет` целиком — такого файла нет. Правильно:

```jsonc
{ "command": "npx", "args": ["-y", "пакет"] }
```

Запись с `args` строкой отбрасывается с жалобой.

## 4. Готовые рецепты

### Claude Code

Сам `claude` по ACP разговаривать **не умеет** — нужен официальный адаптер:

```jsonc
{
  "id": "claude",
  "name": "Claude Code",
  "command": "npx",
  "args": ["-y", "@agentclientprotocol/claude-agent-acp"]
}
```

Требует входа: один раз выполните `claude /login` в терминале. Без входа первый же запрос вернёт «не авторизован», и IDE покажет, как войти.

> Пакет `@zed-industries/claude-code-acp` — прежнее имя того же адаптера, помечен устаревшим. В новых файлах используйте `@agentclientprotocol/claude-agent-acp`.

### OpenHands

Адаптер **не нужен** — CLI OpenHands говорит на ACP сам, подкоманда `acp`:

```jsonc
{
  "id": "openhands",
  "name": "OpenHands",
  "command": "openhands",
  "args": ["acp"]
}
```

CLI ставится отдельно. После установки один раз запустите `openhands` и через `/settings` выберите LLM-провайдера и ключ — ACP-режим читает настройки оттуда, поэтому ключ в `agents.json` писать не нужно.

### Агент для одного пакета монорепо

```jsonc
{
  "id": "web",
  "name": "Claude Code (web)",
  "command": "npx",
  "args": ["-y", "@agentclientprotocol/claude-agent-acp"],
  "dir": "packages/web"
}
```

### Свой агент

Подойдёт любой процесс, реализующий ACP на stdio: он должен отвечать на `initialize`, `session/new`, `session/prompt` и присылать `session/update`.

```jsonc
{
  "id": "custom",
  "command": "/usr/local/bin/my-acp-agent",
  "args": ["--stdio"],
  "env": { "MY_AGENT_PROFILE": "project" }
}
```

## 4.1. MCP-серверы для гостя — `mcpServers`

```jsonc
{
  "id": "claude",
  "command": "/Users/имя/.local/bin/claude",
  "args": ["--acp"],
  // Гость получит ИМЕННО эти серверы и никакие другие.
  "mcpServers": ["filesystem", "docs"]
}
```

**Гость подключается к серверам сам.** ACP передаёт ему не адрес нашего шлюза, а **конфигурации
серверов** — команду с аргументами и окружением либо адрес с заголовками
([спецификация ACP](https://agentclientprotocol.com/protocol/session-setup)). Отсюда всё остальное
в этом разделе.

**Поэтому список поимённый и по умолчанию пустой.** Вместе с конфигурацией уезжают `env` и
`headers`, а там бывают ключи. Значения «отдать всё» не предусмотрено даже как вариант: список,
который растёт сам при добавлении сервера в `mcp.json`, однажды увёз бы гостю то, чего вы не имели
в виду.

**Сервер со списком `tools` не экспортируется.** Ваш список разрешённых инструментов действует в
вызове VibeIDE, а гость нас не спрашивает — экспорт снял бы ограничение молча. Такой сервер
пропускается, и причина пишется в журнал («Активность агента VibeIDE»).

**Что ещё не уедет, и почему это говорится вслух:**

| Случай | Что происходит |
|---|---|
| Сервер выключен тумблером в настройках | Пропускается: выключенный у вас не должен работать у гостя |
| В записи нет ни `command`, ни `url` | Пропускается — передавать нечего |
| `"type": "sse"` | Пропускается: в ACP этот транспорт объявлен устаревшим |
| Имени нет в `mcp.json` | Пропускается — опечатка в политике не должна выглядеть как поломка гостя. Сюда же относится встроенный сервер памяти `vibememory`: в панели MCP он виден, но в `mcp.json` не записан |
| Запись по `url`, а гость не объявил поддержку MCP поверх HTTP | Отсеивается при рукопожатии, строкой в журнале |

`cwd` записи сервера гостю не передаётся: такого поля в ACP нет.

## 4.2. Из реестра ACP — «Добавить из реестра ACP»

Реестр ACP — курируемый список агентов, говорящих на ACP (`https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json`,
адрес меняется настройкой `vibeide.acp.registryUrl`). Кнопка во вкладке «Внешние агенты» (или команда
«Внешние агенты: добавить из реестра ACP») показывает его список, и запись в `agents.json` собирается сама.

- **Пакет запускается ровно той версии, что в реестре:** `npx @vendor/agent@1.2.3`, `uvx agent==1.2.3`. Реестр
  пересобирается ежечасно — без точной версии под той же записью однажды запустилось бы то, что опубликовано в день
  запуска.
- **`--yes` у `npx` не пишется:** npm подразумевает его сам, когда stdin — не терминал, а у ACP-агента stdin — канал
  протокола. Флаг же — находка Config Guard.
- **Бинарь ставится только со сверкой `sha256`** из реестра: скачанное принимается, только если сумма совпала, и ложится
  в профиль VibeIDE. Такая запись пишется только в `~/.vibe/agents.json`.
- **Что отклоняется и почему** — называется словами в списке:
  - у сборки нет `sha256` (в реестре таких почти половина) — скачанное нечем проверить;
  - нет сборки для этой платформы;
  - архив `tar.bz2`, `tar.xz`, `7z` — VibeIDE распаковывает только `zip` и `tar.gz`;
  - команда внутри архива указывает за его пределы;
  - пакет без точной версии.
  Такого агента можно подключить вручную по этой спеке.
- **Перед записью — подтверждение:** что будет запускаться или скачиваться, лицензия, откуда исходники, в какой файл
  ляжет запись. Пакет можно положить в проект или на машину.
- **Обновление** предлагается кнопкой «Обновить X: A → B» у агента, пришедшего из реестра. Меняются только `command`,
  `args` и `registry`; ваше имя агента, `mcpServers`, `dir` и комментарии в файле остаются как были. Новая версия бинаря
  ставится рядом со старой, старая удаляется после успешной записи. Открытые сессии работают на прежней версии до
  переподключения.
- Добавление и обновление пишутся в журнал аудита (`acp_agent_installed`).

## 5. Что нельзя класть в файл

**Ключи и токены.** Файл лежит в репозитории. В `env` передавайте только безобидные настройки; секреты держите в окружении машины или в `~/.vibe/.env` — унаследованное окружение агенту и так достаётся.

## 6. Чего ожидать при запуске

1. IDE запускает процесс и здоровается (`initialize`), запоминая объявленные агентом способы входа.
2. Создаётся сессия в рабочей папке (`session/new`).
3. Задача уходит агенту (`session/prompt`), ответ приходит потоком.
4. Перед каждым действием, требующим разрешения, показывается вопрос с вариантами, которые предложил **сам агент**. Закрыть вопрос, не выбрав ничего, — это отказ.
5. Чекпоинт снимается **до** правки; при отказе он отбрасывается.

**Чужой агент тратит СВОЙ счёт, а не ваши ключи — и в счётчике токенов VibeIDE его нет.** Агент,
входящий по подписке (Claude Code через Claude Agent SDK — типичный случай), расходует лимиты этой
подписки: правило вендора действует и сейчас — «Claude Agent SDK, `claude -p`, and third-party app
usage still draw from your subscription's usage limits», и сторонние приложения названы там прямо
([support.claude.com](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan),
обновление от 15 июня приостановило переход на отдельный кредит). Отсюда два следствия. Первое:
стоимость хода, которую показывает вкладка «Внешние агенты», приходит от самого агента и живёт
отдельно от бюджета BYOK-провайдеров — складывать их в одну сумму нельзя, это разные кошельки.
Второе: упёршись в лимит подписки, агент остановится молча для нашего счётчика — искать причину
надо на стороне его тарифа, а не в `.vibe/providers.json`.

**Метки чужой сессии гасятся автоматически.** Если сама IDE запущена из-под Claude Code, унаследованные переменные (`CLAUDECODE` и родственные) заставили бы агента считать себя вложенным и отказаться стартовать — IDE их вычищает.

## 7. Короткое имя или полный путь в `command`

Приложение, запущенное из Dock, Finder или Launchpad, **не наследует `PATH` из вашей оболочки**:
`~/.zshrc` и `~/.bash_profile` выполняются для терминала, а не для программы, открытой мышью.
Менеджеры версий Node (fnm, nvm, volta) как раз прописывают себя в профиль оболочки.

**VibeIDE разрешает окружение оболочки для агентов** (macOS и Linux) — так же, как VS Code делает это для своих
терминалов: один раз при старте запускается ваша оболочка, и её `PATH` накладывается на окружение процесса агента.
Поэтому короткие `npx`, `uvx`, `claude` находятся так же, как в терминале. На Windows `npx` и `uvx` — это `.cmd`-обёртки,
и запуск идёт через `cross-spawn`, который их понимает.

**Полный путь остаётся надёжным запасным вариантом** — если оболочка не отвечает при старте (слишком долгий профиль,
ошибка в нём), агент стартует с окружением самой IDE, и короткое имя снова даст `ENOENT`.

```bash
# узнать путь (в терминале, где команда работает)
which claude
which npx
```

```jsonc
{ "command": "/Users/имя/.local/bin/claude", "args": ["--acp"] }
```

**Осторожно с fnm:** его путь вида `~/.local/state/fnm_multishells/81301_1786876541400/bin/npx`
привязан к конкретной сессии терминала и после перезапуска перестанет существовать. Берите либо
постоянный путь установки самого агента (как `~/.local/bin/claude`), либо путь внутри каталога
версии (`~/.local/share/fnm/node-versions/v24.18.0/installation/bin/npx`).

Если агент запускается только через `npx`, а постоянного пути нет — пропишите `PATH` явно. Версию пакета указывайте
точно, а `-y` не пишите: npm подразумевает его сам, когда stdin не терминал, а флаг и пакет без версии — находки
Config Guard:

```jsonc
{
  "command": "/Users/имя/.local/share/fnm/node-versions/v24.18.0/installation/bin/npx",
  "args": ["пакет-агента@1.2.3"],
  "env": { "PATH": "/Users/имя/.local/share/fnm/node-versions/v24.18.0/installation/bin:/usr/bin:/bin" }
}
```

## 8. Типичные ошибки

| Симптом | Причина |
|---|---|
| Запись не появилась в списке | Нет `id` или `command`, либо `"active": false`. |
| «процесс не запустился: ENOENT» | Окружение оболочки не получено при старте, а в `command` короткое имя (`npx`, `claude`, `node`) — см. §7. Либо аргументы записаны строкой в `command`, либо путь действительно неверен. |
| В «Есть замечания» — «Config Guard: …» | Команда агента проверяется теми же правилами, что команда MCP-сервера: скачивание с запуском, `sh -c`, пакет без точной версии, `-y`. В режиме `vibeide.configGuard.mode: block` агент с критичной находкой не предлагается. |
| «не авторизован» | Агент требует входа: для Claude Code — `claude /login`. |
| Файл проигнорирован целиком | Не JSON или нет массива `agents`. |
