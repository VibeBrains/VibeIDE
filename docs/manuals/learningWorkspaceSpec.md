# Спека формата: учебная папка `.vibe/learning/`

> **Скопируйте этот файл целиком своей LLM и попросите собрать `MISSION.md` (или любой другой
> файл учебной папки) для вашей темы.** Документ самодостаточен: чтобы им воспользоваться, не
> нужно ни выходить в интернет, ни читать исходники VibeIDE.

Учебная папка — это память обучения, которая переживает конец чата. Разговор хранит контекст,
обучению же нужен прогресс: что ученик уже освоил и на чём спотыкается второй раз подряд.
Всё это лежит обычными markdown-файлами, читается человеком и версионируется гитом.

## Где живёт

Внутри открытой рабочей папки:

```
.vibe/learning/
  MISSION.md        обязательный — зачем и куда учимся
  RESOURCES.md      первоисточники, по которым разрешено учить
  NOTES.md          предпочтения ученика
  lessons/          сами уроки, по одной узкой теме на файл
  records/          следы уроков: что освоено, где застряли
  reference/        выжимки: шпаргалки, глоссарии, синтаксис
```

Обязателен только `MISSION.md`. Остальное появляется по ходу: `records/` пишет агент
инструментом `learning_record`, `lessons/` и `reference/` — он же, по мере уроков.

**Одна тема — одна рабочая папка.** Английский и Rust в одной папке дают одну миссию на двоих
и одну историю застреваний, из которой невозможно выбрать сложность ни для того, ни для другого.

## `MISSION.md` — обязательный

Markdown с четырьмя разделами второго уровня. Пока хотя бы один пуст, обучение не начинается:
урок без миссии выходит пересказом оглавления учебника — верным и бесполезным.

```markdown
# Миссия обучения

## Зачем
Почему навык нужен именно сейчас. Не «полезно вообще», а что не получается сегодня.

## Текущий уровень
Что ученик уже умеет сам, без подсказки. Отсюда начинается первый урок.

## Критерий успеха
Признак, по которому обучение можно закончить. Без него оно не кончается никогда.

## Формат
Как ученику удобно учиться: длина урока, доля практики, что раздражает.
```

**Правила разбора:**

- Заголовки узнаются по синонимам: `Зачем` / `Цель` / `Миссия` / `Why` / `Goal`;
  `Текущий уровень` / `Уровень` / `Что умею` / `Level`; `Критерий успеха` / `Успех` /
  `Результат` / `Success`; `Формат` / `Как учиться` / `Предпочтения` / `Format`.
- Уровень заголовка (`##`, `###`) значения не имеет.
- Незнакомые разделы игнорируются — свои заметки в файле держать можно.
- HTML-комментарии (`<!-- ... -->`) и строка `— не указано` **ответом не считаются**: это
  заглушки образца, и раздел с ними остаётся пустым.
- YAML-шапка между `---` пропускается.

## `RESOURCES.md` — первоисточники

Свободный markdown; читается целиком и отдаётся агенту как «чем разрешено учить». Формат не
навязан, потому что список источников человек ведёт для себя. Полезно указывать, **что именно**
брать из источника, а не только ссылку.

```markdown
# Источники

- Официальная документация языка, раздел про типы — https://example.org/docs/types
- Учебник, которым пользуюсь: «Название», главы 3–5
- Коллега-носитель проверяет произношение раз в неделю
```

Пустой или отсутствующий файл — законное состояние: агент тогда обязан спросить источники,
а не учить по памяти.

## `NOTES.md` — предпочтения

Тоже свободный markdown: темп, время суток, что уже пробовали и не сработало.

## `records/*.md` — следы уроков

Пишет агент, но формат открытый: файл можно поправить руками, и правка учтётся.

```markdown
---
lesson: "Артикли: a/an и нулевой"
created: 2026-08-13T10:00:00.000Z
---

# Артикли: a/an и нулевой

## Освоено
- ставит a/an перед исчисляемыми в единственном числе

## Застрял
- нулевой артикль с абстрактными существительными
```

- Имя файла — время создания; лексикографический порядок обязан совпадать с хронологическим,
  от него зависит выбор сложности.
- `Освоено` — то, что ученик **показал**, а не то, что ему рассказали.
- `Застрял` — короткие темы, сопоставимые между уроками. Строку «было тяжеловато» сравнить
  с прошлой невозможно, тему «нулевой артикль» — можно.
- Пустой `Застрял` — содержательное утверждение «прошло чисто», а не пропуск.
- Синонимы заголовков: `Освоено` / `Learned`, `Застрял` / `Stuck`.

## Как из записей выбирается сложность

Решение принимает код по данным, а не модель по впечатлению от собственного урока:

| Условие | Вердикт | Что делает агент |
|---|---|---|
| Тема повторилась в `Застрял` N раз (по умолчанию 2) | `easier` | Следующий урок разбирает именно её |
| Последние M уроков (по умолчанию 2) без застреваний | `harder` | Шаг вперёд — ровно один |
| Иначе | `hold` | Держит текущий уровень |

Повтор темы **перекрывает** чистую серию: ученик, который трижды спотыкается об одно и то же,
мог отвечать на всё остальное, и усложнение просто закапывает пробел глубже.

Внутри одного урока тема считается один раз: три формулировки одной трудности за вечер — это
одна трудность.

Пороги — настройки `vibeide.learning.stuckRepeatsForEasier` и `vibeide.learning.cleanRunForHarder`.

## Проверка, что файл собран верно

Откройте папку в VibeIDE и попросите агента «продолжим обучение». Если он начинает с вопросов,
которые вы уже расписали в `MISSION.md`, — раздел не распознан: сверьте заголовки со списком
синонимов выше и уберите из него заглушки-комментарии.
