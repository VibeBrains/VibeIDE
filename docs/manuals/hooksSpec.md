# Спека формата `.vibe/hooks.json` — хуки проекта

← [Дерево документации](../README.md)

> **Как этим пользоваться:** скопируйте этот файл целиком своей LLM и попросите собрать `.vibe/hooks.json` для вашего проекта. Здесь есть всё: поля, значения по умолчанию, контракт кода выхода, формат входных данных и рабочие примеры. Выходить в интернет и читать исходники VibeIDE не нужно.

## Что такое хук

Хук — команда **вашего проекта**, которую VibeIDE запускает вокруг работы агента: перед вызовом инструмента, сразу после него или в конце хода.

Разница между хуком и правилом принципиальна. Правило (`.vibe/rules`, `CLAUDE.md`) просит модель вести себя определённым образом — и она обычно слушается. Хук ничего не просит: он выполняет вашу команду, и её **код выхода** решает, состоится действие или нет. «Не трогай папку `migrations/`» — пожелание; `preToolUse`-хук, возвращающий `2` на путь внутри `migrations/`, — факт.

## Где лежит и когда работает

Файл: `.vibe/hooks.json` в корне проекта.

Хуки выполняются, только когда выполнены **все три** условия:

1. включена настройка `vibeide.hooks.enabled` (по умолчанию **выключена**);
2. папка помечена доверенной (Workspace Trust);
3. файл разобрался без ошибок.

Выключено по умолчанию не из осторожности вообще, а по конкретной причине: иначе клонирование чужого репозитория означало бы выполнение его кода у вас на машине. Если в проекте есть хуки, а настройка выключена, VibeIDE один раз скажет об этом и предложит кнопку «Включить хуки».

## Формат

```jsonc
{
  "hooks": [
    {
      "event": "preToolUse",          // preToolUse | postToolUse | turnEnd
      "command": "node .vibe/hooks/guard.js",
      "tools": ["run_command"],       // необязательно; пусто = любой инструмент
      "timeoutMs": 5000,              // необязательно; по умолчанию 30000, максимум 300000
      "label": "Политика команд"      // необязательно; так хук назовут в сообщениях
    }
  ]
}
```

| Поле | Обязательное | Значение |
|---|---|---|
| `event` | да | `preToolUse` — перед инструментом; `postToolUse` — после; `turnEnd` — когда агент закончил ход |
| `command` | да | Командная строка. Выполняется через системную оболочку, рабочая папка — корень проекта |
| `tools` | нет | Точные имена инструментов. Пусто — любой. Для `turnEnd` игнорируется |
| `timeoutMs` | нет | По умолчанию 30 000, потолок 300 000. Больший таймаут урезается, и вам об этом скажут |
| `label` | нет | Человеческое имя хука в сообщениях агенту и в уведомлениях |

Хуки одного события выполняются **по очереди, сверху вниз**; первый же отказ прекращает цепочку.

## Контракт кода выхода

| Код | Что значит |
|---|---|
| `0` | Разрешено. Всё, что хук напечатал в stdout, уйдёт агенту заметкой |
| `2` | **Отказ.** Для `preToolUse` инструмент не выполняется, агент получает текст из stderr (или stdout) как причину. Для `postToolUse` и `turnEnd` действие уже произошло — агенту приходит требование исправить |
| любой другой | Считается **поломкой самого хука**: работа продолжается, пользователь видит предупреждение |

Почему отказ — это `2`, а не `1`: единицу возвращает любой сломанный скрипт (нет бинарника, опечатка в пути, синтаксическая ошибка). Если бы единица блокировала агента, то опечатка в хуке молча запирала бы проект. Остановить агента можно только намеренно.

Таймаут и невозможность запустить процесс тоже считаются поломкой хука и **не блокируют** работу.

## Что хук получает на вход

В stdin приходит JSON одной строкой:

```json
{
  "event": "preToolUse",
  "tool": "run_command",
  "params": { "command": "rm -rf build", "cwd": "/path/to/project" },
  "cwd": "/path/to/project",
  "changedFiles": ["src/a.ts"]
}
```

- `tool` и `params` — есть у `preToolUse` и `postToolUse`; `params` — сырые параметры, как их выдала модель;
- `changedFiles` — только у `turnEnd`: файлы, изменённые за ход;
- `cwd` — корень проекта, он же рабочая папка команды.

Дополнительно в окружении команды доступны `VIBE_HOOK_EVENT` и `VIBE_HOOK_TOOL` — для однострочников, которым разбирать JSON незачем.

## Примеры

**1. Запретить агенту трогать миграции**

`.vibe/hooks.json`:

```json
{
  "hooks": [
    { "event": "preToolUse", "command": "node .vibe/hooks/no-migrations.js", "tools": ["edit_file", "rewrite_file", "create_file_or_folder", "delete_file_or_folder"], "label": "Миграции только руками" }
  ]
}
```

`.vibe/hooks/no-migrations.js`:

```js
let raw = '';
process.stdin.on('data', chunk => { raw += chunk; });
process.stdin.on('end', () => {
	const payload = JSON.parse(raw || '{}');
	const target = String(payload.params?.uri ?? '');
	if (target.includes('/migrations/')) {
		console.error('Файлы миграций правятся только вручную: ' + target);
		process.exit(2);
	}
	process.exit(0);
});
```

**2. Прогонять линтер после каждой правки файла**

```json
{
  "hooks": [
    { "event": "postToolUse", "command": "npm run lint --silent", "tools": ["edit_file", "rewrite_file"], "timeoutMs": 60000, "label": "ESLint" }
  ]
}
```

Линтер вернёт `0` — агент увидит его вывод заметкой; вернёт `2` (если вы так настроите обёртку) — агент получит требование починить.

**3. Тесты в конце хода**

```json
{
  "hooks": [
    { "event": "turnEnd", "command": "npm test --silent", "timeoutMs": 300000, "label": "Тесты" }
  ]
}
```

**4. Однострочник без разбора JSON**

```json
{
  "hooks": [
    { "event": "preToolUse", "command": "sh -c 'test \"$VIBE_HOOK_TOOL\" != delete_file_or_folder || { echo \"Удаление файлов запрещено\" >&2; exit 2; }'", "label": "Без удалений" }
  ]
}
```

## Как проверить, что всё работает

1. Включите `vibeide.hooks.enabled` и убедитесь, что папка доверенная.
2. Положите хук, который всегда отказывает: `{ "event": "preToolUse", "command": "sh -c 'echo стоп >&2; exit 2'" }`.
3. Попросите агента прочитать любой файл — он получит отказ и назовёт причину «стоп».
4. Уберите хук: агент снова работает.

Если ничего не происходит — проверьте настройку, доверие к папке и вывод `vibe doctor`: ошибки разбора файла показываются уведомлением и пишутся в лог.

## Чего хуки не делают

- Не откатывают уже выполненное: `postToolUse` не отменяет правку, а требует её исправить.
- Не заменяют подтверждения опасных действий — это отдельный механизм, он остаётся.
- Не выполняются в недоверенной папке и при выключенной настройке, даже если файл есть.
