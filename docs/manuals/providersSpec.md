# Спецификация формата `.vibe/providers.json` (VibeIDE)

> **Как этим пользоваться.** Скопируйте весь этот файл целиком своей LLM и попросите:
> *«По этой спецификации собери мне `.vibe/providers.json` для провайдера <НАЗВАНИЕ>: base URL — <…>, ключ в переменной окружения <ИМЯ>, модели — <…>».*
> Модель вернёт готовый JSONC, который кладётся в `.vibe/providers.json` в корне рабочей папки.
> Это самодостаточный документ: всё, что нужно для генерации валидного конфига, — ниже.

Канонический источник схемы — TypeScript-типы в
`src/vs/workbench/contrib/vibeide/common/vibeProvidersFile.ts`. Этот файл описывает тот же формат человеческим языком.

---

## 1. Что это и зачем

`providers.json` — пользовательский файл, которым можно **добавить**, **переопределить** или **выключить** LLM-провайдеров и модели **без пересборки IDE**. Объявленный провайдер **равноправен со встроенным**: карточка в «Облачных провайдерах», ввод/проверка ключа, живой каталог моделей, тумблеры моделей, участие в авто-выборе модели («Auto» — конфиг-провайдеры идут первыми, как явная конфигурация пользователя) и подхват ключа из переменной окружения ОС.

- Формат — **JSONC**: допускаются `//`-комментарии и висячие запятые.
- Провайдеры читаются из **четырёх источников**, все необязательны. От слабого к сильному:

  | Источник | Что это |
  |---|---|
  | `~/.vibe/providers/*.jsonc` | каталог провайдеров, общий для всех проектов |
  | `<проект>/.vibe/providers/*.jsonc` | тот же каталог в рабочей папке — засевается в каждый проект |
  | `~/.vibe/providers.json` | ваш глобальный файл |
  | `<проект>/.vibe/providers.json` | ваш файл проекта |

- **Каталог `providers/` — рабочий реестр, а не библиотека примеров:** файлы в нём читаются автоматически, копировать записи в `providers.json` не нужно. Внутри папки порядок алфавитный, поэтому файл с более поздним именем перекрывает более ранний.
- **Почему каталог слабее ваших файлов:** он засевается в каждый проект и играет роль встроенных провайдеров. Стой он выше, засеянный `"active": false` выключал бы провайдера, включённого вами глобально, — и обновление набора молча меняло бы поведение.
- **Мерж при совпадении `id`: сильный источник перекрывает слабый** — по полям (как настройки VS Code), список `models.static` мёржится по id модели. Провайдеры, встреченные только в сильном источнике, добавляются после.
- **Выключить провайдера из каталога, не трогая набор:** `{ "id": "openai", "active": false }` в своём `providers.json` — решение переживёт обновление сидов. Обратно включить — так же, с `true`.
- **Неактивная запись не исчезает из слияния:** её по-прежнему можно унаследовать через `extends` и патчить; фильтр `active` применяется в самом конце, когда реестр уже собран. Запись без поля `active` считается активной — и при слиянии тоже: ваша запись по `id` поверх выключенной засеянной включает её, как в VibeIDEA. Патч, который выключенную запись включать не должен, повторяет `"active": false`. То же у моделей в `static` и у клона через `extends`.
- **Битый файл каталога стоит только себя:** остальные файлы загружаются, а предупреждение называет источник поимённо (`workspace/providers/openai.jsonc`), иначе на дюжине файлов опечатку негде искать.
- **Кэш:** последний успешно смерженный набор запоминается в хранилище приложения и восстанавливается при старте мгновенно — провайдеры видны до того, как дочитаны файлы, и в окне без папки. Каждое чтение файлов перезаписывает кэш, поэтому удалённый из файла провайдер исчезает (ключ, введённый в UI, и тумблеры моделей при этом сохраняются на случай возвращения id).
- В редакторе работают автодополнение и диагностика (подключена JSON Schema).

**Перезапуск:** после изменения *структуры* (id, baseURL, список моделей, protocol) — перезапустить VibeIDE (оба файла также перечитываются на лету при изменении на диске). Значение ключа в `.vibe/.env` подхватывается без рестарта.

## 2. Главные принципы

- **Ключи API в файле не хранятся.** Источник ключа задаётся ссылкой:
  - `apiKeyEnv` — имя переменной окружения. Значение берётся из `.vibe/.env` (строка `ИМЯ=значение`, gitignored, в контекст агента не попадает; глобальный `~/.vibe/.env` тоже читается, workspace-файл перекрывает по имени переменной) **или** из переменной окружения ОС — ключ, экспортированный в `~/.zshrc`, разблокирует провайдера и его статические модели так же, как у встроенных (значение до интерфейса не доходит, им пользуется только процесс отправки).
  - `apiKeyRef` — ключ из защищённого хранилища VibeIDE (вводится в Настройках по id провайдера).
  - Серверу без ключа (vLLM, Ollama, LM Studio, свой шлюз) ключ не задаётся вовсе — ему пишут `"auth": "none"` (§4.1).
  - Серверу на этой машине (`localhost`, `127.0.0.1`, `[::1]`, `0.0.0.0`) ключ необязателен и без `"none"`: не задан — сервер спрашивается без него (§4.1).
  - Сам `providers.json` можно коммитить в репозиторий.
- **`active: true|false`** — тумблер. Есть на провайдере и на каждой модели. По умолчанию `true`.
- **Совпадение `id` со встроенным провайдером → патч.** Ваши поля накладываются поверх встроенного.
- **`extends: "<id>"` → новый провайдер** на базе существующего (оригинал остаётся).
- **Пишите только отличия** — остальное наследуется. Список моделей мёржится по `id` модели.

## 3. Структура файла

```jsonc
{
  "version": 1,
  "providers": [ /* массив провайдеров */ ]
}
```

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `version` | `number` | нет | Версия формата. Сейчас `1`. |
| `providers` | `ProviderEntry[]` | **да** | Массив определений провайдеров. |

Если запись в `providers[]` невалидна (нет `id` и т.п.) — она пропускается с предупреждением, остальные продолжают работать; весь файл из-за одной опечатки не отключается.

## 4. Провайдер — `ProviderEntry`

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `id` | `string` | — (**обяз.**) | Уникальный ключ. Совпал со встроенным → **патч** его; новый → **новый** провайдер. |
| `extends` | `string` | — | Наследовать все поля другого провайдера (встроенного или из файла), затем переопределить ниже. Директива резолвинга, в результат не попадает. |
| `name` | `string` | = `id` | Отображаемое имя. |
| `active` | `boolean` | `true` | `false` выключает провайдера и все его модели. |
| `order` | `number` | — | Порядок среди ВАШИХ провайдеров (меньше = выше). Без него — в конец по имени. |
| `tags` | `string[]` | — | Произвольные метки. |
| `note` | `string` | — | Заметка для себя (в UI не показывается как функционал). |
| `protocol` | `"openai" \| "openai-responses" \| "anthropic" \| "gemini"` | — | Wire-формат API: `"openai"` = OpenAI-**совместимые** chat completions (обычный случай), `"anthropic"` = Messages API, `"gemini"` = Google-нативный. Управляет выбором SDK при отправке с приоритетом: per-model override пользователя (настройка «протокол API» у модели) → **это поле** → каталог models.dev → openai-совместимый fallback. Обязательно указывайте для anthropic/gemini-эндпоинтов с моделями вне каталога — иначе запрос уйдёт не тем форматом. |
| `baseURL` | `string` | — | Базовый URL API. **Обязателен** для нового провайдера (без него запросы не уходят). Путь дописывается к нему как есть — см. врезку ниже. |
| `auth` | `"bearer"` \| `"none"` \| объект (см. ниже) | родной заголовок протокола | Куда уходит ключ (§4.1); `"none"` — сервер ключа не требует. |
| `apiKeyEnv` | `string` | — | Имя переменной окружения с ключом. |
| `apiKeyRef` | `string` | — | Взять ключ из защищённых настроек VibeIDE по этому id. |
| `headers` | `Record<string,string>` | — | Статические заголовки: уходят с каждым запросом и с запросом каталога. Слои сливаются по именам. |
| `query` | `Record<string,string>` | — | Статические query-параметры: уходят с каждым запросом и с запросом каталога. Слои сливаются по именам. |
| `timeoutMs` | `number` | — | Сколько ждать, пока сервер начнёт отвечать, мс. Сильнее общих `vibeide.llm.timeoutMs.*`. Идущий ответ рвёт только тишина потока. |
| `promptCacheKey` | `boolean` | `false` | Endpoint принимает `prompt_cache_key` — так у OpenAI и xAI. VibeIDE шлёт ключ, постоянный в пределах разговора (у плана и у каждого субагента — свой), и запросы попадают на сервер, где уже лежит их кэш; без ключа запрос может уйти на «холодный» сервер, и вход оплатится по полной цене. **Без объявления поле не отправляется:** строгие OpenAI-совместимые вендоры отвечают 400 на незнакомое поле. Ключ — хеш от разговора, о его содержимом он ничего не говорит. |
| `reasoningDialect` | `"openrouter"` | — | Как endpoint пишет рассуждение на проводе OpenAI, если не так, как OpenAI (см. §4.3). |
| `docsUrl` | `string` | — | Ссылка на документацию (кнопка в карточке). |
| `apiKeyUrl` | `string` | — | Ссылка на страницу получения ключа (кнопка в карточке). |
| `quota` | объект | — | Где спросить у вендора остаток подписки: `{ url, format }` (см. §4.2). |
| `models` | `ModelsSpec` | — | Список/каталог моделей (см. §6). Необязателен — по умолчанию модели тянутся из каталога. |

> **`baseURL` — включайте версию пути сами.** Клиент дописывает к нему только имя метода, ничего не «угадывая»: у anthropic-протокола это ровно `/messages`. Значит для Anthropic-совместимого эндпоинта MiniMax правильно `https://api.minimax.io/anthropic/v1`, а не `https://api.minimax.io/anthropic` — со вторым запрос уходит на `/anthropic/messages` и вендор отвечает **404 Not Found** (проверено живьём 06.08.2026). То же правило для openai-совместимых: `…/v1`, если у вендора методы лежат под `/v1`.
>
> **Один вендор — несколько эндпоинтов под разные тарифы.** У Z.AI подписка GLM Coding Plan обслуживается на `https://api.z.ai/api/coding/paas/v4`, а оплата за токены — на `https://api.z.ai/api/paas/v4`. Ключ из раздела «Model & Personal Coding Plan» действует **только** на первом. Симптом перепутанного адреса обманчив: не «неверный ключ», а `HTTP 429, code 1113 — Insufficient balance or no resource package`, то есть подписочный ключ ушёл на пер-токенный счёт, где денег нет. Прежде чем искать проблему в ключе, сверьте адрес с тарифом.

### 4.1. Формат `auth` — куда уходит ключ

```jsonc
// "auth" не указан                           // родной заголовок протокола (таблица ниже) — обычный случай
"auth": "bearer"                              // Authorization: Bearer <key> на любом протоколе
"auth": { "type": "bearer" }                  // то же в явной форме
"auth": { "type": "header", "name": "api-key" }    // ключ в заголовке api-key
"auth": { "type": "query",  "name": "key" }        // ключ в query-параметре ?key=<key>
"auth": "none"                                // сервер без ключа: ключ не отправляется
"auth": { "type": "none" }                    // то же в явной форме
```

**Куда уходит ключ решает протокол запроса**, а не провайдера: модель со своим `protocol` в `static` идёт своим проводом.
Правило общее с VibeIDEA, его проверяют общие векторы набора `testVectors/providerAuth.json`.

| `auth` | Куда уходит ключ |
|---|---|
| не указан ни в одном слое | anthropic — `x-api-key`, gemini — `x-goog-api-key`, openai и openai-responses — `Authorization: Bearer` |
| `"bearer"` | `Authorization: Bearer` на любом протоколе, anthropic и gemini тоже |
| `header` | заголовок `name`; без `name` — родной заголовок протокола, у openai — `x-api-key` |
| `query` | параметр `name`; без `name` — `key` |
| `"none"` | никуда |

- Пишите `auth`, только если сервер ждёт ключ не там, где его кладёт протокол.
- Вендор с одним ключом на несколько протоколов обычно читает его из родного заголовка каждого — так у OpenCode: `/chat/completions` берёт только Bearer, `/v1/messages` — только `x-api-key`. Такому провайдеру `auth` не пишут: явный `"bearer"` ушёл бы Bearer'ом и на `/v1/messages`.
- `"bearer"` на протоколе gemini — предупреждение при загрузке: Google на API-ключ в Bearer отвечает ошибкой OAuth.
- Ключа нет — не уходит ничего: ни заглушки, ни ключа из переменных, которые читают клиенты вендоров (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`).
- Файл, патчащий встроенного провайдера, ходит транспортом встроенного: `auth` у такого патча ничего не меняет.

**`"none"` — сервер, который ключа не требует:** локальный vLLM, Ollama, LM Studio, шлюз в своей сети.

- Ключ не ищется и не уходит ни в каком виде — ни заголовком, ни параметром.
- Объявленные рядом `apiKeyEnv` или `apiKeyRef` не отправляются; о таком противоречии при загрузке выводится предупреждение.
- Заголовки из `headers` уходят как есть: так задаётся постоянный пропуск шлюза, если он нужен.
- Каталог моделей запрашивается без ключа, и решает ответ сервера:
  - ответил — модели в списке;
  - не отвечает — моделей нет, проверка повторяется сама каждые 10 секунд, так что сервер, поднятый после IDE, появится без перезапуска;
  - ответил 401/403 — сервер всё-таки требует ключ: уберите `"none"` и задайте `apiKeyEnv`.
- Карточка провайдера в настройках пишет «Ключ не нужен» и поля ключа не показывает.
- Работает на любом адресе, не только на localhost.

**Сервер на этой машине** — `localhost`, `127.0.0.1`, `[::1]`, `0.0.0.0`, регистр не важен — пускается и без `"none"`: ключ ему необязателен.

- Ключ задан — уходит по таблице выше.
- Не задан — каталог спрашивается без ключа, и решает ответ сервера, как у `"none"`.
- Ответ 401/403 — «Локальный сервер требует ключ — задайте его»: так отвечает, например, локальный прокси к облаку.
- Поле ключа в карточке остаётся — для сервера, которому ключ нужен.

Значения регистрозависимы. Нераспознанное (`"None"`, `"basic"`, `{ "type": "oauth" }`) читается как `"bearer"`, и при загрузке выводится предупреждение с этим значением.

### 4.2. Остаток подписки — `quota`

У подписки остаток считает вендор по своим правилам: множители моделей, пиковые часы, расход вне IDE тем же
ключом. Своим счётчиком IDE его честно не посчитает, поэтому она спрашивает вендора и показывает его ответ.

```jsonc
{
  "id": "minimax",
  "quota": { "url": "https://api.minimax.io/v1/token_plan/remains", "format": "minimax-token-plan" }
}
```

- `url` — адрес запроса остатка, только `https://`. Запрос уходит с ключом провайдера (`Authorization: Bearer`),
  перенаправления не выполняются. Ключ — введённый в настройках, из `.vibe/.env` или переменной окружения.
- `format` — как читать ответ:
  - `minimax-token-plan` — MiniMax Token Plan, официальный запрос (platform.minimax.io/docs/token-plan/faq).
    Смысл полей вендор не документирует, IDE читает их так же, как его собственный CLI (github.com/MiniMax-AI/cli).
  - `zai-monitor` — Z.ai GLM Coding Plan, `https://api.z.ai/api/monitor/usage/quota/limit`. **Вендор этот запрос
    не документирует**, формат уже менялся без предупреждения; в отчёте это сказано строкой.
- Незнакомый `format` или `url` не на https — поле пропускается с предупреждением при загрузке.
- **Когда запрашивается:** только при открытии отчёта «VibeIDE: Ключи и расход». Фонового опроса нет.
- **Что показывается:** по каждому окну плана — сколько осталось в процентах, длина окна и время сброса, с
  пометкой «ответ вендора» и временем запроса. Нечитаемый ответ — строка «данных нет», а не 0. Ошибка вендора
  и сбой сети — своей строкой.
- Одна и та же подписка с тем же ключом спрашивается один раз.
- Формат общий с VibeIDEA; правила прочтения сверяются общими векторами набора (`testVectors/subscriptionQuota.json`).

### 4.3. Диалект рассуждения — `reasoningDialect`

OpenAI принимает глубину рассуждения полем `reasoning_effort`. OpenRouter его не называет: он принимает один объект
`reasoning` для всех моделей, которые маршрутизирует (openrouter.ai/docs/use-cases/reasoning-tokens).

```jsonc
{
  "id": "my-router",
  "baseURL": "https://openrouter.ai/api/v1",
  "apiKeyEnv": "OPENROUTER_API_KEY",
  "reasoningDialect": "openrouter"
}
```

С `"openrouter"` запрос несёт:

- уровень рассуждения — `"reasoning": {"effort": "low"}` вместо `"reasoning_effort": "low"`
- бюджет, если модель задаёт рассуждение бюджетом токенов, — `"reasoning": {"max_tokens": N}`
- «выключено» — `"reasoning": {"effort": "none"}`; свой `reasoning.off` у модели в `static` сильнее

Действует только на OpenAI-совместимом проводе (`protocol: "openai"`): у Anthropic и Gemini свой формат.
Встроенный провайдер `openRouter` так и говорит — поле нужно провайдеру из файла, который смотрит в OpenRouter или в
совместимый с ним роутер. Другое значение не читается: при загрузке выводится предупреждение, рассуждение уходит как у
OpenAI. Поле читают и VibeIDE, и VibeIDEA.

## 5. Каталог моделей — `ModelsSpec`

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `fetch` | `boolean \| string` | `true` | `true` — авто-список из `<baseURL>/models`; строка — фетчить этот URL; `false` — только `static`. |
| `static` | `ModelEntry[]` | — | Статически заданные модели. Мёржатся с авто-списком по `id` (static перекрывает возможности). |

> **Про URL каталога.** При `fetch: true` дёргается `<baseURL>/models` — путь дописывается как есть, как у запросов чата, поэтому версию (`/v1`, `/v1beta`, `/v4`) включают в `baseURL`. Если список лежит в другом месте, укажите полный URL строкой: `"fetch": "https://.../models"`.
>
> Запрос каталога идёт так же, как чат: с `headers` и `query` провайдера и ключом по §4.1 для его `protocol`; у anthropic — ещё `anthropic-version`. Понимаются ответы `{ "data": [...] }` и гугловский `{ "models": [...] }`.
>
> Ответ 404 — каталога по этому адресу нет: в выборе остаются модели из `static`, ключ помечен «не проверен». Сеть или сервер недоступны — моделей нет, проверка повторяется сама каждые 10 секунд.

За сколько дней предупреждать о подорожании — настройка `vibeide.providers.priceChangeWarningDays` (по умолчанию 14, `0` отключает предупреждение; цена всё равно пересчитается в срок).

> **Гейт `npm run seed-fields-check`:** разбор файла молча отбрасывает незнакомые поля — иначе конфиг из более новой версии ронял бы весь набор. Поэтому имя поля, написанное «почти правильно» (`pricing` вместо `cost`), даёт файл, который выглядит рабочим и не делает ничего. Гейт сверяет поля засеваемых файлов с типом и с этой спекой сразу.

#### Надбавка за длинный промпт — `cost.longContext`

Некоторые вендоры берут больше, когда промпт длиннее порога. GPT-6 Astra объявляет: промпт длиннее
272K токенов стоит вдвое дороже по входу и кэшу и в полтора раза дороже по выходу — **за весь
запрос**, а не только за превышение.

```jsonc
"cost": {
  "input": 10, "output": 50, "cacheRead": 1, "cacheWrite": 12.5,
  "longContext": { "overInputTokens": 272000, "input": 2, "cache": 2, "output": 1.5 }
}
```

- `overInputTokens` — порог по длине **промпта**, срабатывает строго выше него. Считается весь
  промпт: свежий вход, чтение из кэша и запись в кэш — кэшированная часть ведь тоже отправлена.
  Ответ в порог не входит: когда цена определяется, ответа ещё нет.
- `input`, `cache`, `output` — множители к базовым ставкам `cost` на весь запрос: `input` — к
  свежему входу, `cache` — к чтению из кэша и к записи в кэш, `output` — к выходу. Если множитель
  не указан, он равен 1.
- Блок без порога или со всеми множителями, равными 1, считается необъявленным.
- Надбавка решается для каждого запроса. Суммы за прогон (карточка роли, повтор прогона)
  считаются по базовым ставкам: по сумме нельзя сказать, какой из запросов был длинным.
- `costAfter` принимает тот же блок.
- **Каталоги-агрегаторы порог обычно не указывают** — берите числа со страницы вендора.

#### Цена по часу — `cost.timeOfDay`

Некоторые вендоры берут разную цену в разные часы. У DeepSeek с 10.09.2026 пик — 01:00–04:00 и
06:00–10:00 UTC с понедельника по пятницу, а всё остальное время — половина пиковой ставки
(api-docs.deepseek.com/quick_start/pricing).

```jsonc
"cost": {
  "input": 0.30, "output": 1.20, "cacheRead": 0.006,
  "timeOfDay": {
    "peakUtc": ["01:00-04:00", "06:00-10:00"],
    "peakDays": ["mon", "tue", "wed", "thu", "fri"],
    "offPeakFactor": 0.5
  }
}
```

- Ставки в `cost` — **пиковые**, вне пика все они умножаются на `offPeakFactor`: вендоры называют
  внепиковую цену долей пиковой, и запись повторяет их прайс.
- `peakUtc` — окна `ЧЧ:ММ-ЧЧ:ММ` по UTC, конец не входит; окно через полночь пишется как есть
  (`22:00-02:00`), конец суток — `24:00`. `peakDays` — `mon` … `sun`; нет поля — окна действуют каждый день.
- Час берётся по моменту **окончания хода**. Где момента нет (сумма за прогон роли, прогноз стоимости),
  считается пиковая ставка: завышение безопаснее для потолка расходов, чем занижение.
- Множитель действует вместе с надбавкой за длинный промпт и в `costAfter` тоже.
- Битое окно, день или множитель роняют **весь блок**, и предупреждение при загрузке называет модель: цена
  по половине расписания выглядела бы верной и ошибалась молча.
- Шаг пайплайна с `"offPeak": true` ждёт конца пика своей модели — см. `pipelinesSpec.md`.
- Формат общий с VibeIDEA — там блок читается так же.

### Шлюз перед провайдерами (LiteLLM, ARBR и подобные)

Самохостящийся шлюз с одним OpenAI-совместимым эндпоинтом подключается как **обычный конфиг-провайдер**: `baseURL` на шлюз, `protocol: "openai"`, ключ через `apiKeyEnv`. Отдельной интеграции для этого не нужно и не будет — со стороны IDE шлюз неотличим от любого другого OpenAI-совместимого API.

```jsonc
{
  "id": "gateway",
  "name": "Внутренний шлюз",
  "protocol": "openai",
  "baseURL": "http://localhost:4000/v1",
  "apiKeyEnv": "GATEWAY_API_KEY",
  "models": { "fetch": true }
}
```

**Ставить его перед VibeIDE ради маршрутизации и бюджетов смысла нет** — авто-fallback, бюджеты на роль с суточным окном, отчёт по расходу и определение локальности уже здесь. Шлюз оправдан, когда он и так стоит в компании: как единая точка учёта и политики для всех приложений, а не для одного редактора.

Учтите цену выбора: шлюз нормализует все модели под OpenAI-формат, а поле `protocol` существует ровно потому, что для части моделей это ломает вызов инструментов и передачу размышлений. Anthropic и Gemini лучше подключать напрямую своим протоколом, даже если остальное идёт через шлюз.

> **Агрегатор с несколькими форматами на одном ключе.** У OpenCode Go базовый URL один, ключ один,
> а формат привязан к модели: GLM, Kimi, DeepSeek и MiMo обслуживаются на `/v1/chat/completions`,
> MiniMax и Qwen — на `/v1/messages` (Anthropic), Grok и GPT — на `/v1/responses`. Провайдерского
> `protocol` для такого каталога не хватает по построению: любое одно значение будет верным лишь
> для части моделей, а остальные уйдут не тем форматом. Поэтому формат объявляется у модели:
>
> ```jsonc
> {
>   "id": "opencode-go",
>   "protocol": "openai",                       // большинство моделей каталога
>   "baseURL": "https://opencode.ai/zen/go/v1",
>   "models": {
>     "static": [
>       { "id": "glm-5.3" },                                    // наследует openai
>       { "id": "MiniMax-M3",  "protocol": "anthropic" },       // /v1/messages
>       { "id": "qwen3.8-max", "protocol": "anthropic" }
>     ]
>   }
> }
> ```
>
> Модели, живущие на `/v1/responses` (Grok 4.6, GPT 5.6 Luna, Muse Spark), объявляются
> `"protocol": "openai-responses"`. Это **другой эндпоинт**, а не диалект chat-completions: модель
> оттуда ответит 404 на `/v1/chat/completions` и наоборот, поэтому значение выбирается явно и
> никогда не подставляется само.
>
> ```jsonc
> { "id": "grok-4.6", "protocol": "openai-responses" }
> ```
>
> **Живьём не проверено** (нет ключа с доступом к этим моделям): маршрутизация покрыта типами и
> тестом, но ответ вендора в этом формате мы не наблюдали.

### 6.4. `floating` — плавающий алиас

Некоторые id ведут не к одной модели, а к той, на которую вендор направил их сегодня: `-latest`, `~…` у OpenRouter,
снятая модель, чьё имя временно отвечает другой (DeepSeek перевёл `deepseek-v4-flash` на V4.1 Flash 10.09.2026).
В ответе при этом часто приходит то же имя, и подмену по нему не увидеть.

```jsonc
{ "id": "~deepseek/deepseek-flash-latest", "floating": true }
```

- «Авто» выбирает закреплённую модель и берёт плавающую, только если других нет.
- Совет моделей помечает мнение такого советника «(плавающий алиас)».
- План, одобренный на плавающей модели, говорит об этом при возобновлении.
- У OpenRouter признак ставится сам — по полю `alias_target` каталога; у DeepSeek, OpenAI и Anthropic
  `/models` алиасы не отличает, поэтому пометка ручная.

### 6.3. `deprecation` — модель отключают

Вендор объявляет дату отключения в ченджлоге, который никто не перечитывает, и в назначенный день
начинает отвечать 404. Пользователь узнаёт об этом посреди задачи — в момент, когда сменить модель
уже дорого. Объявите дату здесь, и предупреждение появится там, где выбор ещё ничего не стоит.

```jsonc
{
  "id": "minimax-m2.5",
  "deprecation": {
    "date": "2026-12-01",            // ISO YYYY-MM-DD, день отключения
    "replacedBy": "MiniMax-M3",      // на что переходить
    "note": "объявлено в ченджлоге вендора 15.08.2026"
  }
}
```

- **Все три поля необязательны.** Вендор мог назвать дату, преемника, ни того ни другого — запись
  без даты показывается как «объявлено об отключении» и не теряется.
- **Дата с опечаткой не отменяет предупреждение.** Нечитаемая строка трактуется как «объявлено без
  даты»: вендор всё-таки сказал, что модель уходит, и прятать это из-за формата было бы хуже.
- **Жёсткой блокировки нет.** Отключённая модель, которая всё ещё отвечает, — дело ваше, а дата
  может съехать: вендоры переносят. Единственное исключение — **авто-выбор модели**: уже
  отключённую модель он не предложит, потому что там выбираете не вы.
- Ближе чем за 30 дней предупреждение становится заметнее — это единственный порог, и он в коде
  один (`DEPRECATION_SOON_DAYS`).

### 6.2. `maxTools` и `maxPromptDirectoryChars` — бюджеты объёма

Слабые и локальные модели мажут по вызовам инструментов не потому, что не знают протокол, а потому
что тонут в четырёх десятках встроенных инструментов и в длинном промпте. Эти два поля говорят,
**сколько давать** конкретной модели; каталог квирков про объём не знает ничего — он правит формат.

```jsonc
{
  "id": "qwen2.5-coder:7b",
  "name": "Qwen2.5 Coder 7B (локально)",
  "toolFormat": "openai",
  "maxTools": 12,                  // столько инструментов увидит модель
  "maxPromptDirectoryChars": 2000  // столько символов обзора проекта попадёт в промпт
}
```

- **Оба поля необязательны, и отсутствие = как было.** Не указали — модель получает всё, ровно как
  до появления этих полей. Умолчания «на всякий случай» тут нет намеренно: одно число, применённое
  ко всем моделям, тихо покалечило бы frontier-модель.
- **Базовые инструменты не урезаются никогда** — чтение файла, правка, поиск, список каталога,
  запуск команды и завершение хода. Бюджет, который убрал бы `edit_file`, даёт не более лёгкого
  агента, а агента, который описывает правки, но не может их сделать. Если бюджет меньше базового
  набора, побеждает набор.
- **Порядок урезания фиксирован**: первыми уходят инструменты MCP (самые ситуативные), затем
  специализированные встроенные — с конца реестра к началу. Одна и та же модель с тем же бюджетом
  получает один и тот же список при каждом запуске, иначе воспроизвести чужой баг было бы нельзя.
- **`maxPromptDirectoryChars`** ограничивает обзор дерева файлов — единственную часть промпта,
  которая растёт с размером репозитория, а не с задачей. Глобальный аналог —
  настройка `vibeide.prompt.directoryOverviewChars`; поле модели сильнее её.

### 6.1. `reasoning` — «думающие» модели

```jsonc
"reasoning": {
  "canTurnOff": true,               // размышление можно выключить
  "effort": ["low", "medium", "high"], // допустимые значения усилия → слайдер в UI
  "thinkTags": ["<think>", "</think>"], // если модель отдаёт мысли инлайном — вырезать эту пару
  "off": { "thinking": { "type": "disabled" } } // что послать в положении «выключено»
}
```

- `effort` включает слайдер усилия; VibeIDE шлёт `reasoning_effort` и парсит `reasoning_content`.
- `off` — поля тела запроса, которые уходят, когда размышление выключено в интерфейсе. Нужен там, где «выключено» — отдельный запрос вендору: без `off` не уходит ничего, и вендор включает размышление по своему умолчанию. Пример — Xiaomi MiMo: `{"thinking": {"type": "disabled"}}`. Уходит только на OpenAI-совместимом проводе (`protocol: "openai"`), только в положении «выключено» и только если размышление у модели выключаемое (`canTurnOff` не `false`).
- **Провайдеро-специфичный** тумблер размышления, который должен быть включён всегда (например Moonshot/Kimi `thinking`), кладётся не сюда, а в `extraBody` модели — он уходит в тело запроса без изменений. Учтите: `extraBody` статичен, он включает режим всегда (раньше здесь значилось поле `field`, но оно не работало и удалено — одного имени ключа мало, форма значения у вендоров разная; переключатель «вкл/выкл» теперь описывает `off`).
- `"reasoning": false` — модель без размышления.

|---|---|

| клон встроенного как отдельный вариант | новый `id` + `extends: "<builtin>"` |

### 8.4. Локальная модель через vLLM (self-host)

Локальный сервер подключается как обычный OpenAI-совместимый провайдер:

```jsonc
{
  "id": "local-vllm",
  "name": "Локальный vLLM",
  "protocol": "openai",
  "baseURL": "http://localhost:8000/v1",
  "auth": "none",
  "models": { "fetch": true }
}
```

Ключ не нужен (§4.1): модели придут из каталога сервера, карточка провайдера напишет «Ключ не нужен — сервер ответил».
Если сервер ещё не запущен, модели появятся сами в течение 10 секунд после его запуска.

**Про tool calling — со стороны сервера, а не конфига.** vLLM по умолчанию не разбирает
вызовы инструментов: сервер надо запускать с `--enable-auto-tool-choice` и подходящим
`--tool-call-parser` (для Nemotron 3 формат qwen3-совместимый → `--tool-call-parser
qwen3_coder`). Без этих флагов модель вызовы генерирует, но сервер отдаёт их простым
текстом — со стороны IDE симптом неотличим от «модель не умеет инструменты», и правкой
`providers.json` он не лечится.

## 9. Чек-лист валидного конфига

- [ ] Корень — объект с массивом `providers`.
- [ ] У каждого провайдера есть уникальный `id`.
- [ ] У нового провайдера задан `baseURL`.
- [ ] Ключ задан ссылкой (`apiKeyEnv` или `apiKeyRef`), а не значением в файле; серверу без ключа — `"auth": "none"` и никакого ключа.
- [ ] `auth` написан, только если сервер ждёт ключ не там, где его кладёт протокол (§4.1); вендору с несколькими протоколами на одном ключе `auth` не пишут.
- [ ] `baseURL` включает версию пути; если каталог моделей не на `<baseURL>/models` — `fetch` указан полным URL строкой.
- [ ] У каждой модели в `static` есть `id`.
- [ ] Для OpenAI-совместимого API у моделей `toolFormat: "openai"`.
- [ ] Провайдеро-специфичные тумблеры — в `extraBody`, а не в стандартных полях.

См. также готовый пример: `.vibe-defaults/providers.example.jsonc` (засевается в `.vibe/`).
