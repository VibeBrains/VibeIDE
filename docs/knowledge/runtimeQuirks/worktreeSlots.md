# Слоты ресурсов для деревьев агентов

**Зачем.** Параллельные роли в своих деревьях git делили всё, что не в git: порт dev-сервера и имя стенда docker compose
Второй `npm run dev` падал на занятом порту, второй `docker compose up` гасил стенд первого

**Как устроено.** При создании дерева main-сервис выбирает наименьший свободный номер 1…N (`common/worktreeSlots.ts`)
Номер пишется в служебную папку дерева у git (`.git/worktrees/<имя>/vibe-slot`): удаление дерева уносит его само, утечек после падения IDE нет
Занятые номера читаются из служебных папок всех деревьев, а не из памяти окна: деревья прошлых запусков тоже на счету
В корень дерева пишется `.vibe-slot.env` (спрятан через `.git/info/exclude`)
`run_command` находит слот по папке запуска: путь внутри `.vibe-worktrees/<имя>` — читается `.vibe-slot.env` этого дерева, и переменные уходят в окружение терминала
Слот не протаскивается через параметры инструмента: команда вне дерева идёт как раньше, а контракт инструмента не меняется

**Чего нет.** База на слот: универсально создать БД IDE не может, проект делает схему сам по `VIBE_SLOT`
Сбой слота не роняет создание дерева: дерево без слота лучше, чем никакого
