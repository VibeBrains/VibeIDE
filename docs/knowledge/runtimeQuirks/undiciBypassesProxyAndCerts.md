## [квирк] Голый `undici`/Node-`fetch` в electron-main ≠ сетевой стек браузера

**Контекст:** каталог models.dev (`electron-main/llmMessage/modelsDevCatalog.ts`) грузился напрямую через `import { fetch } from 'undici'`. Пользователь жаловался, что каталог «постоянно недоступен» (модал «офлайн режим»), хотя тот же `https://models.dev/api.json` открывается в браузере. Диагностика с машины владельца: `curl` и `undici` оба отдают HTTP 200, системного прокси нет — значит на этой машине дело было в таймауте (см. ниже), но корневая хрупкость шире.

**Суть:**

- **`undici` (и Node global `fetch`, он на undici) не читает системный/VS Code прокси** без явного `ProxyAgent` и **не доверяет системному хранилищу CA** (macOS Keychain / Windows cert store) — использует только вкомпилированный в Node набор корней. Браузер и Electron `net` используют системный стек: и прокси, и корпоративные/MITM-корни. Отсюда классика «URL открывается в браузере, а IDE пишет offline» на корпоративной сети с прокси или TLS-инспекцией.
- **Единый таймаут на весь запрос опасен для крупного тела.** Было `AbortSignal.timeout(10_000)`, покрывавшее соединение + скачивание **~3.2 МБ** (каталог разросся) + `res.text()` + `JSON.parse`. На медленной/нестабильной сети → интермиттентный `TimeoutError` → ложный «офлайн». Симптом «стало постоянно» = каталог перевалил за объём, который стабильно качается за 10 с.

**Применение:**

- В electron-main любые внешние HTTP-запросы вести через **`IRequestService.request()`**, не через `undici`/global `fetch`. В main он идёт через Electron `net` → системный прокси + системные CA. Пример-близнец: `RemoteCatalogFetchChannel`. Таймаут закладывать под реальный объём тела (для models.dev — 55 с).
- Module-singleton без DI (как `modelsDevCatalog`) — сервис инъектить один раз на старте через явный `init...(service)` из `registerVibeideMainChannels.ts`, а не тащить `IRequestService` параметром через каждый вызов.
- При code review сетевого кода в main: увидел `undici`/`node-fetch`/global `fetch` — красный флаг, спросить про прокси и сертификаты.

**Антипаттерны:** «починить» офлайн поднятием таймаута или `NODE_TLS_REJECT_UNAUTHORIZED=0` / кастомным `ca` — это заплатка, оставляющая прокси-слепоту; правильный путь — штатный `IRequestService`.
