## [квирк] Одиночный наблюдатель отказывается от всего под `/Volumes/`

**Контекст:** на живом стенде 23.09.2026 правка `settings.json` не доходила до окна, а журнал `fileWatcher.log`
стенда был полон строк
_«Refusing to watch … for changes using fs.watch() for possibly being a network share»_.
Стенд лежал в `/Volumes/Storage/Caches`, а у владельца под `/Volumes/Storage/Projects` лежат и все проекты.

**Суть:**
- На macOS одиночный (нерекурсивный) наблюдатель VS Code отказывается от любого пути под `/Volumes/`.
  Проверка грубая — по префиксу пути: слежение за samba-шарами роняло приложение (microsoft/vscode#106879)
- Рекурсивный наблюдатель рабочей папки (parcel) этой проверки не имеет и под `/Volumes` работает: файл,
  созданный в рабочей папке стенда, появился в проводнике
- Одиночный наблюдатель **файла** пробует переиспользовать рекурсивный — но только если тот уже
  зарегистрирован в момент запроса. Это гонка: на стенде `.vibe/agents.json` получил отказ в одном из двух
  запусков окна
- Одиночный наблюдатель **папки** рекурсивный не переиспользует никогда — под `/Volumes` он мёртв всегда
- Отказ молчаливый для кода: коррелированный наблюдатель (`createWatcher`) просто не присылает событий. У
  некоррелированного (`fileService.watch` + общий `onDidFilesChange`) события файлов рабочей папки всё равно
  приходят — от рекурсивного наблюдателя

**Применение:**
- Файл внутри рабочей папки слушать через общий `onDidFilesChange` (`e.contains(uri)`). Коррелированный
  наблюдатель — только для файлов вне рабочей папки (`~/.vibe/…`)
- Настройки одноразового профиля стенда в `Caches` задавать **до** загрузки окна: запись в `settings.json`
  и штатная команда «Разработчик: Перезагрузить окно». Правка на лету стенд не увидит
- Перезагрузку окна делать командой VS Code, а не `reload` страницы через CDP: такая перезагрузка идёт
  мимо жизненного цикла окна, главный процесс пишет десятки «acceptReply was called without receiving a
  matching request». Стенд, закрывшийся вскоре после неё без записи о падении, по всей видимости погасил
  владелец: копии съедали память (см. сторож памяти в [liveSmokeStand.md](../testing/liveSmokeStand.md))

**Антипаттерны:** «предпочитать коррелированные наблюдатели» из гайдлайнов VS Code не распространяется на
файлы рабочей папки под `/Volumes` — там это единственный способ ничего не услышать.
