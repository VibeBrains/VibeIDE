## [решение] `~/.vibe/mcp.json` вместо `~/.vibeide/mcp.json` (2026-10-15)

**Контекст:** VibeIDE читала серверы из `~/<dataFolderName>/mcp.json`, VibeIDEA — из `.vibe/mcp.json` проекта.
Один человек держит одни и те же серверы (трекер, база, документация) в обеих IDE, и два файла значили писать каждый
сервер дважды и искать, в какой из копий лежит устаревший токен. У брата владельца общий файл `~/.vibe/mcp.json` уже
был — с сервером `mcp-atlassian`.

**Что выяснено по коду, а не по письму** (сверка 15.10.2026):
- VibeIDEA читает **только** `<проект>/.vibe/mcp.json` (`McpServersFile.pathIn`), домашнего файла у неё нет.
- Из полей она знает `command`, `args`, `env`, `disabled`. Запись без `command` — жалоба `NO_COMMAND`, то есть записи по
  адресу (`url`) для неё жалоба, а не пропуск. `cwd`, `tools`, `headers`, `headersHelper`, `type` она не читает.
- Запись и с `command`, и с `url` VibeIDE подключала по адресу (проверка `server.url` идёт первой), VibeIDEA запускает
  команду: одна запись значила два разных сервера.
- Подстановок `${VAR}` и ссылок на `.env` в записи нет ни у одной: `env` берётся как написано.
- `disabled` у VibeIDE не было вовсе: включённость жила в настройках приложения (`mcpUserStateOfName`), не в файле.

**Решение:**
- Общий файл — `~/.vibe/mcp.json`, один путь для релиза и dev-сборки (папка семейства, а не продукта).
- Проектный файл — `<проект>/.vibe/mcp.json`, сильнее общего: запись заменяет запись с тем же именем **целиком**, а не
  по полям (`command` одного сервера с `args` другого — сервер, которого никто не писал). Порядок слоёв тот же, что у
  провайдеров VibeIDEA: общий слабее проектного.
- Разбор и слои — чистая часть [`common/mcpServersFile.ts`](../../../src/vs/workbench/contrib/vibeide/common/mcpServersFile.ts),
  перенос — [`common/mcpLegacyMigration.ts`](../../../src/vs/workbench/contrib/vibeide/common/mcpLegacyMigration.ts)
  с подставной файловой системой в тестах.
- Общий формат стережёт набор `.vibe`: `testVectors/mcpServersFile.json`, его читают тесты обоих продуктов. Там же то,
  чем VibeIDEA расходится с договорённостью сейчас (читать оба файла, молча пропускать записи по адресу, называть
  двусмысленную запись) — хендофф лежит в её памяти.
- `disabled: true` выключает сервер в файле, и переключатель в настройках VibeIDE его не включает (главный процесс
  проверяет запись, а не только сохранённую включённость). Состояние «offline» несёт текст, почему выключен.
- Запись с `command` и `url` сразу — жалоба `AMBIGUOUS`, запись пропускается в обоих продуктах.
- Серверы проекта запускаются, только когда папка доверена: клонированный репозиторий не должен запускать программы одним
  открытием. «Добавить запись в файл — значит согласиться» верно для файла самого человека, но не для чужого репозитория,
  поэтому согласием служит доверие папки. Config Guard сканирует слитый набор как обычно.

**Перенос из `~/<dataFolderName>/mcp.json`** — при первом запуске, один раз:
- общий файл пишется **первым**, прежний переименовывается **после** в `mcp.json.migrated` (с номером, если имя занято):
  сбой между ними ничего не теряет, а повтор не дублирует — перенесённые имена уже на месте;
- по имени, не по содержимому: запись общего файла не затирается, та же — переносить нечего, другая — конфликт в уведомлении,
  проигравшая запись остаётся в переименованном файле;
- записи едут такими, какими были, вместе с неизвестными полями; прочие ключи общего файла сохраняются;
- нечитаемый прежний или общий файл — перенос не выполняется, уведомление называет причину: затирать нечитаемое нельзя;
- второе окно, успевшее раньше, не сбой: файла уже нет, как и просили.

**Окна и общие серверы.** Серверы живут в главном процессе одним набором, а проектный файл у каждого окна свой. Раньше
главный процесс верил картине последнего окна, и окно без проекта закрыло бы серверы окна с проектом.
Теперь он хранит последнюю картину каждого окна и сверяется с **объединением** ([`unitePictures`](../../../src/vs/workbench/contrib/vibeide/common/mcpReconcile.ts)):
- имя одно на приложение; одно имя с разными запусками у двух окон — запущена запись, что уже работает, иначе окна,
  заговорившего первым; второму окну по его IPC-каналу сообщается конфликт, и оно показывает у имени ошибку «имя занято»
  (второй сервер под тем же именем увёл бы вызовы агента на сервер чужого проекта);
- закрытие окна убирает его картину: сервер, нужный только его проекту, закрывается; закрытие последнего окна ничего не меняет;
- сохранённое «включён/выключен» общее для окон, поэтому окно забывает только имена, что были в его собственной прошлой
  картине: иначе окно без проекта стирало бы выключатель серверов проекта.

**Грабли:**
- **dev-стенд с настоящим домом теперь читает и запускает серверы владельца.** Раньше dev-сборка читала отдельный
  `~/.vibeide-dev/mcp.json`; общий файл один. Стенду нужен свой `HOME`.
- **`~/.vibeide-dev/mcp.json` dev-сборки тоже переезжает** в общий файл (путь выводится из `dataFolderName`). Пустой переезжает молча.
- **Правка `docs/manuals/mcpSpec.md`** требует перегенерации `vibeDocsBundle.generated.ts` (`npm run gen:docs-bundle`).
- **Транспиляция точечных файлов поверх чужого `out/`** гонится с `npm run compile` в другой сессии: `out/` очищается, и
  тест падает на отсутствующем `uri.js`. Дождаться конца компиляции.

**Проверено живьём** (dev-стенд с изолированным `HOME`, подставной stdio-сервер на SDK, 15.10.2026):
- перенос: запись `legacyA` из `~/.vibeide-dev/mcp.json` переехала в `~/.vibe/mcp.json`; `dup` с другой записью осталась записью общего
  файла; ключ `custom` общего файла цел; прежний файл переименован в `mcp.json.migrated` с исходным содержимым, проигравшая запись в нём;
- запущены три сервера (по одному процессу): `dupShared`, `sharedB-user`, `legacyA` — перенесённый стартовал сразу;
- тот же перенос прошёл и на настоящем `HOME`: dev-стенд, запущенный с новым кодом без изолированного `HOME`, переименовал пустой
  `~/.vibeide-dev/mcp.json` и создал пустой `~/.vibe/mcp.json`. Данных это не затронуло, но показывает, зачем стенду свой `HOME`.

**Не проверено:**
- слой проекта на живом окне: стенд открылся без папки (заголовок окна без имени папки), серверы проекта не стартовали;
- текст уведомления о переносе: к моменту чтения тосты ушли;
- доверие папки (запуск был с `--disable-workspace-trust`), наблюдатель создания `.vibe/mcp.json` в проекте;
- два реальных окна с конфликтом имён; Windows.
