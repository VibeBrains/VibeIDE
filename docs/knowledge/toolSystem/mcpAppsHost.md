# Хост MCP Apps в чате VibeIDE

**Домен:** toolSystem · **Дата:** 2026-09-14

---

## 1. Почему свой хост, а не апстримный

`ChatMcpAppModel` из апстрима вшит в апстримный чат:
- ждёт `IChatToolInvocation` и его состояние
- кладёт текст через `IChatWidgetService`
- скачивание и ссылки ведёт через файловую систему ответов чата

Наш чат на React ничего из этого не имеет.
`IMcpAppCallTransport` расширяем, а модель — нет.
Поэтому протокол повторён в `browser/mcpAppHost.ts`, а общее взято у апстрима без копии:
- `injectMcpAppPreamble` — CSP и мост `postMessage` (вынесено из приватного метода модели)
- `readResourceContentToHtml` — разбор ресурса (стал экспортом)

При обновлении базы VS Code эти два экспорта — наши правки в апстримных файлах, их стережёт проверка оверлея.

## 2. Где что живёт

| Слой | Файл | Что делает |
|---|---|---|
| Правила | `common/mcpApps.ts` | Ресурс и видимость из `_meta.ui`, старый ключ `ui/resourceUri`, возможность клиента, допустимые ссылки |
| Главный процесс | `electron-main/mcpChannel.ts` | Объявляет расширение, хранит `callResult`, команды `readResource` и `callToolForApp` с ответом-исходом |
| Сервис окна | `electron-browser/mcpService.ts` | Фильтр видимости для модели, проверка «инструмент того же сервера и с `app`» |
| Хост | `browser/mcpAppHost.ts` | Webview, JSON-RPC, подтверждения |
| Чат | `SidebarChat.tsx` → `McpAppFrame` | Монтирует хост под результатом, высота от приложения |

## 3. Грабли

- **`call` канала глотает исключение и отдаёт `undefined`.**
  Для запросов приложения это превращалось бы в «ответ пустой».
  Поэтому команды приложения возвращают `{ ok, value | error }`, а сервис окна разворачивает исход в исключение
- **Инструмент приложения может ответить одним `structuredContent`.**
  Раньше пустой `content` падал на `content[0].type`.
  Теперь модель получает JSON структурного ответа, а приложение — результат целиком
- **Возможности клиента задаются при создании `Client`.**
  Смена `chat.mcp.apps.enabled` без переподключения ничего не меняет, поэтому она перезапускает обновление серверов
- **Черновик поля ввода не имел внешнего входа.**
  `setThreadDraft` вызывается на каждое нажатие клавиши, событие там дало бы петлю.
  Отдельный `offerThreadDraft` кладёт текст только в пустой черновик и сообщает об этом событием
- **`connect-src 'self'` у апстрима.**
  Сервис-воркер webview выключен, так что `'self'` сетевого доступа не даёт; это поведение апстрима, мы его не меняли
