# MRTR: что показал стенд с подставным сервером

← [Knowledge Index](../README.md)

**Повод:** обработка MRTR (SEP-2322) была написана без единого живого сервера новой ревизии —
серверов попросту нет. Стенд заменил их подставным: `/Volumes/Storage/Caches/vibeide/mcp-mrtr-stub/`
(README там же).

---

## Сервер написан БЕЗ SDK — и это главное решение стенда

Соблазн был собрать подставной сервер тем же SDK. Тогда стенд проверял бы не спеку, а согласие SDK
сериализовать наш конверт: поле, которого SDK не знает, он мог бы срезать на обеих сторонах разом, и
проверка прошла бы зелёной, ничего не проверив.

Поэтому сервер пишет байты сам (JSON-RPC построчно, как велит транспорт stdio), а клиент — настоящий
SDK, тот же, что в главном процессе. Асимметрия здесь и есть метод.

**Что этим выяснено:** SDK 1.29.0 **не срезает** незнакомые поля результата — `resultType`,
`requestState` и `inputRequests` доходят до нашего разбора целыми. Это было главным неизвестным:
не дойди они, вся обработка оказалась бы мёртвым кодом.

---

## Сервер ревизии 2026-07-28 до нас не доходит вовсе

Первый же запуск стенда отказал на рукопожатии:

```
Error: Server's protocol version is not supported: 2026-07-28
```

`SUPPORTED_PROTOCOL_VERSIONS` у SDK 1.29.0 заканчивается на `2025-11-25`. Сервер, настаивающий на
ревизии, которая MRTR и ввела, отвергается клиентом ДО первого вызова инструмента.

Отсюда честная граница возможности: сегодня наша обработка MRTR достижима только у сервера, который
шлёт `input_required`, договорившись о более ранней ревизии. Полная поддержка приедет с обновлением
SDK, а не с правкой нашего кода.

**Что сделано с этим:** отказ перестал быть английской строкой из недр SDK —
`describeProtocolMismatch` называет ревизию, говорит, что это не ошибка настройки, и предлагает
единственное, что тут в руках пользователя: включить у сервера режим совместимости.

## Что стенд проверяет, а что нет

Проверяет: конверт целиком, разбор схемы в форму, разделение просьб (человеку / окну / отказ),
**дословность `requestState`** (сервер сверяет его сам и жалуется на искажение), непопадание пустого
необязательного поля, приведение целого к числу, повтор вызова.

Не проверяет: диалог с человеком и мост «главный процесс → окно → главный процесс» — их заменяет
функция, повторяющая поведение окна. Эти два звена проверяются только в живой сборке.

**Правило:** заявление «MRTR работает» до живой сборки означает ровно то, что перечислено выше, —
и не больше.
