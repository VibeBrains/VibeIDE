# Извлечение по схеме и модели без инструкций

← [Индекс базы знаний](../README.md)

## [правило] Модель, которая не принимает промпт, не зовут через чат (2026-09-13)

**Контекст:** Schematron (inference.net) извлекает JSON из HTML по схеме и, по документации вендора,
не использует ни системный, ни пользовательский промпт. Задача дайджеста 13.09 — подключить её.

**Почему не провайдером в чате:**
- путь чата всегда несёт системный промпт;
- для модели без системной роли `supportsSystemMessage: false` вклеивает его в первое сообщение
  пользователя — то есть прямо в HTML;
- `extraBody` файла провайдера статичен, а схема нужна своя на каждый вызов.

**Как сделано:**
- Инструмент `extract_structured` зовёт модель напрямую, как совет моделей: одно сообщение
  пользователя с HTML, без системного промпта.
- Схема на один вызов едет полем `extraBody` → `runtimeOptions.extraBody` → слияние в
  `openAICompatExtraBody`, которое кладётся **после** тела SDK. Значит, `response_format` вызова
  перекрывает любое значение SDK и провайдера.
- Модель — настройкой `провайдер/модель`, а не новой фичей в списке `featureNames`: тот закрыт и
  тянет правку интерфейса настроек.

**Грабли по дороге:**
- **`...proxyParams` в сервисе окна.** Всё, что не разобрано по имени, уезжает в главный процесс
  верхним уровнем. Новое поле параметров надо разбирать явно и класть в `runtimeOptions`, иначе оно
  молча не дойдёт до адаптера.
- **Правка большого файла скриптом без записи.** Первый заход по `toolsService.ts` оборвался до
  `write` и не сообщил об ошибке — факт правки проверяется грепом по файлу, а не выводом скрипта.

**Открыто:** живой ответ Schematron не проверен — нет ключа. Не проверено и то, что OpenRouter
прокидывает `response_format` этой модели без изменений.
