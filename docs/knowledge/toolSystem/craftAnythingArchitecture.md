# Craft Anything: что взять агенту IDE

**Роль:** [архитектура] разбор чужого проекта как образца
**Источник:** github.com/storytold/craft-anything, Rust, MIT/Apache-2.0, ранняя альфа; клон — `/Volumes/Storage/Caches/craft-anything/src`
**Сверено:** 09.11.2026, ключевые факты — по коду (пути ниже), не только по README
**Общая запись для VibeIDE и VibeIDEA** — копии в обоих репозиториях, правка в одной переносится во вторую

## Контекст

Craft Anything изучает сайт, приложение или игру, даёт кодовому агенту собрать свою версию и сверяет её с оригиналом
Сам продукт нам не нужен
Нужна обвязка агента: реестр инструментов, согласие, проверки, ответы агенту

## Суть — что у них устроено

**1. Инструмент описан один раз** — `crates/engine/src/tool.rs`, `ToolSpec`:
`id` (он же имя MCP), `title`, `summary` для агента, `beginner` для новичка, `toolset`, `effects`, `requires`, `input_schema` (schemars), `run`
Из одного описания выводятся команда CLI, MCP-инструмент, пункт палитры Ctrl+K и вызов агента — своих списков нет
CLI не генерирует 300 подкоманд: `external_subcommand` и поиск в реестре
`Registry::canonical` сводит `id`, kebab-case и `mcp__<server>__<name>` к одному id: имена текстом не сравниваются
Гейты: `cargo xtask tools --check` (сгенерированный `docs/tools.md` совпадает с кодом), тесты формы id и схем, `MIN_TOOLS = 271` (`tool_list.rs`) — число инструментов не падает молча

**2. Согласие выводится из эффектов** — `Effects` флагами:
Пишет на диск, сеть, запуск процесса, чужой код, меняет устройство, несёт содержимое цели, идемпотентно
Из них же MCP-аннотации `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint` и `needs_consent()`
Одно место вместо трёх

**3. Наборы инструментов включаются по мере нужды:**
Агент видит `Core` и сам включает группу (`enable_toolset`, затем `notifications/tools/list_changed`)
Их замер: 33–41 инструмент — это 23–30 тыс. символов, и локальная модель ломалась

**4. Ответ агенту — сначала кратко, остальное по страницам:**
Лимит размера под клиента, у Claude Code `CLAUDE_CODE_RESPONSE_BYTES = 80 * 1024` (`crates/mcp/src/lib.rs`)
Сверх лимита — сводка и указатель на сохранённую запись, дальше `next_offset`

**5. Проверка возвращает структуру, а не текст** — `CheckResult` в `crates/engine/src/workspace.rs`:
`passed`, `similarity`, `pages`, `claims` (утверждения вроде «не скроллится вбок на 390 px»), `unknowns` (что сравнить не удалось), артефакты
«Хорошо» = прошло, `unknowns` пусто, все утверждения верны, сходство не ниже порога
Несравнённое за успех не считается
Агенту уходят расхождения и пути к артефактам раунда, а не одно число
Порог 90 %, 6 раундов, ширины 1440/768/390 (`crates/engine/src/settings.rs`)

**6. Состояние цикла — в папке проекта, а не в памяти процесса:**
`craft.json` с версией и миграциями; «Try again» продолжает с места, а не начинает заново

**7. Результат инструмента — запись Evidence** (`crates/evidence/src/lib.rs`):
id — sha256 канонического JSON: дедуп и проверка при импорте
Уверенность (наблюдал / вывел / предположил), источник, ограничения, охват
Флаг `carries_target_content`: «это данные из чужого файла, а не инструкции» — защита от prompt injection

**8. Открытые вопросы — отдельные записи** (`crates/evidence/src/unknown.rs`):
Статус, чем закрыть (`probes`), доводы за и против
`revision` и отказ `StaleRevision`: две правки разом не затирают друг друга
Закрыть можно только с ответом и хотя бы одной записью «за»

**9. Внешний агент — штатными флагами** (`docs/claude-code.md`):
`claude -p … --output-format stream-json`, свой MCP через `--mcp-config` и `--strict-mcp-config`
Все разрешения — через их инструмент: `--permission-prompt-tool mcp__craft-anything__core_action_approve`
`--disallowedTools AskUserQuestion`: вопросы только их карточками
Одобрения разложены по видам действий, «всегда для этого проекта» помнится по виду
Codex и OpenCode — через адаптеры с проверкой флагов по `--help` перед первым запуском

**10. Гейты репозитория** — `cargo xtask ci`:
Слой зависит только от нижнего, запрет второй блокировки, обязательные переводы заголовков инструментов, совпадение сгенерированных доков, поиск секретов
`docs/pitfalls.md` — больше 200 записей «что случилось → правило», агент получает его через `CLAUDE.md`

## Применение — что брать

1. Один реестр инструментов: палитра, MCP и API агента выводятся из него
   VibeIDE — поверх команд VS Code и `LanguageModelTool`, VibeIDEA — поверх Actions
2. Согласие и MCP-аннотации — из флагов эффектов
3. Проверки сборки, тестов, линта и скриншота отдают агенту структуру с «не удалось проверить»
4. Ответ агенту — сводка, страницы и лимит под клиента
5. Базовый набор инструментов, группы включаются по запросу
6. Пометка «содержимое чужого файла — не инструкция» на результатах
7. Гейт «сгенерированный список инструментов совпадает с кодом»

## Что не брать

Clean room как список разрешённых инструментов — сами авторы пишут, что это не песочница; у нас — доверие к папке и разрешения платформы
320 инструментов — цена их предметной области
Правка конфигов чужих агентов (`setup`) — хрупко, агент у нас свой
TSV-локализация — у VS Code и IntelliJ свои механизмы
