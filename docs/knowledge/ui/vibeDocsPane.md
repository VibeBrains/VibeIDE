# Панель «Документы»: CRUD поверх ObjectTree

← [Knowledge Index](../README.md)

Панель markdown-навигации (`contrib/vibeide/browser/vibeDocs*`). Раньше жила разделами внутри [[specsPane]] — с превращением в read-write выросла в свою запись. Паттерн добавления боковой панели и DnD-контракт (`text/uri-list`, capture-фаза в `sidebarPane.ts`) по-прежнему там.

---

## [архитектура] Read-only витрина → панель с файловыми операциями (2026-07-15)

**Контекст:** панель показывала дерево `.md` из `docs/` и умела только открывать превью. По фидбеку добавлены тулбар (Создать файл/папку, Обновить, Свернуть все), ПКМ-меню (переименовать, вырезать/копировать/вставить, удалить, пути, показать в ОС) и скрытие расширения в строках.

**Суть:**

| Слой | Что держит |
|---|---|
| `vibeDocsService` | скан + **мутации** (`createFile`/`createFolder`/`rename`/`delete`/`paste`) + чистые `validateDocName` / `applyMarkdownExtension` |
| `vibeDocsViewPane` | дерево, инлайн-ввод, свой буфер cut/copy, контекст-кеи, ПКМ |
| `vibeDocs.contribution` | `registerDocsAction` — один хелпер на все 14 команд (тулбар + ПКМ + кейбинды) |

Действия **не принимают аргументов**: резолвят живой пейн через `IViewsService.getViewWithId` и работают по выделению дерева. Одна точка входа на ПКМ и кейбинд, ничего не надо плюмбить через `getActionsContext`.

**Применение:** мутации — только в сервисе (чистая ФС), диалоги/нотификации — в пейне. Новую команду добавлять через `registerDocsAction`, не копируя `registerAction2`.

**Связано:** [[specsPane]] — паттерн панели и DnD.

## [правило] Скрытие расширения тянет за собой три неочевидных следствия (2026-07-15)

**Контекст:** панель markdown-только, `.md` в каждой строке — шум. Скрыли — и вылезло то, чего в задаче не было.

**Суть:**

1. **Валидация раздвоилась.** Пользователь вводит `guide`, на диск идёт `guide.md`. Пустое имя проверять надо по **введённому** (иначе пустая строка превращается в `.md` и проходит), а коллизию — по **итоговому**. Отсюда `validateDocName(typed, finalName, siblings, original?)` с двумя именами, а не одно.
2. **`.md` vs `.mdx` схлопываются.** `guide.md` и `guide.mdx` в одной папке дают две визуально одинаковые строки. Дерево не ломается (`id` = relPath), но глазами не различить → `.mdx` помечен CSS-бейджем `x` на иконке (`.vibe-docs-icon.is-mdx::after`). В репо сегодня 0 файлов `.mdx` — задел, не мёртвый код: фильтр их принимает.
3. **Переименование обязано сохранять расширение.** Показали `russianFirst` — на accept подставляем **исходное** расширение, не `.md` вслепую. Явно введённое `.md`/`.mdx` уважаем (`applyMarkdownExtension(name, fallbackExt)`).

**Применение:** трогаешь `displayName()` — проверь все три. Полное имя всегда остаётся в тултипе строки.

## [баг] Пруниг пустых папок vs «Создать папку» — взаимоисключающие (2026-07-15)

**Контекст:** `_walk` не отдавал папку без `.md` внутри — осознанное решение read-only витрины («дерево доков не должно показывать пустые каталоги»).

**Суть:** с кнопкой «Создать папку» это превращается во вредительство — папка создаётся и **тут же исчезает из дерева**, потому что она пуста. Пруниг снят, папки показываются все.

**Применение:** записанное решение может быть верным для своей эпохи и стать ложным после смены контракта панели. Это ровно тот случай, о котором говорит правило «раскопок»: проверять обоснование по фактам, а не принимать на веру. Read-only → read-write ломает инварианты, а не только добавляет кнопки.

## [квирк] Инлайн-ввод в ObjectTree: фокус на кадр позже, иначе edit самоотменяется (2026-07-15)

**Контекст:** `WorkbenchObjectTree` перестраивается целиком (`setChildren`) на каждое изменение ФС. Инлайн-ввод живёт в строке дерева, которая монтируется посреди этой перестройки.

**Суть:**

- `input.focus()` **прямо в `renderElement`** — ловушка: список забирает фокус обратно, пока досоздаёт строки → `blur` → имя пустое → правка отменяется, и «Создать файл» просто не работает. Фокус берём через `DOM.scheduleAtNextAnimationFrame` + флаг `focused`, blur до этого момента игнорируем.
- **Re-entrancy:** `accept()` обязан сбрасывать `_edit` **до** записи на диск — иначе blur от исчезающего инпута входит второй раз. Blur дополнительно сверяет идентичность: `getEdit() !== edit → return`.
- **Черновик переживает repaint:** watcher может дёрнуть `_paint` посреди набора текста. `IEditContext.draft` пишется на каждый `onDidChange` и восстанавливается в новый InputBox.
- **Состояние раскрытия тоже переживает repaint.** `collapseByDefault:false` + перестройка = дерево само разворачивается на каждое изменение ФС; «Свернуть все» без этого живёт до первого watcher-события. Держим `Set<string>` collapsed-id из `onDidChangeCollapseState` и кормим обратно в `IObjectTreeElement.collapsed`.
- **Welcome-view скрывает body.** При пустой панели `_rosterEmpty` прячет дерево → инпут «Создать файл» негде показать. Условие: `nodes.length === 0 && !this._edit`.

**Применение:** любой инлайн-ввод в дереве, которое перестраивается извне, обязан закрыть все пять пунктов. Синтетическая строка-плейсхолдер (`NEW_NODE_ID`) вставляется в `_toElements` по `parentNodeId`.

**Антипаттерн:** NUL-префикс (`' ...'`) как id плейсхолдера писать **escape-последовательностью**, а не живым байтом — иначе `.ts` становится бинарным для grep/diff.

## [правило] Буфер панели — свой, не общий с Проводником (2026-07-15)

**Контекст:** развилка при проектировании ПКМ: переиспользовать clipboard-слой `contrib/files` или держать свой.

**Суть:** выбран свой (`{sources: URI[], move: boolean}` в пейне + контекст-кей `vibeDocsClipboardHas`). Панель не импортирует из `contrib/files` **ничего** — единственная общая точка остаётся `fillEditorsDragData` из `workbench/browser/dnd.ts`. `revealFileInOS` дёргается **по id команды**, а не импортом, — связанности не создаёт.

Что сервис обязан гасить сам при вставке: папка в себя/потомка (`isEqualOrParent` — иначе источник съедается), move в ту же папку (no-op, не копия), коллизии имён (суффикс `copy`, расширение остаётся хвостом).

**Применение:** «вырезал в Документах — вставил в Проводнике» намеренно **не** работает. Захотят — это отдельное решение с протаскиванием состояния files-слоя, а не докрутка.
