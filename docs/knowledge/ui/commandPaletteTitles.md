# Заголовок команды не повторяет категорию

← [Индекс базы знаний](../README.md)

> **[грабли+гейт]** Найдено 01.09.2026 на экране, при живом смоуке HTTP API: палитра показывала
> «VibeIDE: VibeIDE: Показать токен HTTP API». Замер по форку: так жили **40** команд, ещё **21**
> висела в палитре вовсе без группы, а **17** заголовков были по-английски.

---

## Контекст

`Action2` описывает команду двумя полями: `category` и `title`. Палитра рисует их сама, склеивая
`<категория>: <заголовок>`. Значит категория в `title` — это не «поясняющий префикс», а второй
экземпляр той же строки.

## Суть

**Ошибка невидима для всех проверок и проявляется только на экране.** Тайпчек к строке равнодушен,
тесты команду не открывают, а гейт локализации смотрит на наличие `localize()`, а не на смысл
текста. Поэтому дубль спокойно дожил до сорока команд: каждый следующий автор копировал соседнюю
регистрацию вместе с префиксом.

Тот же механизм скрыл и вторую половину: **17 заголовков были на английском** («Accept Diff»,
«Query Codebase», «Generate Commit Message») при правиле «все пользовательские тексты — русские,
сразу в исходнике». Правило есть, а смотреть на его соблюдение было нечем.

Третья грань — команды без `category`: формально работают, но в палитре лежат вне группы, и найти
их можно только точным словом.

## Применение

- `category: VIBE_COMMAND_CATEGORY` (`common/vibeCommandCategory.ts`) — единственный источник;
  литералы `{ value: 'VibeIDE', … }` и локальные `const category` разошлись бы по словам;
- `title` — только сам заголовок, по-русски, без префикса;
- `f1: false` — команда в палитру не попадает, категория ей не нужна и добавляет шум;
- гейт: `npm run command-titles-check` (`scripts/vibe-command-titles.ts`) падает на всех трёх
  видах ошибки. Проверен не «зелёным прогоном», а тремя пробами: каждая ошибка внесена в живой
  файл и гейт на ней упал.

## Мелочь, стоившая отдельного круга

Гейт сначала написался как `.mjs` — и pre-commit хук его не пропустил: репозиторий запрещает
новые JavaScript-файлы (`.eslint-allowed-javascript-files` прямо говорит «DO NOT ADD NEW
ENTRIES»). Обойти было бы просто — строкой в allowlist или `--no-verify`; правильный путь —
переписать на TypeScript. При этом `scripts/package.json` пинует `"type": "commonjs"`, поэтому
`.ts` в этой папке пишется через `require()`, а не `import` (как соседний
`scripts/test-agent-host-e2e.ts`) — иначе Node падает на «Cannot use import statement outside a
module».

Побочно вскрылось: `scripts/vibe-quirks-provenance.mjs` в allowlist отсутствует — значит был
закоммичен в обход хука. Переписывать его, однако, **не нужно**, и это проверено: `scripts/` не
входил ни в один tsconfig, поэтому `.ts` там ничем не проверялся, а `.mjs` в папке 39 против 6
`.ts` — правило там де-факто не действует. Вместо переписывания заведён `scripts/tsconfig.json` и
`npm run scripts-typecheck`: новые скрипты, которые хук и так вынуждает писать на TypeScript,
теперь действительно проверяются (первая ошибка нашлась сразу).

Родственное: [[../i18n/russianFirst]] — правило про русский в исходнике, у которого до сих пор не
было гейта на заголовки команд.
