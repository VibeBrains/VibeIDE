## [правило] CSS-обвязка, написанная по догадке, не работает и попадает в своих

**Контекст:** файл `hideBuiltinChat.ts` скрывает поверхности встроенного чата VS Code. Он писался по
чтению апстрима и порт-заметкам, без единой проверки на запущенном приложении. 14.08.2026 разметка
снята с живой IDE через CDP.

**Что выяснилось:**

- **`data-action-id` не существует в разметке вообще.** Элементы композит-баров несут только
  `class`, `role`, `draggable`, `aria-*`, `tabindex`, `style`. Пять правил не делали ничего;
  порт-заметка «в 1.118+ используются data-action-id» была неверна и никем не проверена.
- **Идентификатор композита в DOM не пишется** — `[id="workbench.panel.chat"]` тоже мёртв.
- **Два правила попадали в наш собственный чат.** `.part.auxiliarybar [aria-label="Chat"]` замерено
  совпадающим с `.view-workbench-view-vibeide-chat` — вкладкой VibeIDE, которая лежит ровно в этой
  части и называется «Чат» только потому, что интерфейс сегодня русский. При английской локали
  правило скрыло бы наш собственный чат.

**Правило:** селектор по видимому тексту (`aria-label`, содержимое) — это решение по строке, а оно
запрещено правилом локализации: строка разная в каждом языке, и завтра под неё попадёт своё.
Целиться можно в классы и структуру, но не в подписи.

**Второе правило:** CSS против чужого UI пишется с запущенным приложением, а не по чтению
исходников. Проверка занимает пять минут:

```bash
VSCODE_SKIP_PRELAUNCH=1 ./run-dev.sh --remote-debugging-port=9224
npx agent-browser connect 9224
npx agent-browser eval '[...document.querySelectorAll(".part.auxiliarybar .action-item")].map(e => [...e.attributes].map(a => a.name).join(","))'
```

**Побочно найдено:** `run-dev.sh` лежал в git с режимом `100644` — задокументированная команда
`./run-dev.sh` падала с `permission denied` на свежем клоне. Тот же класс, что [[executableBitInBundle]].
