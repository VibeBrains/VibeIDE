# Раскладка сообщений чата

← [Knowledge Index](../README.md)

Ответ ассистента слева за линией, запрос пользователя справа в пузыре.
Три раскладки — по ширине самой панели чата; ширина окна ничего не решает.

---

## [архитектура] Ответ слева, запрос справа в пузыре — и три ширины панели

**Контекст:** запрос пользователя был плашкой с датой мелко в правом углу под ней, ответ шёл обычным потоком.
Владелец утвердил макет «как в мессенджере»: два голоса различаются положением, цвет фона — второй признак.

**Суть:**
- **Ширина.** Лента (`.vibe-chat-scroll-root`, скроллер Virtuoso) объявлена контейнером запросов: `container: vibe-chat-feed / inline-size`.
  Пороги читают её ширину, поэтому тот же чат в боковой панели на 320 px и в редакторе на 900 px раскладывается по своему
- **Широко (больше 360 px).** Ответ: линия слева 2 px, отступ от неё 10 px, отступ справа 18%.
  Запрос: пузырь с отступом слева 22%, фон и рамка 1 px из токенов, скругление `14px 14px 4px 14px` («хвостик» снизу справа),
  дата и время `ДД.ММ.ГГГГ ЧЧ:ММ` внутри пузыря справа внизу
- **Узко (до 360 px).** Ответ на всю ширину, без линии и без отступа. Отступ пузыря 12%
- **Совсем узко (до 280 px).** Пузырь превращается в плашку на всю ширину: скругление 8 px, рамка только слева 3 px,
  время уходит в подпись сверху «Вы · ДД.ММ.ГГГГ ЧЧ:ММ», нижнее скрыто. Оба элемента лежат в разметке, какой виден — решает CSS
- **Одно место.** Размеры — переменные первого блока `media/vibeChatMessages.css`. Две ширины (360 и 280) записаны дважды,
  в двух правилах `@container`: значение переменной в условии запроса CSS не читает
- **Цвета — токены темы** (`vibeideChatMessageColors.ts`): `vibeide.chat.userMessageBackground`, `userMessageBorder`,
  `userMessageLabel`, `assistantRule`; в CSS — `var(--vscode-vibeide-chat-<имя>)`. Описания по-русски
- **Что остаётся в потоке без пузыря и линии:** карточки инструментов, плашки ошибок и паузы, подсказки автопилота
  (`isSyntheticNudge`), сообщения ассистента с `notice` — их пишет IDE («Прогон завершён…»).
  Замечания, не объясняющие остановку хода, ушли в журнал: [chatJournal.md](chatJournal.md)
- **Редактор сообщения** (режим правки) занимает всю строку: это форма

**Применение:**
- Новый вид сообщения в чате — сперва решить, чей он голос. Модели — линия, человека — пузырь, IDE — без обрамления
- Селекторы правил раскладки только с префиксом `.vibe-scope`. Причина — следующая запись
- Вносить размер или порог — в переменные первого блока файла и, для порогов, в оба `@container`
- Время запроса — тот же формат, что у ответа (`formatChatTimestamp` без паттерна, `DD.MM.YYYY HH:mm`), секунды — в `title` элемента `<time>`.
  Время ответа — в его разметке, вне пузыря. Журнал служебных строк берёт время константой `CHAT_JOURNAL_TIME_PATTERN` (`HH:mm`)

## [foot-gun] Рамка и линия не появились: прямой класс проигрывает preflight Tailwind

**Контекст:** первый живой запуск раскладки. Пузырь был залит, но без рамки, а у ответа не было линии. Замер: `border-left-width` ответа — `0px`,
цвет `rgb(229, 231, 235)` — это `#e5e7eb`, цвет границы из preflight Tailwind.

**Суть:** `scope-tailwind` оборачивает preflight в `.vibe-scope *` (специфичность 0,1,0) и вставляет его стилем в рантайме — позже
любого CSS воркбенча. Класс `.vibe-chat-assistant-msg` (тоже 0,1,0) стоит раньше и проигрывает: `*` обнуляет `border-width` у каждого элемента.
Залитый фон выжил, потому что preflight его не трогает; рамка и линия — единственные свойства, которые он сбрасывает.

**Применение:** правила, задающие `border`, в файлах воркбенча для React-дерева писать как `.vibe-scope .класс` (0,2,0).
Проверка — замер вычисленного `border-left-width` живьём: чтение CSS показывает правило, но не эффект.

**Антипаттерны:** лечить `!important` — он лечит одно место и ломает утилиты рядом.

## [правило] Цвета: акцент фокуса у тем Vibe тусклый — токены заданы явно

**Контекст:** по заданию фон пузыря — акцент фокуса с прозрачностью (`transparent(focusBorder, 0.12)`), рамка — он же с 0,55.
У тем Vibe `focusBorder` задан намеренно близким к фону (Neon `#1f212b`, Midnight `#3d4460`, Graphite `#3a3e41`), и пузырь из него невидим.

**Суть:**
- Умолчания (`registerColor`) работают для штатных тем: у Light 2026 `focusBorder` `#0069cc`, у Dark Modern `#0078D4`
- Все семь файлов `extensions/vibeide-neon/themes/vibe-*.json` получили `vibeide.chat.userMessageBackground` (акцент темы, 15%) и
  `vibeide.chat.userMessageBorder` (он же, 55%). Акцент — тот же, что у `vibeide.chatGroup.activeBorder` темы. `vibe-neon-noglow.json`
  берёт их из Neon через `include`
- **Линия ответа — не от `panel.border` и не от `widget.border`.** Это тихие разделители: у Light 2026 `panel.border` — `#F0F1F2`
  на `#FAFAFD`, то есть линии нет; `widget.border` у штатных тёмной и светлой тем не задан. Умолчание — цвет текста темы с силой 0,25:
  виден в любой теме и сам подстраивается, поэтому в файлы Vibe этот токен не вписан
- **HC:** фона нет, рамка и линия — `contrastBorder`
- Токен без значения в теме CSS не получает вовсе: `var(--имя, transparent)` в файле раскладки страхует это место

**Применение:** править палитру — в JSON темы или `workbench.colorCustomizations` пользователя; кэш тем: правка JSON под работающей IDE не видна
(см. [themesAndChat.md](themesAndChat.md)).

## [квирк] `container-type: inline-size` не делает ленту содержащим блоком для `position: fixed`

**Контекст:** лайтбокс вложений (`util/ImageLightbox.tsx`) рисуется `fixed inset-0` прямо внутри сообщения пользователя, то есть внутри ленты.
Контейнер запросов мог привязать его к ленте и обрезать.

**Суть:** замерено в сборке на Chromium этой IDE — элемент `position: fixed; inset: 0`, вставленный в пузырь при
`container-type: inline-size` на ленте, занял весь экран (`0,0,1440,900`): границы ленты на него не действуют. Портал для лайтбокса не понадобился.

**Применение:** если контейнер запросов когда-нибудь заменят на `size` или добавят `contain: layout`, повторить замер.

## [инструмент] Как смотреть три ширины на стенде

Панель чата — вспомогательная боковая: перетаскиванием левого края (`.monaco-sash` слева от `.part.auxiliarybar`) через CDP
(`mousemove` / `mousedown` / `mouseup` из `@playwright/cli`). Ширину контейнера читать из `.vibe-chat-scroll-root`: `clientWidth` (он на 10–11 px
меньше панели: полоса и рамка). Боковую панель слева закрыть (`Meta+B`): иначе редактор в середине не отдаёт места.
Тему менять записью `workbench.colorTheme` в `User/settings.json` стенда — по **settings id** (`vibe-neon`, `Light 2026`,
`Default High Contrast`); ярлык темы не подходит. Прокручивать ленту `scrollTop`, не `scrollIntoView`: он сдвигает весь воркбенч на несколько пикселей.
Virtuoso держит в DOM только видимое — перед поиском сообщения по тексту прокрутить к началу.
