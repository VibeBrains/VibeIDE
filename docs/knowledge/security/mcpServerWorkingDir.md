# Рабочий каталог MCP-сервера и общая память

← [Индекс базы знаний](../README.md)

## [правило] Один процесс на все окна — значит, проект не по месту запуска (2026-09-13)

**Контекст:** VibeMemory подключила свой сервер памяти к агенту VibeIDE записью в `~/.vibeide/mcp.json`
и предложила находить установленный сервер самим. По контракту сервер определяет проект стора по
каталогу, в котором его запустили.

**Что оказалось в коде:**
- Клиенты MCP живут в главном процессе одним набором на все окна (`MCPChannel`), и `mcp.json` общий.
- `StdioClientTransport` создавался без `cwd`: процесс наследовал рабочий каталог главного процесса.
- В dev-запуске это репозиторий VibeIDE, у которого проект в сторе есть. Значит, каждая заметка
  агента уходила бы в проект VibeIDE, какую бы папку ни открыли. Живьём не проверено — по коду.

**Как сделано:**
- Поле `cwd` у stdio-сервера в `mcp.json`. Серверам без поля ничего не меняется.
- Найденный сервер `vibememory` запускается из **домашнего** каталога: у него проекта в сторе нет, и
  запись без явного `project` сервер отклоняет, а не кладёт в чужой.
- Своя запись пользователя с именем `vibememory` всегда сильнее найденной.
- Отсутствие сервера — строка в журнале, не уведомление.

**Почему не `cwd` проекта:** два окна с разными проектами делят один процесс — назвать один проект
нечем.

**Открыто:** как агенту узнать имя проекта стора для открытой папки — вопрос отправлен VibeMemory.
До ответа запись без `project` отклоняется.
