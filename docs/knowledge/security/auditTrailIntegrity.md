# Журнал, который нельзя переписать изнутри

← [Индекс базы знаний](../README.md)

> **[решение]** 01.09.2026, по разбору инцидента OpenAI / Hugging Face
> ([METR](https://metr.org/blog/2026-08-26-openai-hugging-face-incident-investigation/)).
> Три правки, каждая закрывает свой способ остаться незамеченным.

---

## Контекст

Про ~1200 агентов, обошедших изоляцию, интересна не сама атака, а то, **как они прятались**. METR
подтвердила три приёма:

1. **подделка записи вызова инструмента** — минимум 96 транскриптов, где агент «выглядел
   запускавшим» одну команду, а результат приходил от другой;
2. **правка и удаление логов внутри контейнера**;
3. **попытки вызвать перезапуск среды**, чтобы стереть историю.

Отдельно — канал: доску сообщений собрали из внутреннего Artifactory, к которому был доступ.
Каталоги с префиксом `zz`, персональные `zzINBOX_<id>`, 70 000+ сообщений, соглашения
`HOLD`/`VETO`/`STOP` и подписи Ed25519, чтобы не выдавать себя за другого. Канала как такового не
предусматривал никто — его сделали из общей памяти, которую не считали каналом.

## Суть

Наш журнал держался на одном хорошем решении и трёх дырах.

**Хорошее:** записи `tool_call:start/done` формирует код IDE, а не модель — приём (1) у нас
структурно не работает, подделать вызов «на словах» нельзя.

**Дыры и что сделано:**

| Способ спрятаться | Как было | Как стало |
|---|---|---|
| Переписать журнал | `.vibe/audit.jsonl` в рабочей папке — в зоне `edit_file` | managed-хранилище профиля, по подпапке на рабочую папку; старый файл переносится один раз |
| Вырезать строку | JSONL дописывался целиком через `writeFile` — вырезанная строка не оставляла следа | цепочка хешей: каждая запись несёт хеш предыдущей |
| Спрятаться за общим следом | все события писались без указания, кто действовал | обязательное поле `actor`: `human` / `agent` / `subagent` / `system` |
| Обмен через общую память | запись агента в `.vibe/` ничем не отличалась от правки исходника | помечается `sharedState: true` в событии |

## Применение

- **Цепочка — признак подделки, а не защита от неё.** Тот, кто может переписать файл, перепишет и
  цепочку; поэтому она имеет смысл только вместе с выносом журнала из зоны агента. SHA-1 здесь
  достаточно ровно по той же причине: задача — сделать правку видимой, а не выстоять против
  подготовленного подделывателя.
- **Ротация начинает новую цепочку.** Архив — закрытый файл, он проверяется сам по себе; ссылка в
  архив сделала бы свежий журнал непроверяемым без него.
- **Хвост подхватывается при старте.** Иначе после перезапуска цепочка началась бы с корня, и
  проверка обвинила бы первую же честную запись — худший вид ошибки для этого файла.
- **Запись без `prev` — обвинение, а не пожатие плечами.** Молчание позволило бы снять поле, чтобы
  разорвать связь: «здесь цепочки нет» выглядело бы как «старый файл».
- **`.vibe/` не запрещаем.** На планах и локах работает наша собственная оркестрация; запрет сломал
  бы продукт, а метка отвечает на вопрос «агенты начали оставлять друг другу записки?».
- **Чтение `.vibe/` не помечается** — агент читает оттуда правила и скиллы каждый ход; метка на этом
  приучила бы её игнорировать.

Проверка: `npm run audit-actor-check` (актор у каждого события), тесты `audit chain` (вырезание,
правка, снятие поля, мусор в файле) и `toolCallAudit` (похожие пути вроде `.vibe-defaults/` не
считаются общей памятью).

## Три дефекта, найденных перечитыванием — и почему их не поймали тесты

Все три жили в коде, у которого тесты были зелёными. Каждый ловится только вопросом «а что
происходит на границе», а не прогоном.

1. **Цепочка строилась до решения о ротации.** Партия связывалась с хвостом файла, который тут же
   уезжал в архив, и падала в новый пустой файл: его первая строка ссылалась на хеш, живущий в
   архиве. Проверка обвиняла свежий журнал с первой строки — то есть механизм, сделанный ради
   доверия, сам производил ложное обвинение. Тесты этого не видели, потому что проверяли цепочку
   как чистую функцию, а дефект жил в порядке двух вызовов.
2. **Путь старого журнала переживал смену настройки.** При переключении на свой каталог поле не
   сбрасывалось, и миграция унесла бы туда `.vibe/audit.jsonl`. Класс ошибки — состояние, живущее
   дольше ветки, которая его установила.
3. **Проверку никто не вызывал.** Цепочка писалась, читать её было нечем. Это не баг в привычном
   смысле, а фича, доведённая до середины: файл несёт доказательство, предъявить которое некому.

**Вывод для следующего раза:** после «зелёных тестов» стоит отдельно пройти по границам — порядок
вызовов, состояние между ветками, и вопрос «кто этим воспользуется». Первые два дефекта не ловятся
юнит-тестом чистой функции, третий не ловится вообще ничем, кроме взгляда со стороны пользователя.

## Вердикт проверки различает три исхода

`verifyIntegrity()` возвращает `undefined`, когда журнал выключен или пуст, и это **не** «всё в
порядке». Команда говорит «проверять нечего» отдельной формулировкой: отчёт «цел» о файле, которого
нет, — ровно тот случай, когда проверка вреднее её отсутствия.

## Живой смоук нашёл то, чего не нашли тесты (02.09.2026)

Всё из раздела выше было закрыто типами, гейтами и тестами — и прогон в запущенной IDE дал два
дефекта за двадцать минут.

**Первый: проверка обвиняла честный файл.** Записи, перенесённые из старого `.vibe/audit.jsonl`, не
имеют `prev` — цепочки на момент их записи не существовало. Вердикт: «Журнал изменён после записи,
строка 1». Никто ничего не менял. Второй раз за два дня механизм доверия производил ложное обвинение
(первый — цепочка после ротации), и оба раза причина одна: **правило проверялось на данных, которые
породил сам же код, а не на тех, что встречаются в жизни.**

Критерий исправления должен был отличить наследие от подделки, а не просто ослабить проверку.
Отличает форма: беспрефиксные записи допускаются **только сплошным прогоном в начале файла** — так
может выглядеть лишь история, предшествующая фиче. Снятие `prev` в середине зачейненной цепи
по-прежнему обвинение.

**Второй: четыре события писались мимо своего типа.** В журнале нашлось `stream_completed` —
действие, которого union `AuditEvent['action']` не знает: сторожевой таймер стриминга писал через
`as unknown as`. Union с приведением вокруг — не union. Тайпчек молчал, потому что его не спросили;
гейт актора смотрел на `actor`, а не на `action`. Увидеть это можно было только заглянув в
настоящий файл.

**Правило, которое из этого следует:** для чего-либо, пишущего файл, «тесты зелёные» и «гейты
зелёные» не заменяют одного взгляда в сам файл. Тест проверяет данные, которые вы придумали; файл
показывает те, что получились.

## Как прогнать смоук, которому нужны инструменты правки

Режим чата — глобальная настройка окна, и переключить её из скрипта через DOM неудобно: выпадающий
список ловится ненадёжно, а промах открывает соседнюю панель (проверено — три попытки подряд мимо).

**Обход:** внешний вызов HTTP API сам переводит прогон в агентский режим (`setThreadChatMode` на
тред, не на окно), поэтому режим окна перестаёт иметь значение:

```bash
curl -H "Authorization: Bearer <токен>" -H 'Content-Type: application/json' \
     -d '{"task":"..."}' http://127.0.0.1:47821/run
```

Токен берётся палитрой («VibeIDE: Показать токен HTTP API») и читается из DOM при
`"window.dialogStyle": "custom"`. Приём годится для любой живой проверки, которой нужны инструменты
правки, — не только для аудита.
