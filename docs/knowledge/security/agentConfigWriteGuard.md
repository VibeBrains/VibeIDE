# Агент не правит свою конфигурацию

**Проблема.** Конфигурация агента решает, что ему можно дальше: хуки, команды, агенты, пайплайны, роли, провайдеры, MCP, `.env`, навыки и правила
Инструмент записи, который может её править, может и расширить себе права — сводка 14.11.2026

**Решение.** Запрет — свойство пути, а не отдельного инструмента: `common/agentConfigWriteGuard.ts`, `isProtectedAgentConfigPath`
- Защищены в `<проект>/.vibe/` и `~/.vibe/`: `hooks.json`, `commands.json`, `agents.json`, `pipelines.json`, `roles.json`, `providers.json`, `mcp.json`, `.env`, каталоги `skills/`, `rules/`, `providers/` и сам `.vibe`
- Защищены токены команд VibeMemory: `~/.vibememory/tokens`
- Путь приводится к одному написанию до сравнения: `\` → `/`, двойные слеши, `.` и `..`, регистр без учёта — обходы `./.vibe/../.vibe/hooks.json` и `.VIBE/HOOKS.JSON` ловятся
- Проверяются все имена файла, которые видит `toolsService` (включая цель симлинка), отказ — ошибкой инструмента без вопроса
- Человек правит эти файлы в IDE как прежде; команды терминала агента стережёт отдельный механизм (`commandPathsOutsideProject.md`)

## Навыки с инструментами или хуками без человека

`decideSkillLaunch` в `common/skillApproval.ts`: навык, который объявил `allowed-tools`/`requires-tools` или `hooks`, в прогоне без человека запускается, только если человек одобрил именно этот отпечаток пакета
Интерактивный запуск идёт прежним вопросом; без человека — отказ с причиной «одобрите его в IDE»
Треды без человека помечает `chatThreadService.setThreadAutonomous`: HTTP API и бот Telegram
