# Code Mode — скрипт вместо серии вызовов инструментов

**Контекст.** Цепочка «прочитал → нашёл → прочитал ещё» стоит нескольких раундов модели, хотя решается обычным циклом. Code Mode (`vibeide.agent.codeMode`, off by default) даёт модели инструмент `run_code_mode`, внутри которого она пишет JavaScript: `await tools.read_file({...})`, `console.log(...)`, `return {...}`. Один раунд вместо серии.

**Суть.** Скрипт исполняется не в окне: главный процесс поднимает отдельный Electron utility-процесс (`node/codeMode/codeModeSandboxMain`) на каждый прогон, память ограничена `--max-old-space-size=128`. Внутри — `vm.createContext` с `codeGeneration: { strings: false, wasm: false }`, куда не передаётся ни один объект хоста: только интринсики нового realm (JSON, Math, Date, Promise), `console.log` в массив и объект `tools`, собранный Proxy'ом в самой песочнице. Наружу ведёт ровно одна функция-мост, у которой прототип снят (`Object.setPrototypeOf(bridge, null)`): у неё нет `.constructor`, поэтому `constructor.constructor('return process')()` обрывается.

**Применение.** Каждый `tools.<имя>(args)` — это событие в окно и ответ обратно. В окне вызов идёт ОБЫЧНЫМ путём инструмента: `validateParams`, правила путей и `agentConfigWriteGuard`, диалог одобрения по той же категории (`approvalTypeOfBuiltinToolName` + автопилот/`autoApprove`), `callTool`, аудит `tool_call:done` с пометкой `codeMode: true`. Своего пути исполнения у Code Mode нет — иначе он был бы ярлыком мимо запретов.

**Пределы.** Время — `vibeide.agent.codeModeTimeoutSec` (60 с по умолчанию, зажимается 1–300), вложенных вызовов — 50, размер скрипта и аргументов — 100 тыс. символов, отчёт — 12 тыс. Синхронную часть ограничивает `vm.runInContext({ timeout })`; после первого `await` vm уже не следит за кодом, поэтому работает гонка с таймером, а `while (true)` без `await` блокирует event loop процесса целиком — такой процесс снимает главный по сторожевому таймеру (`timeout + 2 с`).

**Что закрыто.** `require`, `process`, `module`, `globalThis.process` — не определены; `Function`/`eval` — `codeGeneration.strings: false`; `import()` — динамический импорт в vm не настроен; `setTimeout` — не передан; вложенный `run_code_mode` — отказ по имени; `__proto__`/`prototype`/`constructor` — отказ по имени до вызова; имена не по форме (`[a-z][a-z0-9_]*`) — отказ; превышение бюджета вызовов — отказ без исполнения; выключенная настройка — инструмент не показывается модели и `validateParams` бросает ошибку.

**Границы.** Песочница изолирует код, а не намерения: если пользователь одобрил `run_command`, скрипт может запустить команду — как и обычный вызов. Аудит пишет по событию на вложенный вызов, но аргументы инструментов в журнал не попадают (как и в обычном пути). Отчёт обрезается и честно помечает обрезку.
