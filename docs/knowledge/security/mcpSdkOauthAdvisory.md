# CVE-2026-104850: OAuth-клиент MCP SDK отдавал учётные данные чужому серверу авторизации — нас не задевает, версия поднята

## [факт] Что за уязвимость и почему путь нас не касается

**Контекст:** догоняющая сводка 09–21.10.2026 назвала это «срочно поднять SDK до 1.31.0+»; VibeIDEA, разобрав ту же сводку,
оставила проверку версии нам. Проверено 22.10.2026: страница advisory (advisories.gitlab.com, GHSA-6qxp-vccf-f47h),
`npm view @modelcontextprotocol/sdk`, код `mcpChannel.ts`.

**Суть уязвимости (advisory):**
- OAuth-клиент TypeScript SDK позволял MCP-серверу самому назвать сервер авторизации, а клиент отправлял ему
  `refresh_token` и `client_secret`, сохранённые при прошлом входе, и `client_secret` или подписанное утверждение
  встроенного провайдера: без участия человека
- CVSS 3.1: 7.5 (`AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N`), CWE-345 и CWE-522; опубликовано 06.10.2026
- затронуты версии от 1.12.0 до 1.31.0 (1.31.0 не включая), исправлено в 1.31.0

**Почему нас это не задевает:** уязвим путь, который включается объектом `authProvider` в опциях транспорта.
Наш `mcpChannel.ts` создаёт `StreamableHTTPClientTransport` и `SSEClientTransport` без `authProvider`:
заголовки приходят из записи сервера (`_headersOf`), а вход по OAuth к серверам MCP выполняет механизм редактора
(`mcpClientRegistration.md`), а не клиентский код SDK. Из SDK берутся только `Client`, три транспорта и схема
`ToolListChangedNotificationSchema`. Другого места, где пакет подключался бы из `src/`, нет (`grep` по `src/`).

**Что сделано:** `@modelcontextprotocol/sdk` поднят с `^1.29.0` до `~1.31.0` в `package.json` и `package-lock.json`
(1.29.0 → 1.31.0; единственное изменение в зависимостях — допуск `@hono/node-server` `^1.19.9 || ^2.0.5`).
Путь не задействован, но версия остаётся в дереве зависимостей и в отчётах `npm audit`, а любой будущий `authProvider`
сразу попал бы на уязвимый код: дешевле поднять сейчас, чем помнить об этом потом.

**Почему `~1.31.0`, а не `^1.31.0`:** в 1.32.0 клиентские HTTP-транспорты (`StreamableHTTPClientTransport`,
`SSEClientTransport`) следуют за редиректом только в пределах того же origin; переход на другой хост или порт требует
`redirectPolicy: 'follow'` или конечного адреса (релизные заметки 1.32.0, github.com/modelcontextprotocol/typescript-sdk,
22.10.2026). Для адресов, которые пользователь вписал в `mcp.json`, это изменение поведения, и принимать его надо
осознанно, а не вместе с исправлением безопасности. Допуск `^` дотянул бы замок до 1.32.1.

**Проверка:** клиент 1.31.0 прогнан на настоящих транспортах: stdio к подставному серверу и Streamable HTTP к серверу
на том же SDK (заголовок клиента дошёл, `listTools` и `callTool` ответили). Тесты `mcp*`, `acpIdeMcp`, `acpMcpExport`, `modelDeprecation`
и `builtinModelProfiles` — 165 зелёных. Живьём в окне IDE не прогонялось.

**Не затронуто:** `test/mcp/package.json` пинует 1.26.0 — это пакет автоматизации VS Code (`code-oss-dev-mcp`), в сборку
продукта не входит; обращения к OAuth-клиенту SDK в `test/mcp/src` нет (`grep`).

**Применение:** появится собственный OAuth-клиент к MCP (`authProvider`) — взять версию не ниже 1.31.0 и передать опцию
`expectedIssuer`; токены, сохранённые до обновления, перевыпустить. Когда возьмёмся за 1.32+, решить про
`redirectPolicy` отдельным пунктом.
