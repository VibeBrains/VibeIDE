# Путь вне проекта в аргументе команды

## Случай

Агент VibeIDE (исполнитель этапа пайплайна) выполнил:

`npm run compare:brandbook -- --save /VolumES`

Скрипт по `--save` очищал каталог целиком
macOS сравнивает имена без учёта регистра: `/VolumES` — это `/Volumes`, корень всех внешних дисков
Внешний диск пользователя был стёрт почти целиком

## Почему ни одна проверка не сработала

- `analyzeShellLine` (`common/nlShellSafetyAnalyzer.ts`) судит текст строки: `rm`, `dd`, `git push -f`
  В `npm run …` удаления нет — оно внутри скрипта, и проверка его не видит
- `commandEscapesScope` у шага с границами записи ловил только `cd`, `git -C`, `eval`
  Абсолютный путь в аргументе не проверялся вовсе
- ACP (`common/acp/acpPermissionPolicy.ts`) собирал пути shell-команды только у программ «только чтение»

Общая дыра: разрушительное действие спрятано в скрипте, а цель передана путём в аргументе

## Что сделано

`common/commandPathsOutsideScope.ts` — чистый разбор путей в аргументах ЛЮБОЙ программы:
- абсолютные, `~`, `$HOME`, `X:\`, `\\server\share`, выход через `..`, значение `--opt=/path` и `-o/path`
- свой путь — в папках проекта, корне прогона или временном каталоге (`TEMP_ROOTS` из `shellRemovalScope.ts`)
- на macOS и Windows сравнение без учёта регистра — иначе `/VolumES` не узнать
- `critical` — корень диска, тома, домашней или системной папки

Где действует:
- Исполнитель этапа (`vibeSubagentRunnerService.ts`): путь вне проекта — отказ до запуска
- Основной чат (`toolsService.ts`, `_gateDestructiveCommand`): диалог «Команда работает с путями вне проекта»
  Корневой путь спрашивается всегда, даже при `vibeide.agent.confirmDestructiveCommands: false`
  `run_nl_command` теперь проходит ту же проверку: раньше разобранная из текста команда шла мимо неё
- ACP: путь вне проекта у любой программы — `outsideProject`, корневой — `irreversible` до разрешений сессии

## Чего проверка не делает

Она не знает, что скрипт сделает с путём: чтение вне проекта тоже спрашивается
Это сознательная цена: отличить `--save` от `--read` по тексту нельзя, а ошибка в одну сторону стоит диска
Вторая половина защиты — сам скрипт: правило набора `rules/security.mdc`, раздел «Каталог вне проекта — не цель для очистки»
