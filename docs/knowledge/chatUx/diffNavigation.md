# Переход по правкам после «Принять» и «Отклонить»

← [Knowledge Index](../README.md)

---

## [баг] Правка проскакивала, а следующая оставалась за экраном

**Контекст:** отзыв пользователя 08.10.2026 — после принятия чекпоинта следующий, стоящий ниже экрана, не показывался, стрелки уводили дальше него.
Критичную правку, которую надо отклонить, можно было проскочить.

**Суть:**
- `acceptDiff`/`rejectDiff` удаляют правку синхронно, и события списка приходят до возврата из вызова
- Команда с клавиатуры после этого делала `getNextDiffIdx(1)`: номер уже указывал на следующую, шаг проскакивал её
- Удаление последней правки блока шло событием «блоки изменились», а оно сбрасывало текущую на 0
- Кнопки на самой правке (`AcceptRejectInlineWidget`) никуда не прокручивали
- Каждое обновление пересоздаёт правки файла с новыми id: держаться за id нельзя, только за позицию

**Применение:**
- Перед удалением `editCodeService` шлёт `onWillResolveDiff`, командная панель запоминает место правки в списке
- Первое обновление, где список стал короче, делает текущей следовавшую правку (`diffIdxAfterResolve`, `common/diffNavigation.ts`) и показывает её через `revealLinesInCenterIfOutsideViewport`
- Команды «Принять»/«Отклонить» больше сами не шагают — это делает сервис
- Новые блоки от агента по-прежнему начинают с первой правки

**Связано:** `browser/vibeideCommandBarService.ts`, тест `test/common/diffNavigation.test.ts`
