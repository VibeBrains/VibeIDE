## [архитектура] Кадры по сменам сцен + транскрипт → один vision-запрос

**Контекст:** фича `/watch` (2026-07-17, ветка `next`): пользователь даёт ссылку/путь на видео, модель «смотрит» его целиком. Источник идеи — публичный рецепт скилла watch для Claude Code (yt-dlp + ffmpeg scene detection + Whisper); у нас Whisper заменён на уже живущий в IDE локальный STT (GigaAM), а пайплайн встроен в чат как первая по-настоящему перехватываемая slash-команда.

**Суть.** Слои повторяют рецепт голосового ввода ([[localSttSherpaOnnx]]):

- `common/video/` — контракты (`vibeVideoTypes.ts`), каталог бинарей с SHA256 (`vibeVideoTools.ts`, зеркало-релиз `video-tools-v1`: yt-dlp 2026.07.04 + ffmpeg-static b6.0 на 4 платформы), настройки `vibeide.video.*`. Чистые модули, юнит-тесты в `test/common/video/`.
- `electron-main/video/vibeVideoMainService.ts` — докачка инструментов при первом использовании (общий хелпер `electron-main/vibeVerifiedDownload.ts`, вынесен из voice) и пайплайн **дочерними процессами** (`child_process.spawn`): probe (`yt-dlp --dump-single-json`) → субтитры (`--write-subs --write-auto-subs --convert-subs srt`) → видео ≤`frameHeight`p → кадры (`ffmpeg select='eq(n,0)+gt(scene,T)',scale,showinfo -fps_mode vfr`) → при отсутствии субтитров звук в raw PCM16 16 кГц. **UtilityProcess не нужен**: внешний CLI и так не роняет IDE — воркер оправдан только для синхронных N-API аддонов вроде sherpa.
- `electron-browser/video/vibeVideoChatService.ts` — оркестратор `/watch`: vision-гейт ДО пайплайна (`isModelVisionCapable`), consent-модалка на инструменты, прогресс с отменой, STT-fallback через фасад voice, кадры → `ChatImageAttachment[]` → `addUserMessageAndStreamResponse({ images, displayContent })`. Канальный клиент — **единственная вечная подписка listen** (ловушка `ChannelClient#requestEvent`, см. [[localSttSherpaOnnx]]).
- STT-fallback: новый session-less запрос `decodeBatch` в voice-воркере; нарезка на чанки ≤28 с (= `MAX_SEGMENT_SECONDS` воркера) живёт в `VibeVoiceMainService.transcribePcm16`, и вся работа считается одной busy-периодой idle-shutdown (иначе `keepAliveSec: 0` убивал бы движок между чанками с перезагрузкой моделей на каждый чанк).

**Применение:** новый «тяжёлый внешний инструмент» в IDE = каталог в common (url/SHA256/размер) + `vibeVerifiedDownload` + consent-модалка + spawn из electron-main. Бинари НЕ бандлить: рантайм-загрузка снимает вопросы ASAR/dylib/подписи GPL-сборок.

## [архитектура] Аудио-ветка: /watch слушает подкасты и голосовые без кадров

**Контекст:** 2026-07-18 (вопрос из комьюнити): аудио-only источник ронял пайплайн в двух местах — remote-формат `bv*+ba` требует видеодорожку, а локальный mp3 падал ещё раньше, на видеофильтре стадии кадров.

**Суть.** Тип входа определяется дважды, и это принципиально разные ответственности:

- **Дешёвый хинт в renderer** — чистый `classifyWatchInput` (расширение файла/URL, `common/video/vibeVideoTools.ts`): решает, ставить ли vision-гейт (аудио-запрос без картинок не требует vision-модели) и как озаглавить прогресс («Слушаю аудио…»). Query/fragment срезаются **только у URL** — `#` легален в именах файлов на всех ОС (`?` — на unix), резать по нему локальный путь = ложный 'unknown' (поймано адверсариальным ревью 2026-07-18). Страницы платформ без расширения — `'unknown'` → консервативно как видео.
- **Вердикт в main — probe-first с tie-break'ом**: local — проба `ffmpeg -i` (выход ненулевой без output-файла — это норма, читаем только stderr-баннер; ноль Stream-строк = файл не читается → пробросить хвост ошибки ffmpeg, а не врать «нет аудиодорожки»), видеопоток с пометкой `(attached pic)` — обложка, не видео; remote — `probe.audioOnly` (все `formats[].vcodec === 'none'`) ИЛИ «проба неинформативна (generic-экстрактор не дал ни одного vcodec) И расширение аудио». **Положительное свидетельство видео всегда побеждает хинт** — иначе remote `.ogg` с Theora-видео молча терял бы видеоряд (первая версия условия `hint || audioOnly` ровно так и падала — поймано ревью).

Аудио-хвост (`finishAudioOnly`): субтитры есть → медиа **вообще не скачивается** (видео-ветка качает всегда — ей нужны кадры; аудио при готовом транскрипте — незачем); нет → `-f ba/b` (не `-x`: конвертация лишняя, PCM16 всё равно извлекает наш ffmpeg) → тот же STT-fallback. Результат несёт `kind: 'audio'` и ноль кадров; renderer собирает текстовый промпт без «что на экране» и **абортит с уведомлением**, если транскрипта не вышло совсем (нет кадров И нет текста — отправлять модели нечего); при добровольной отмене — молча, без ложных тостов (флаг `cancelRequested`; предупреждение «разбор пойдёт только по кадрам» для аудио подавлено — кадров нет).

**Батч-СТТ для /watch работает ТОЛЬКО с русским профилем — не повторять мою ошибку в доках:** fallback идёт через `transcribePcm16` → воркер `decodeBatch`, а батч требует **offline**-модель профиля. Русский — GigaAM v3 CTC (offline): тяжелее и медленнее стриминговых, **но русскому это нужно** (WER ~8.4; лёгкие модели на русском заметно врут слова — проверено 2026-07-18 в скилл-референсе: whisper small путал слова 3-мин русского вокала, medium — нет). Английский профиль — NeMo fast-conformer **streaming-only, offline-модели нет** → `transcribePcm16` бросает `no offline model for batch transcription`: английский подкаст без субтитров площадки сейчас честно абортится. Первая версия этой записи утверждала «для английского подкаста хватает NeMo streaming» — ложь, пойманная адверсариальным ревью: описанной ветки не существовало. Для английского хватило бы и лёгкой offline-модели (аналог «small достаточно для en» из скилла) — задел в roadmap. Детали моделей — [[localSttSherpaOnnx]].

**Применение:** источник «может оказаться аудио» — не городить общий детект на одном уровне: дешёвая классификация по имени для UX-решений ДО пайплайна + авторитетная проба инструментом ВНУТРИ пайплайна, и хинт может быть только tie-break'ом при неинформативной пробе, не со-решателем. Ремотный вход без расширения (страница подкаст-платформы) на non-vision модели упрётся в vision-гейт до probe — осознанная цена раннего гейта для YouTube-видео; снимать её пробой до гейта не стали (лишний сетевой запрос на каждый /watch). Обратный перекос (файл-«аудио» по имени, видео по факту — переименованный mp4) ловится **повторным** vision-гейтом после пайплайна: поздно, но вежливо — вместо жёсткого блока картинок при отправке.

## [квирк] yt-dlp игнорирует навязанный контейнер при мерже

**Контекст:** сухой прогон 2026-07-17: `yt-dlp -f "bv*+ba" -o video.mp4` на ролике с webm-дорожками.

**Суть:** при мерже видео+аудио yt-dlp выбирает контейнер сам — получился файл `video.mp4.webm`, и «фиксированный» путь протух. ffmpeg при этом читает любой контейнер.

**Применение:** всегда `-o "video.%(ext)s"` и поиск результата глобом/префиксом `video.*`; расширение не хардкодить.

## [квирк] Однокадровое видео даёт ноль кадров при обычном пороге сцен

**Контекст:** тот же прогон: статичный talking-head ролик, `select='gt(scene,0.3)'` → ноль кадров; 0.1 → один кадр.

**Суть:** scene detection меряет разницу кадров — статичный скринкаст/говорящая голова может не пробить даже низкий порог. Без якоря пайплайн возвращает пустоту и vision-запрос не из чего собирать.

**Применение:** в фильтр всегда добавлять якорь первого кадра `eq(n,0)+…`; при < 3 кадров — один автоповтор с порогом 0.1 (`RETRY_SCENE_THRESHOLD` в `vibeVideoMainService.ts`).

## [квирк] Формат showinfo различается между мажорами ffmpeg: `s:WxH` vs `s=WxH`

**Контекст:** живой CDP-смоук 2026-07-17: пайплайн прошёл все стадии, но «(кадров: 0)» — модель отвечала по субтитрам без vision. Лог main: `only 0 frames at threshold 0.3 — retrying at 0.1` и тишина.

**Суть:** регулярка парсинга showinfo писалась по выводу ffmpeg 8.1.2 (`s=320x240`), а боевой статический бинарь из зеркала — ffmpeg 6.0, который печатает **`s:320x240`** (двоеточие). Ноль совпадений → ноль кадров, при этом ffmpeg выходит с кодом 0 и jpg-файлы на диске ЕСТЬ — падения нет, тихая деградация. Двойная ловушка: сухие прогоны скилла делались brew-ffmpeg 8, поведение боевого бинаря отличалось.

**Применение:** разделитель в регулярке — `s[:=]` (уже в `vibeVideoMainService.ts`); при обновлении зеркала на новый мажор ffmpeg — перепроверить формат showinfo живым прогоном ИМЕННО зеркального бинаря, не системного.

## [правило] yt-dlp протухает — это норма жизни, а не инцидент

**Контекст:** YouTube регулярно ломает экстракторы; захардкоженный SHA256-каталог по образцу voice-моделей конфликтует с потребностью частых обновлений инструмента.

**Суть:** SHA256 зеркала гарантирует только первую установку. Дальше — самообновление: standalone-бинарь yt-dlp умеет `yt-dlp -U`; канал отдаёт команду `updateYtDlp`, а renderer вешает кнопку «Обновить yt-dlp» прямо на уведомление об ошибке скачивания (`reportPipelineError`, эвристика по подстроке `yt-dlp` в сообщении).

**Применение:** при жалобе «/watch не качает с YouTube» — сначала кнопка обновления, потом отладка. При выпуске `video-tools-v2` — новая версионная папка (`VIDEO_TOOLS_DIR`), не перезапись v1.

**Связано:** [[localSttSherpaOnnx]] — рецепт слоёв, ловушка listen, consent-модалка; `docs/knowledge/architecture/layerSplitElectronBrowser.md` — куда класть desktop-реализации фасадов.
