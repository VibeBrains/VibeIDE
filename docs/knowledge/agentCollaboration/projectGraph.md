## [архитектура] Подсистемы по Leiden, карта в два уровня, один холст на два графа

**Контекст:** 09.10.2026 владелец взял за образец graphify (github.com/Graphify-Labs/graphify): граф кода с июля строился
для агента (`code_graph`), а человек его не видел. Нужны были картина, цвета-подсистемы и отчёт.

**Суть:**
- Подсистемы — Leiden по модулярности (`common/codeGraph/communities.ts`) на связях файлов: импорт, наследование,
  вызовы, поднятые с символов на файлы. Leiden, а не Louvain: Louvain может оставить сообщество из несвязанных файлов,
  и один цвет на чужие друг другу файлы — ложь картинки. Тест проверяет связность каждого сообщества
- Детерминированно: где статья берёт случайный ход (уточнение), берётся лучший; номера подсистем — по размеру.
  Одинаковый репозиторий — одинаковая картина и проверяемый тест
- Подписи без модели: общая папка файлов подсистемы (последние два сегмента), иначе имя главного файла;
  одна папка в двух подсистемах — к подписи добавляется главный файл
- Раскладка графа попарная (O(n²) за кадр). Тысячи файлов разом окно не вытянет, поэтому вкладка двухуровневая:
  карта подсистем, клик раскрывает одну, до `SUBSYSTEM_VIEW_LIMIT` (400) самых связанных файлов.
  Соседние подсистемы остаются узлами — видно, куда ведёт, без их файлов
- Холст общий (`browser/vibeGraphCanvas.ts`, модель `common/graphView.ts`): граф документов и граф проекта переводят
  свои данные в «узел, подпись, группа, вес»; цвет группы назначает хост. У подсистем цвет — оттенок по золотому углу
  с яркостью по теме: подсистем больше, чем токенов темы

**Применение:**
- Новый вид графа — переходник в `IGraphView`, а не вторая копия холста
- Пустой граф при холодном индексе — не «связей нет»: вкладка сначала прогревает индекс (`warmIndex`) и говорит об этом
- Отчёт для человека и для агента один: `analyzeCodeGraph` + `renderReport` (запрос `report` у `code_graph`)

**Грабли живого прогона (09.10.2026, VibeIDE как проект):**
- Импорт TS ESM пишется `./x.js`, файл — `x.ts`: резолвер без этого соглашения теряет почти все связи ядра
- Исключения индекса по подстроке пути (`path.includes('out')`) молча выбрасывают `layout.ts`, `timeout.ts`, `builder/`;
  правило — целый сегмент от корня проекта (`common/indexScope.ts`) плюс `.gitignore` и `.vibe/ignore`
- Без `.gitignore` в индекс идут `.claude/worktrees` — копии репозитория, подсистемы-двойники в отчёте
- Сменили правило отбора — поднять `INDEX_SCOPE_VERSION`, иначе сохранённые индексы останутся по старому правилу

**Вызовы (09.10.2026):**
- Читаются tree-sitter, свой индекс `vibeCallIndexService`: индекс навигации включается настройкой по языкам, сканирует лениво
  и намеренно не знает TypeScript — там отвечает языковой сервер
- Связь — файл к файлу: без типов неизвестно, какая из перегрузок вызвана, известно только, какой файл объявляет имя
- Происхождение: через импорт — `inferred`; по имени — `ambiguous`; имя объявлено больше трёх раз (у метода на объекте
  неизвестного типа — больше одного) — связи нет. «Только факты» прячет все вызовы
- `this`, `self`, `$this`, `super` — не получатель: вызов на своём объекте, иначе резолвер искал бы файл с именем `this`
- Формы узлов проверяются тестом на настоящих грамматиках (`test/node/callSites.test.ts`): поддельное дерево, написанное
  по той же догадке, прошло бы и с неверным именем поля
