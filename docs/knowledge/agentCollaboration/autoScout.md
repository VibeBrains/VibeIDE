# Vibe Agents — авто-разведчик на continuation-запросах («продолжи» → разведка перед ходом)

**Задача.** На запросах-продолжениях («продолжи», «дальше», «доделай») модель обычно без контекста — ссылается на прошлую работу, которая уехала из треда. Перед основным ходом запускаем read-only разведчика (роль `explore`) по последним правкам и незакрытому плану, показываем зацепки + гипотезу в чате, пользователь подтверждает «оно / не оно».

**Ветка/коммиты:** `next`, `0474764b` (ядро+гейт) → `5cb699ab` (тумблер-форс C). Релиз v1.7.0.

## Ключевые решения (почему именно так)

1. **Триггер = A + C, НЕ B.** A — continuation-маркеры (`scoutTrigger.ts::isContinuationRequest`, regex: продолж/дальше/доделай/…, кириллица подстрокой — `\b` в JS только ASCII). C — ручной one-shot форс (тумблер-следы у инпута / флаг `_scoutNextTurnByThread`). **B (эвристика «короткий/размытый») НЕ брали** — короткий ≠ размытый («запусти тесты» короткое и ясное), даёт много ложных срабатываний и жжёт токены. Continuation — самый высокий сигнал при низком шуме.
2. **Гейт В ТРЕДЕ, не модалкой.** Новый `role:'scout'` (`ScoutMessage`) с кнопками `[Продолжить][Уточнить][Отмена]` — мягче модалки, и сама разведка уже информативна. Рендерится `ScoutComponent` в `_ChatBubble` (сайдбар-бандл — Tailwind полный, в отличие от бандла модалки).
3. **Как контекст разведки доходит до модели — БЕЗ правки конвертера.** На «Продолжить» контекст дописывается в `content` предыдущего user-сообщения (`_applyScoutContext`; `displayContent` не трогается — пользователь по-прежнему видит «продолжи»), затем `_runChatAgent` по существующим сообщениям. Конвертер (два провайдер-пути, OpenAI/Anthropic) НЕ трогали — карточка `scout` ему просто неизвестна и пропускается. Дешевле и безопаснее, чем учить конвертер новой роли.
4. **v2 «тонкий контекст».** Если в треде уже есть живой незакрытый план (`approvalState` approved/executing, есть невыполненные шаги) — разведка ПРОПУСКАЕТСЯ: «продолжи» = исполняй план, контекст уже в треде. Форс (C) этот skip перебивает.
5. **confidence-автоскип.** При `exploreReport.confidence ≥ vibeide.subagent.scoutAutoProceedConfidence` (0.85) гейт пропускается, ход идёт сразу, но плашка `scout` (state `proceeded`) всё равно постится — пользователь видит, что нашли.
6. **«Уточнить» = петля.** Ставит `_scoutNextTurnByThread` (тот же флаг, что тумблер C) → следующее сообщение разведывается заново. Петля разведал→уточнил→разведал→оно, без новой машинерии.

## Точки интеграции

- Pre-hook — `chatThreadService._addUserMessageAndStreamResponse` ПОСЛЕ коммита user-сообщения: `_maybeRunScout` → `spawnExplore` (goal из `buildScoutGoal` = запрос + изменённые файлы из чекпоинтов + незакрытый план) → вставка `ScoutMessage`. Возврат `'gate'` (short-circuit) / `'auto-proceed'` (продолжить ход) / `'skip'`.
- Контекст правок — обход `role:'checkpoint'` сообщений (`voidFileSnapshotOfURI`); незакрытый план — последний `PlanMessage` с невыполненными шагами.
- Конфиг — `vibeide.subagent.autoScout` (bool, default ON), `…scoutAutoProceedConfidence` (0–1, 0.85).

## Грабли

- **Разведка read-only, свой бюджет/таймаут** (explore-роль) — не ломает состояние и не висит вечно.
- **Loop-guard:** повторный вход не сканируется, т.к. `_runChatAgent` (не `_addUserMessageAndStreamResponse`) не проходит через pre-hook — отдельный suppress-флаг НЕ нужен (был, убран как мёртвый).
- **Пустой результат → skip:** если разведчик не нашёл зацепок, гейт не показывается (не блокируем пользователя пустой карточкой).
- Чистое ядро `scoutTrigger.ts` (тесты `scoutTrigger.test.ts`) отделено от сервисной обвязки — SRP, тестируемо из `test/common/`.
