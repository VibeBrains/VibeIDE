# Разбор внешних сервисов → паритет с VibeIDE (рабочий лог)

← [Knowledge Index](../README.md)

> **Зачем.** Владелец присылает ссылки на сервисы, мы разбираем «что взять». Частый итог — «у нас это уже есть, просто нигде не сопоставлено с известным пользователю названием». Человек, знающий сервис X, проходит мимо нашей фичи, потому что не узнаёт её. Поэтому каждый разбор фиксируем здесь (внутренний лог: паритет + лицензия + что реально ново), а **пользовательскую проекцию** — в [`docs/references-v1/vibeide-vs-alternatives.md`](../../../docs/references-v1/vibeide-vs-alternatives.md) (её показывает `vibeAlternativesComparisonContribution`, встроенный фолбэк `COMPARISON_CONTENT` держать в синхроне).

## [правило] Как разбираем присланную ссылку на сервис

**Контекст:** повторяющийся запрос владельца — оценить сервис по рамке «что взять Клоду (мой процесс) / что взять Вайбу (продукт)».

**Суть — алгоритм:**
1. Fetch + описание: что делает, механизмы, **лицензия** (copyleft-заражение = дисквалификатор заимствования кода; см. PCLink/AGPL ниже).
2. Проверить фактом (grep по `src/vs/workbench/contrib/vibeide/`), что из механизмов **уже есть** — не верить памяти.
3. Разнести: (а) уже есть → маппинг «их название → наш сервис»; (б) реально ново и нужно → roadmap-пункт; (в) не наша ниша → назвать почему.
4. **Зафиксировать здесь** (лог) + при наличии пользовательской ценности — строкой в `vibeide-vs-alternatives.md`.

**Применение:** не плодить roadmap/knowledge-записи там, где полный паритет — дублировали бы описание своих же фич. Ценность разбора паритетного сервиса — именно в **пользовательской проекции** («знаешь X? у нас это Y»), а не в новом плане.

## [архитектура] Managed-agent платформы: Multica, Paperclip — паритет с Vibe Agents

**Контекст:** разбор 2026-07-19 (Multica `github.com/multica-ai/multica`, Paperclip `paperclip.ing`). Обе — оркестрация команд AI-агентов «как компанией/командой». Проверено грепом по нашему коду.

**Суть — их фича → наш эквивалент:**

| Механизм (Multica / Paperclip) | Наш эквивалент | Файл |
|---|---|---|
| Squads (лидер роутит работу) / оргчарт-роли | subagents + оркестратор + vision-роутинг ролей + personas | `vibeSubagentRunnerService`, `vibePersonasPaletteContribution` |
| Reusable Skills в реестре + семантический поиск (pgvector) | Agent Skills + Community Skills marketplace + локальные эмбеддинги | `vibeSkillsLibraryService`, `vibeSemanticSearchService`, `repoIndexerService` |
| Autopilots (расписание → авто-issue: стендапы, аудиты) | background agent + nightly-roadmap skill | roadmap «Agent Skills», `roadmap-autopilot/SKILL.md` |
| Тикеты + append-only аудит tool-calls | persisted plans + JSONL-журнал плана + audit log | `.vibe/plans/*.plan.md`, dashboard |
| Бюджет + авто-пауза | токен-бюджет посессионный + Dead Man's Switch + статус-бар стоимости | `vibeTokenBudgetService`, `VibeDeadMansSwitchService` |
| Governance (пауза/терминация/override, одобрение) | plan-кнопки, lease, `.vibe/constraints.json` | — |
| Goal alignment (цели/миссия) | `session_goals`, `<project_rules>` | `convertToLLMMessageService` |
| Agent-agnostic адаптеры | мульти-провайдер BYOK (Claude/OpenAI/Gemini/…) через AI SDK | — |

**Что реально РАЗНОЕ (не наше по дизайну):** Multica **не имеет своего агента** — дирижирует внешними CLI (Claude Code, Cursor Agent, Codex…) через локальный демон с авто-детектом PATH. У нас агент **встроен в IDE** — противоположное позиционирование, не заимствуем.

**Что реально НОВО (единственный кандидат):** Paperclip — **денежный** per-agent бюджет ($/месяц) с авто-паузой. У нас бюджет **токенный/посессионный**. Ценность — только под сценарий фоновых агентов, жгущих деньги без присмотра; для локальной IDE под вопросом. Зафиксировано ремаркой к `vibeTokenBudgetService` в roadmap. Лицензии обе пермиссивные (Multica permissive, Paperclip MIT) → код изучаем.

**Применение:** в roadmap Multica уже была строкой-конкурентом; ничего сверх ремарки Paperclip не заводить. Пользовательская проекция — секция «Managed-agent платформы» в `vibeide-vs-alternatives.md`.

## [правило] Skales — BSL и снимок v7: репозиторий-витрина, из которого нечего брать

**Контекст:** разбор 2026-08-09 (`github.com/skalesapp/skales`, 1599 звёзд, автор-одиночка Mario Simic, Вена). Прислано с гипотезой «морда по управлению агентами» — **гипотеза не подтвердилась**: это самостоятельный десктопный агент общего назначения (Electron + Next.js 14, `~/.skales-data` = JSON + SQLite, ReAct-цикл, 180+ инструментов, отдельные приложения Android и iOS). Позиционирование обратное нашему: не IDE, а бытовой ассистент «для всех от 6 до 60+», установка двойным кликом, «ни Docker, ни терминала».

**Две причины не смотреть в код — независимые, достаточно любой:**

1. **BSL 1.1** (лицензиар Mario Simic, Change Date 19.04.2030 → Apache 2.0). Дословно запрещает использовать работу для конкурирующего коммерческого продукта без письменного разрешения; VibeIDE под это определение попадает. До апреля 2030 — только идеи, ни строки кода.
2. **Код в репозитории мёртв.** Продукт закрытый; выложенное дерево — снимок **v7** (проверено фактом: `package.json` → `"version": "7.1.0"`, март 2026), тогда как продукт идёт на **12.7.1**. Коммиты августа правят только README, CHANGELOG и SECURITY. Даже с разрешения смотреть там нечего — это прошлогодний код, который ни у кого не работает.

**Обобщение (ради чего запись):** звёзды и живая лента коммитов **не означают, что репозиторий содержит продукт**. Класс «репозиторий-витрина» — релизы, ченджлог, issues при закрытом бинаре — надо распознавать до того, как потрачено время на чтение дерева. Дешёвая проверка за один запрос: сверить `package.json`-версию в дереве с версией последнего релиза; расхождение на пять мажоров и есть диагноз.

**Что взято (обе идеи — в roadmap, реализация не начата):** пер-модельные профили бюджета инструментов (их LLM Profiles) и раздача задачи на второй компьютер + приём по Agent2Agent (их Swarm/A2A). Обе — рядом с уже открытыми у нас пунктами: «Входящий HTTP API» и каталог квирков.

**Что НЕ взято:** ширина ради ширины — Studio, соцсеть агентов Discover, Wrapped, питомцы, голосовой глаз Iris. Глубина в кодинге у них заметно меньше нашей (окно с транскриптом и диффами, без гейтов хода, детекторов дизайна и замеров), но **это суждение по README и ченджлогу — бинарь не ставился**, и повышать его до проверенного факта нельзя.

**Связано:** [[externalAgentToolkits.md]] · [[agentRunLedger.md]].

## [правило] Разбор дайджеста: скептик обязателен, и он окупается кодом

**Контекст:** 09.08.2026 разобрано 12 тем из пяти дайджестов (05–09.08) двойным проходом — разведка по источникам, затем отдельный агент-скептик с задачей ОПРОВЕРГНУТЬ, а не подтвердить.

**Результат метода:** скептик опроверг или существенно переоценил **шесть тем из двенадцати**. Причём мимо шли не факты о внешнем мире, а выводы «нам это нужно»:

- «политики для своего репозитория нет» — есть, и жёстче предлагаемой (`docs/manuals/howToContribute.md:151`);
- «агентские коммиты не помечаются» — помечаются (`scripts/vibe-commit.js:92`), а смена формы трейлера тихо сломала бы `isAgentCommit`;
- «журнал вызовов MCP наполовину написан» — живой, пишет каждый вызов;
- «id модели в аудите нет» — есть и заполняется;
- предложенный CIMD-документ **сломал бы** авторизацию: `redirect_uris` были скопированы из примера спеки и не совпадают с нашими фактическими.

**Три приёма, которые дали больше всего:**

1. **Требовать первоисточник, а не агрегатор.** Слух о продлении окна Agent SDK-кредита до 19.08 рассыпался при чтении официальной страницы поддержки: там только 15–16.06 и баннер о паузе. Механизм рождения слуха воспроизвёлся — поиск повторно выдал ту же ложную сводку. Для инцидента с Kimi первоисточник, наоборот, нашёлся и **изменил вывод**: вектор был шелл (`git clone` по открытому 443), а не веб-инструменты, то есть задуманный guard закрывал не тот вектор.
2. **Спрашивать не «правда ли это», а «что это меняет у нас».** Тема EU AI Act ст. 50 закрылась одной строкой официальной FAQ: исходный код прямо изъят из пункта 2.
3. **Проверять трудоёмкость, а не только пользу.** «Конфиг» дважды оказывался «PR в quirks»: поля сэмплинга в `providers.json` объявлены в типах и схеме, но не читаются кодом.

**Побочный улов важнее тем.** Семь дефектов в нашем коде, подтверждённых чтением: провенанс вставлял невалидный синтаксис (исправлено в тот же день), выбрасываемые поля сэмплинга, необязательное обещание `vibeide.privacy.strict`, три бумажных `[x]` в roadmap, мёртвый `isExternalRepo()`, нечитаемое `reasoning.field`, отсутствующая `workflowsSpec.md`.

**Правило:** разбор внешней новости заканчивается не списком «что взять», а грепом по своему репозиторию. Половина «новых идей» — уже написанный код, а половина проверок находит рядом настоящую поломку.

**Связано:** [[externalAgentToolkits.md]].

## [архитектура] repowise (AGPL-3.0): что взято и что опровергнуто грепом

**Контекст:** 14.08.2026 владелец прислал `repowise-dev/repowise` — «слой понимания репозитория» для агентов на Python: пять слоёв поверх одного индекса (граф на 18 языках, поведенческая аналитика git, генерируемая вики, архитектурные решения с цитатами, code health на 49 детекторах), 10 MCP-инструментов, дашборд, PR-бот без единого вызова модели.

**Лицензия решает объём заимствования:** AGPL-3.0 — код не берётся вовсе, только механика. Тот же случай, что PCLink.

**Собственный греп опроверг мой же первый вывод.** По заголовку «distill — сжатие вывода команд» я записал это в гэпы. Греп по слову `distill` дал только доки; греп по коду нашёл `commandOutputCompressor.ts` — шесть профилей (git/test/ls/docker/find/install), защитные окна вокруг ошибок, порог выигрыша, учёт сэкономленных токенов. Фича была на 70% сделана и называлась иначе. **Правило подтвердилось второй раз за месяц:** грепать надо не термин источника, а механику своими словами.

**Что реально отсутствовало (после проверки):**

- **Обратимость сжатия.** `[… +N passing tests]` вернуть было нельзя, а `truncateHeadTail` вдобавок режет СЕРЕДИНУ по символам — то есть выбрасывает ровно тот участок сборки, где стоят ошибки. Единственный способ достать подробность — перезапуск команды: дорого, а на недетерминированном прогоне даёт другой вывод. Сделано: архив сырого вывода в памяти окна + инструмент `expand_output` (с фильтром по подстроке).
- **Профили линтера, сборки и флуда поиска** — самые ходовые у нас формы вывода (`tsgo`, eslint, `rg`) шли общим проходом.
- **Дефект детекта:** `npm run <script>` целиком классифицировался как ТЕСТ (ветка ловила слово `run`), поэтому вывод `npm run typecheck` фильтровался профилем, написанным под другую форму. Решает имя скрипта, а не слово `run`.
- **Связанность правок и история починок из git.** Граф импортов не видит пару файлов, которые двадцать раз меняли вместе и ни разу порознь: между ними нет ни строки кода — потому их и забывают.

**Механики, взятые из их методики (не код):**

1. **Массовый коммит связанности не создаёт.** Коммит на сорок файлов связывает каждый с каждым — 780 «пар», ни одна ничего не значит. Порог отсечения — настройка.
2. **Починка определяется формой коммита, а не словом в заголовке.** Половина `fix:` правит опечатку в доке или подкручивает тест; считая их, «файл, который часто чинят» превращается в «файл, который часто упоминают». У них классификатор совпал с ручной разметкой 240 коммитов на 98,3% — цифра проверяемая, метод дешёвый.
3. **«Часто меняется» ≠ «часто ломается».** Первое означает лишь, что здесь идёт работа.
4. **Абсолютная шкала риска непортируема** — ранжировать надо против собственной истории репозитория. **Проверено 14.08 и НЕ подтверждено для нас:** их довод адресован метрикам формы диффа (строк добавлено, файлов тронуто), которые растут вместе с типичным размером коммита в проекте; наш `editRiskScoringService` нормирует изменение на размер файла либо использует булевы признаки, поэтому от «типичного коммита» не зависит. Перенос был бы карго-культом. **Но сама проверка окупилась впятеро** — см. запись ниже: пять дефектов, найденных арифметикой на голых числах.

**Грабли реализации (обе мои):** литерал `\0` в строке TypeScript, записанный как настоящий байт, превращает файл в бинарный для grep, а `\0` перед цифрой читается как восьмеричный escape — нужен `\x00`. И `\w`/`\b` в JavaScript определены по латинице: `\bисправ\w*\b` не совпадает ни с чем, поэтому русские коммиты-починки молча не считались бы вовсе. Поймано тестом, а не чтением.

**Что НЕ взято и почему:** 49 детекторов code health (перекрывается линтерами и нашими 65 детекторами дизайна, месяцы работы ради числа, которое у нас уже есть в другой форме), генерируемая вики (есть `docs/` + `docs_search` + бандл справки), PR-бот и публичные страницы анализа (не наш продукт), их индекс на tree-sitter (у нас свой `code_graph` с провенансом рёбер). Заявленные бенчмарки (−31,6% выходных токенов, ROC AUC 0,737) **не перепроверялись** — они про их продукт, а не про наш, и на решение «что взять» не влияли.

**Связано:** [[externalAgentToolkits.md]] · [[metricOptimizationLoop.md]].

## [баг] editRiskScoringService: пять дефектов, которые видно только вне сервиса

**Контекст:** 14.08.2026, проверка гипотезы, перенесённой из разбора repowise. Сервис решает, спросить ли человека при включённом автоодобрении правки, и не был покрыт ни одним тестом с момента появления.

**Что было сломано** (каждый пункт подтверждён прогоном, а не чтением):

| Дефект | Как проявлялся |
|---|---|
| Критический файл автоодобрялся | `.env`, `.github/workflows/*`, `package.json` давали ровно `0.5` при пороге «строго больше `0.6`» → MEDIUM → проходили без вопроса |
| Ветка низкой уверенности мертва | уверенность стартовала с `0.7`, не опускалась ниже `0.65`, порог стоял на `0.5` |
| Уровень LOW недостижим | требовалось `confidence > 0.7` строго при базовом значении ровно `0.7` |
| `/test\//` ловил `latest/`, `protest/` | подстрока без границ сегмента пути |
| Тестовый файл ПОВЫШАЛ риск | `+0.2` вопреки комментарию рядом, обещавшему «lower risk» |

**Корень один на все пять:** правила жили внутри сервиса вперемешку с `IModelService` и `IMarkerService`, поэтому не проверялись тестом. Глядя на `+= 0.5` внутри одной ветки, невозможно увидеть порог, стоящий двумястами строками ниже; собранные в один объект веса делают несостыковку очевидной за секунду.

**Правило:** решающая логика — та, от которой зависит, спросят ли человека, — обязана жить в чистом модуле с тестами. Не ради чистоты, а потому что её ошибки не видны при чтении: они арифметические и распределены по файлу.

**Второе правило:** пороги сравнивать нестрого хотя бы с одной стороны. Три из пяти дефектов — значение, попавшее ровно на границу, которая не принадлежала никому.

**Убрано:** оценка «качества модели» по подстрокам имени (`gpt-4`, `sonnet`, `pro`). Список знал `gpt-4`, но не `gpt-5.6`, то есть уверенность зависела от того, успели ли мы дописать строку в массив после релиза вендора. Замысел спасён в роадмап: качество берётся из каталога возможностей, а не из хардкода.

**Связано:** [[metricOptimizationLoop]] (тот же принцип «решает код, а не впечатление»).
