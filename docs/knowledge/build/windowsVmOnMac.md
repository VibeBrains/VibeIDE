## [грабли] Инструменты родные, цель — x64

**Контекст:** 10.10.2026, релиз 1.24.0. Windows-машины под рукой нет, self-hosted раннер снесён.
Сборка `win32-x64` поднята в Windows 11 ARM64 под UTM на Mac с M4. Порядок работы — `docs/manuals/windowsBuildOnMac.md`.

**Суть:**
- Гонять инструменты сборки как x64 под эмуляцией нельзя. При параллельной сборке встроенных расширений
  один `esbuild.exe` не завершается и держит унаследованные каналы вывода соседних сборок.
  `gulp` ждёт `git` и `microsoft-authentication` вечно: ночь простоя, 23 секунды процессора за 10 часов.
  По одному расширения собираются за секунду — зависание видно только под нагрузкой
- Правильно: Node, esbuild и tsgo родные (ARM64), цель задаётся `npm_config_arch=x64` и `VSCODE_ARCH=x64`.
  Нативные модули MSVC кросс-компилирует под x64
- npm выбирает готовые платформенные пакеты по процессору хоста; цель сборки он не учитывает.
  В поставку попал `@vscode/vsce-sign-win32-arm64`. `sherpa-onnx-win-x64` не попал вовсе: ARM64-варианта у него нет.
  Лечит `scripts/win-vm/crossDeps.mts`: по lock-файлу докладывает production-пакеты под цель и убирает вставшие вместо них.
  Dev-пакеты не трогает — инструменты должны остаться родными
- Дочерние процессы сборки не наследуют `--max-old-space-size` у gulp. На машине с 10 ГБ памяти лимит кучи Node
  по умолчанию около 2 ГБ, и бандл ядра падает с кодом 134. Нужен `NODE_OPTIONS=--max-old-space-size=8192`
- `release-windows.ps1` — UTF-8 без BOM. Windows PowerShell 5.1 читает его как ANSI, и русское тире ломает разбор.
  Запускать через `pwsh` (PowerShell 7)
- `npm ci` в машине отказывается: у `ssh2` в lock-файле записан необязательный `cpu-features` без своей записи.
  На маке тот же npm этого не замечает. В сценарии — `npm install`, lock после него возвращается из git
- InnoSetup в систему ставить не нужно: `ISCC.exe` сборка берёт из npm-пакета `innosetup`

**Применение:**
- Кросс-сборку проверять сверкой с артефактом настоящей платформы: список бинарников и архитектура каждого PE.
  Смоук-чек скрипта (версия, коммит, x64) прошёл на сборке без голосового ввода и с чужим `vsce-sign`
- Долгую фоновую сборку сторожить по росту журнала: зависший процесс кода выхода не возвращает
- Виртуальную машину гасить после сборки: 10 ГБ из 16
