# Права на исполнение в бандле: бит, который наследовался с диска разработчика

## Контекст

Фаза 1 релиза 1.13.0 (2026-08-13, macOS arm64). Артефакты собрались — DMG и ZIP на месте, — а
смоук-проверка самого приложения упала:

```
✗ Smoke check FAILED: app CLI produced no output (bin/vibeide and bin/code both failed)
```

Прямой запуск объяснил причину коротко: `permission denied` на
`VibeIDE.app/Contents/Resources/app/bin/code`. Файл лежал в бандле с правами `644`.

## Суть

CLI-шорткат для macOS собирается так (`build/gulpfile.vscode.ts`, ветка `platform === 'darwin'`):
берётся `resources/darwin/bin/code.sh`, в нём подставляются имена продукта и файл
**переименовывается** в `bin/code`.

Общий `setExecutableBit(['**/*.sh'])` в этом потоке не участвует — и не помог бы: к моменту
упаковки расширения `.sh` у файла уже нет. Значит режим брался оттуда, откуда его берёт `gulp.src`
по умолчанию, — **со стата файла на диске разработчика**.

Дальше начинается интересное:

- в индексе git файл значится `100644` — и значился так со дня первого импорта;
- на машине, где собирались прошлые релизы, у него исторически стоял `755`;
- поэтому все прошлые сборки (включая опубликованную 1.12.0) проходили, а **на чистом клоне
  сборка сломалась бы у любого**.

Мина лежала с самого начала и вскрылась только тогда, когда рабочее дерево привели к индексным
правам (`git checkout -- .` после инцидента с массовой сменой режимов).

## Применение

Чинить надо с двух сторон, и обе стороны обязательны:

1. **Бит выставляется явно в потоке упаковки** — `.pipe(util.setExecutableBit())` сразу после
   `rename('bin/code')`. Сборка перестаёт зависеть от прав на диске того, кто её запускает.
2. **Режим исправлен в индексе** — `git update-index --chmod=+x resources/darwin/bin/code.sh`.
   Shell-скрипт обязан быть исполняемым в репозитории; без этого шага чистый клон снова получит
   `644` на диске, и любой другой путь копирования повторит проблему.

Проверка на однотипные мины: `git ls-files -s | awk '$1=="100644"' | grep '\.sh$'`. Остальные
найденные скрипты — апстримные и покрыты общим правилом, потому что **сохраняют расширение** и
попадают под маску `**/*.sh`. Опасен ровно тот случай, где файл переименовывают.

## Что из этого стоит помнить дальше

- **«Раньше же собиралось» — не аргумент.** Сборка может держаться на локальном состоянии машины,
  которого нет ни у кого другого и нет в репозитории.
- **Смоук-проверка собранного приложения окупилась ценой одной строки.** Без неё в релиз уехал бы
  бандл, где `code --version` молчит: типы, тесты, компиляция и упаковка на это не реагируют
  никак — файл ведь собран и подписан.
- `gulp.src` переносит режим файла вместе с содержимым. Любое место, где файл переименовывается
  или собирается из шаблона, теряет связь с масками вида `**/*.sh` — и режим там надо задавать
  явно, а не надеяться на наследование.
