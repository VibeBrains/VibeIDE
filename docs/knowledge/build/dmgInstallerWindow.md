## [правило] Релиз под macOS собирал голый образ, а не стоковый (2026-09-13)

**Контекст:** VibeIDEA заметила в `build/darwin/` стоковые фоны VS Code с надписью `#HAPPY_CODING!`
и передала, что у VibeIDE окно установки чужое.

**Что оказалось на деле:** эти фоны в релиз не попадали вовсе. `create-dmg.ts` — путь апстрима, ему
нужны Python ≥3.10 и `dmgbuild`, и наш `release-macos.sh` им не пользуется. Релиз собирал образ голым
`hdiutil create -srcfolder`: окно открывалось списком файлов, без фона, без стрелки и без строки про
первый запуск неподписанной сборки. Для неподписанной сборки последнее важнее всего: без него macOS
пишет «повреждено», и приложение удаляют.

**Как сделано:**
- `scripts/build-dmg-macos.sh <app> <dmg>` — образ на запись, раскладка через Finder, сжатие. Только
  системные утилиты. Его зовёт `release-macos.sh`, и его же гоняет стенд на заглушке приложения:
  одна механика для стенда и релиза.
- Фон — шаблон `build/darwin/dmg-background.svg`, скрипт рисует его на каждую сборку в двухстраничный
  TIFF (1x и 2x); с 23.09 готовый TIFF в репозитории не хранится (см. раздел ниже).
  Вариант «Пульс» из знака VibeIDE: шина ЭКГ с `{ }` служит стрелкой, словесный знак
  «VibeBrains IDEs», как у VibeIDEA.
- Координаты окна и иконок — константами в скрипте рядом со ссылкой на SVG: это две половины одной
  раскладки.
- **Гейт в самом скрипте:** сжатый образ монтируется, фон сверяется с отрисованным для этой сборки по
  sha256, версия приложения внутри — с числом на фоне, и отсутствие `.DS_Store` роняет сборку — иначе
  образ у получателя откроется списком без единой ошибки.
- `create-dmg.ts` и стоковые фоны апстрима не тронуты: путь нами не используется.

**Грабли замера:**
- Первый замер `checkCentering.py` дал разные ответы на двух одинаковых плашках: −0,5 и +4. Окно
  замера начиналось слишком высоко и захватывало низ светлой папки Applications со значком ярлыка —
  светлое считалось подложкой. Со строки ниже иконки обе плашки согласились. **Разный ответ на
  одинаковых плашках — ошибка замера, а не раскладки.**
- Итог: подпись на 16 точек ниже низа иконки, по центру подложки ±0,5.

**Грабля git: двоичный файл в `build/` портится при коммите.**
- `build/.gitattributes` начинается с `* text eol=lf` и сильнее корневого для своей папки.
  Исключений в нём было два: `*.exe` и `*.dll`.
- Первый коммит фона записал TIFF с переписанными байтами переводов строк: блоб `84d6…` против
  отрисованного `cc04…`. Предупреждение git было одно — «CRLF will be replaced by LF».
- Гейт по sha256 в образе такое **не ловит**: он сравнивает фон с копией из репозитория, а после
  чистого клона испорчены обе одинаково.
- Правило в корневом `.gitattributes` не помогает — оно перекрыто вложенным. Лечение —
  `*.tiff`, `*.tif`, `*.icns binary` в самом `build/.gitattributes`, затем `git rm --cached` и
  `git add` заново и сверка `git cat-file -p :путь | shasum` с файлом на диске.
- **Любой новый двоичный файл в `build/` проверять так же.** Стоковые фоны апстрима рядом испорчены
  тем же правилом, но они не отгружаются и не тронуты.

**Проверено:** стенд на пустом `.app` с настоящей иконкой — сборка, монтирование сжатого образа,
снимок окна, замер обеих подписей. Полная релизная сборка с этим скриптом ещё не прогонялась.

## [правило] Номер версии на фоне и служебные папки в окне (2026-09-23)

**Контекст:** правило навыка `dmg-installer` (владелец, 18.09) требует номер версии прямо на фоне окна
установки: у владельца на столе лежит по два-три образа, и какой из них новее, должно быть видно из
окна. У VibeIDE номера не было. Владелец выбрал вариант «со словом» из четырёх: «версия» тусклым
тоном и число полужирным, в правом верхнем углу на одной линии со словесным знаком.

**Как сделано:**
- В SVG стоит подстановка `__VERSION__`, а не число. Скрипт берёт версию из
  `CFBundleShortVersionString` упаковываемого `.app` — число на фоне совпадает со сборкой внутри образа
  по построению. Аргументом версия не передаётся: аргумент, который надо помнить на каждом выпуске,
  однажды забудут.
- Фон рисуется на каждую сборку (`rsvg-convert` 1x и 2x → `tiffutil -cathidpicheck`) во временную
  папку. Закоммиченный `dmg-background.tiff` удалён: готовая картинка показывала бы ту версию, для
  которой её нарисовали, а гейт сверял бы две одинаково устаревшие копии.
- `rsvg-convert` (`brew install librsvg`) — единственная внешняя зависимость. `release-macos.sh`
  проверяет его до компиляции, а не после.
- Отказы: шаблон без подстановки или с двумя, версия не из цифр и точек (защита `sed` от чужих
  символов) — сборка падает с причиной. Проверено на стенде.

**Грабли — скрытые файлы в окне:**
- Finder, которому показаны скрытые файлы (у разработчиков — частый режим, `Cmd+Shift+.`), показывает
  и `.background`, и `.fseventsd`. Сами они встают в первые свободные клетки — поверх словесного знака.
- **Флаг `chflags hidden` не помогает:** при показанных скрытых файлах папка с флагом видна так же
  (проверено снимком на macOS 26.6.2). Утверждение из скрипта VibeShot, что флаг держит папку вне окна,
  здесь не подтвердилось.
- `.fseventsd` заводит система на томе, смонтированном на запись, — скрипт удаляет его перед
  отмонтированием; в сжатом образе, смонтированном только на чтение, он больше не появляется.
- `.background` уводится под холст (`BACKGROUND_FOLDER_Y`). У того, кто скрытое показывает, это даёт
  вертикальную полосу прокрутки у правого края — она не задевает ни версию, ни строку про первый запуск.
  Уводить вправо хуже: горизонтальная полоса ложится на строку про первый запуск, а для неподписанной
  сборки она главная.

**Грабли замера:** на мониторе без Retina снимок окна выходит в 1x (480×380), и `checkCentering.py`
видит в подписи 12 pt одну строку «букв»: две одинаковые плашки дали −6,5 и −12. Это ошибка замера —
раскладку правка не трогала. Мерить посадку подписей только снимком в 2x.

**Проверено:** стенд на пустом `.app` с настоящими `Info.plist` и иконкой — сборка, монтирование сжатого
образа, снимок окна; сборка с подменённой версией 9.9.9 показала на фоне 9.9.9. Полная релизная сборка
с этим скриптом не прогонялась.
