## [решение] Засев кэша, а не подмена пути — и только нужный вариант данных

**Контекст:** распознавание сканов качало языковые данные при первом использовании; без сети первый скан не
читался. Владелец решил везти русский и английский в дистрибутиве.

**Проверено фактом:**
- `tesseract.js` 7.0.0 сначала читает `${cachePath}/${lang}.traineddata` и только если файла нет, идёт на
  jsDelivr (`@tesseract.js-data/${lang}/4.0.0_best_int` в режиме LSTM, режим по умолчанию)
- Прочитанное из кэша он сам проверяет на сигнатуру gzip и распаковывает — файл копируется как есть
- В пакете `@tesseract.js-data/<lang>` два варианта: `4.0.0_best_int` (eng 2,95 МБ, rus 2,68 МБ) и `4.0.0`
  (eng 10,9 МБ, rus 8,6 МБ). Распознавателю по умолчанию нужен только первый

**Решения:**
- **Засевать кэш, а не задавать `langPath`.** С `langPath` на папку дистрибутива распознаватель перестал бы
  докачивать языки, которых там нет. Засев кладёт наши языки туда, где он их и так ищет, и ничего не отнимает
- **Вариант `4.0.0` вырезан в `build/.moduleignore`.** Оценка «+25 МБ» считала оба варианта по размеру пакетов;
  на деле дистрибутив прибавляет около 5,6 МБ
- **Код языка проверяется** до того, как станет частью пути: строка языков приходит из запроса окна

**Как проверить:** удалить `ocr-langdata` из профиля, распознать скан без сети — в логе `[VibeOcr] данные языка
rus взяты из приложения, без сети`.
