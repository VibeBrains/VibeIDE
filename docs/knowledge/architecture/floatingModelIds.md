# Плавающие идентификаторы моделей

← [Индекс базы знаний](../README.md)

## [правило] Квирк на плавающее имя — это квирк на сегодняшнюю модель (2026-09-12)

**Контекст:** квирк модели заводится на идентификатор. Часть идентификаторов каталога ведёт к
разным моделям в разные дни, и вендор не объявляет перенацеливание.

**Почему это хуже, чем звучит:** несовместимость после перенацеливания **не падает ошибкой**. Она
тихо меняет поведение — те же имена, тот же запрос, другой ответ. Единственная защита в том, чтобы
увидеть плавающий id **до** того, как на него что-то повесили.

**Две формы, обе живые** (проверено по каталогу OpenRouter 12.09.2026):
- **явный алиас** — `alias_target: { slug }`, сам id помечен ведущей `~` (16 записей);
- **датированный снапшот** — `canonical_slug`, отличный от id: `sakana/fugu-ultra-v2` разрешается
  в `sakana/fugu-ultra-v2-20260911` (294 записи).

Вторая форма многочисленнее и незаметнее: имя выглядит как обычное, никакого `latest` в нём нет.

**Как сделано:** чистая `floatingTargetOf` в `common/catalogAliases.ts` отдаёт слаг, на который
имя указывает сегодня; алиас сильнее канонического слага — он называет модель, а не снапшот.
Значение идёт тем же путём, что `modality`: каталог → оверрайды модели → список моделей, где
появляется пометка «плавающий» с подсказкой. **Ничего на нём не маршрутизируется** — вся его
работа в том, чтобы быть видимым рядом с именем.
