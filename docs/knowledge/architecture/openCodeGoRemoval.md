# OpenCode Go вынесен из встроенных провайдеров

## [решение] Go — провайдер из набора, Zen остаётся встроенным (21.10.2026)

**Контекст:** OpenCode убрал бесплатный тариф. Владелец решил (вариант Б): **OpenCode Go (`openCodeGo`) вырезать из встроенных** и оставить только провайдером из общего набора (`.vibe-defaults/providers/opencode-go.jsonc`, id `opencode-go`); **OpenCode Zen (`openCodeZen`) остаётся встроенным** — со слов постановки задачи, живой `/zen/v1/models` отдаёт бесплатные модели (big-pickle, deepseek-v4.1-flash-free, minimax-m3.1-flash-free и др.), сам запрос здесь не повторялся. Порядок встроенных: MiniMax первым, DeepSeek вторым, Zen после них.

**Раскопки перед удалением — что было завязано на `openCodeGo`** (94 упоминания в коде, из них функциональных — около десятка мест, остальное комментарии и тесты):
- таблицы провайдеров: `defaultProviderSettings`, `defaultModelsOfProvider`, `modelSettingsOfProvider` (`modelCapabilities.ts`; `openCodeSettings` был копией `openCodeZenSettings` слово в слово), `defaultSettingsOfProvider`, подпись, подсказка и заглушка ключа (`vibeideSettingsTypes.ts`), `CallFnOfProvider` (`sendLLMMessage.impl.ts`)
- главный процесс: тип `AiSdkProviderName`, набор агрегаторов, ветка транспорта с адресом `https://opencode.ai/zen/go/v1` и заголовками клиента (`aiSdkAdapter.ts`)
- каталог моделей: список провайдеров с живым каталогом и `switch` с адресом `/zen/go/v1/models` (`remoteCatalogService`, общий и `electron-browser`)
- порядок «Авто» (`autoModelFallbackProviderOrder`) и знакомство (вкладки, подсказка, условие значка «Подробнее»)
- наборы агрегаторов для зрения (`imageQAIntegration.ts`, `visionModelHelper.ts`): без правки второй из них падал бы на `settingsOfProvider['openCodeGo'].apiKey` — тип там `ProviderId` (строка), и компилятор такого не ловит
- **ничего не висело** на причудах моделей (`resources/model-quirks.json`), `modelHealthTracker`, `tokenCalibration`, `builtinProviderIdOf`: их правила привязаны к подстроке провайдера `openCode` (она есть и в `opencode-go`) или к строке-ключу, а не к списку встроенных. Тесты на этих строках остались как данные

**Старый id в каталоге причуд.** Правила провайдера в `model-quirks.json` записаны как `"provider": "openCode"` — это id до переименования 1.2.4, и сопоставление идёт по подстроке без учёта регистра. Поэтому они до сих пор работали и для `openCodeGo`, и для `openCodeZen`, а теперь работают для `opencode-go` из файла. Это стережёт тест `modelQuirksCatalog.test.ts`: у Zen и Go одни причуды, у чужого провайдера правило OpenCode не срабатывает, правил с привязкой к Go в каталоге нет.

## [проверка] Файл набора заменяет встроенного не полностью — что добавлено

Сид `opencode-go.jsonc` до сих пор был **патчем** встроенного (id совпадал, `builtinProviderIdOf` приводил его к `openCodeGo`); после вырезания он ОПРЕДЕЛЯЕТ провайдера, и всё, что встроенный делал сам, должно прийти из файла или из кода.

| Что | Было у встроенного | Теперь |
|---|---|---|
| Адрес | `https://opencode.ai/zen/go/v1` в коде | тот же `baseURL` в файле |
| Модели | каталог `/models` + выбор формата по models.dev | `fetch: true` и `static` с форматом по каждой модели (anthropic, openai-responses) |
| Ключ | поле встроенного | карточка провайдера, `OPENCODE_API_KEY` в `.vibe/.env` и слот `apiKeyRef: "opencode"` |
| Причуды моделей | правила по подстроке `openCode` | те же правила: подстрока есть в `opencode-go` |
| Заголовки клиента шлюза | в коде: `User-Agent: opencode/0.13.0`, `x-opencode-client/project/session/request` | **в файл не помещаются** (сессия и запрос меняются) — добавляются в коде по адресу: любой провайдер с `baseURL` на opencode.ai получает их сам (`common/opencodeGateway.ts`); заголовки из файла сильнее |
| Ключ, общий с Zen | у Go и Zen были отдельные поля | слот `opencode` набора (его читает и VibeIDEA) указывает на встроенный `openCodeZen` (`apiKeySlotOfRef`); до этого `apiKeyRef: "opencode"` не указывал ни на что — в наших настройках слота `opencode` нет |

Без заголовков клиента шлюз отдаёт запросы по общему пути, и MiniMax с Qwen присылают числовые имена инструментов — поэтому они нужны провайдеру из файла так же, как встроенному (см. комментарий в `opencodeGateway.ts`).

## [миграция] Что происходит у тех, кто пользовался встроенным Go

Перенос идёт при чтении настроек (`openCodeGoMigration.ts`, чистая функция над сырым состоянием), один раз:
- ключ → `dynamicProviderApiKeys['opencode-go']` (ключ, уже введённый у провайдера из файла, не затирается)
- выбор модели по функциям (`modelSelectionOfFeature`) и по ролям агентов (`modelSelectionOfRole`) → `providerName: 'opencode-go'` с тем же именем модели: каталог один и тот же, `/zen/go/v1/models`
- параметры выбора (`optionsOfModelSelection`) и правки моделей (`overridesOfModel`) → под новым id
- модели, включённые вручную (`isHidden: false`), → явные переключатели видимости `dynamicModelHidden`
- `settingsOfProvider.openCodeGo` удаляется, состояние тут же сохраняется

Выбор, указывающий на провайдера из файла, не сбрасывается, пока файл не прочитан: валидация состояния не трогает выбор динамического провайдера до загрузки оверлея. Уведомление по-русски (`openCodeGoMigrationNotice.ts`) показывается один раз и только тому, кто Go использовал (ключ, выбор или включённые модели): пустой `openCodeGo` есть у каждого профиля как стартовое значение, и сообщение о его «уходе» было бы шумом. Текст прямо говорит, что провайдер теперь приходит файлом и появляется при открытии папки проекта.

**Не перенесено:** отчёт о расходе по старому id остаётся в журнале под `openCodeGo` (история), калибровка токенов `openCodeGo:модель` пересчитается заново, потоки чата с моделью Go продолжатся на выборе по функции, а не на сохранённом id.

## [порядок] Встроенные: MiniMax → DeepSeek → Zen

Порядок ключей `defaultProviderSettings` задаёт список провайдеров в настройках (`providerNames`), вкладку «Платно» знакомства и (через `nonlocalProviderNames`) всё, что его перебирает; `autoModelFallbackProviderOrder` — порядок «Авто» (голова та же, дальше прежний порядок облаков, локальных и агрегаторов). Знакомство открывается на вкладке «Платно» (MiniMax, DeepSeek), «Бесплатно» с Zen — следом. Тест `openCodeGoRemoval.test.ts` держит голову обоих списков.

**Побочное следствие порядка «Авто»:** у пользователя с ключами и MiniMax, и Anthropic «Авто» теперь берёт MiniMax первым. Так решил владелец («выбор по умолчанию»), но это меняет поведение для тех, у кого сильного облака раньше хватало.

**Не проверено живьём:** перенос на настоящем хранилище, показ уведомления, поведение провайдера из файла с настоящим ключом OpenCode (запрос к шлюзу с заголовками клиента) — ключа с доступом к Go у нас нет.
