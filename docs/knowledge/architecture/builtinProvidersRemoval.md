## [решение] Встроенными остаются MiniMax, DeepSeek, OpenCode Zen, OpenRouter, LM Router, LiteLLM и локальные (22.10.2026)

**Контекст:** после OpenCode Go ([openCodeGoRemoval.md](openCodeGoRemoval.md)) владелец вынес из встроенных ещё одиннадцать провайдеров: Gemini, Groq, Pollinations, Anthropic, OpenAI, Mistral, xAI, Google Vertex AI, Microsoft Azure OpenAI, AWS Bedrock и «Совместимо с OpenAI API». Их подключают файлы общего набора `.vibe/providers/*.jsonc` (репозиторий VibeBrains), а в настройках они стоят сворачиваемым блоком «Свои провайдеры» после встроенных. Механизм Go обобщён: один список переездов (`LEGACY_PROVIDER_MOVES`), а не копия на каждого.

| Был встроенный | Файл набора (id) | Что пришлось добавить |
|---|---|---|
| `anthropic` | `anthropic.jsonc` (`anthropic`) | ничего: файл уже был патчем встроенного |
| `openAI` | `openai.jsonc` (`openai`) | ничего |
| `gemini` | `google-gemini.jsonc` (`google-gemini`) | включён (был `active: false`), ключ родным заголовком вместо `?key=` |
| `xAI` | `xai.jsonc` (`xai`) | ничего |
| `mistral` | `mistral.jsonc` (`mistral`) | новый |
| `groq` | `groq.jsonc` (`groq`) | новый |
| `pollinations` | `pollinations.jsonc` (`pollinations`) | новый |
| `googleVertex` | `google-vertex.jsonc` (`google-vertex`) | новый; **`params` и `auth: "google-adc"`** |
| `microsoftAzure` | `azure-openai.jsonc` (`azure-openai`) | новый; **`params`** |
| `awsBedrock` | `aws-bedrock.jsonc` (`aws-bedrock`) | новый; **`params`** |
| `openAICompatible` | `_template-openai-compatible.jsonc` + кнопка «Добавить провайдера» | файл `~/.vibe/providers/openai-compatible.jsonc` создаётся при переносе тем, у кого был адрес |

## [раскопки] Что было завязано на эти id

Функциональных мест около сотни, остальное комментарии и тесты. Ничего не висит; проверено `grep` по литералам и по `settingsOfProvider.<id>`.

- **Таблицы провайдеров** (`modelCapabilities.ts`, `vibeideSettingsTypes.ts`): `defaultProviderSettings`, `defaultModelsOfProvider`, `modelSettingsOfProvider`, `defaultSettingsOfProvider`, подписи, подсказки ключа, заглушки ключа, `apiKeyEnvVarOfProvider`. **Профили моделей Claude, GPT, Gemini, Grok, Codestral остались** (`vendorProfiles`): знание о моделях не зависит от способа подключения.
- **Провод и конечные точки** (`aiSdkAdapter.ts`): ветки `resolveEndpoint` для десяти провайдеров удалены, остался путь файлового провайдера; выбор SDK (`builtinWireSdkNpm`), особые пути Anthropic (диагностика кэша, усилие системным сообщением, ответ вендора без легаси-бета-заголовков), `store: false` у Responses OpenAI, `thinkingConfig` Gemini переехали с `providerName === 'anthropic'` на **вендора провайдера**.
- **Автодополнение (FIM)** (`sendLLMMessage.impl.ts`): у файловых провайдеров FIM был `null` («follow-up»). Без правки пропали бы Codestral (Mistral) и FIM «Совместимо с OpenAI API». Теперь у файловых провайдеров свой `sendFIM`: Mistral — родным методом `fimComplete`, остальные — OpenAI-совместимым `/completions` с ключом, заголовками и параметрами из транспорта.
- **Каталог моделей** (`electron-browser/remoteCatalogService.ts`): девять вендорских функций выбора и разбора удалены — файловые провайдеры опрашиваются общим путём (`catalogRequestOf`), он умеет и Anthropic (`x-api-key` + `anthropic-version`), и Gemini (`{ models: [...] }`). `remoteCatalogCapableProviderNames` сократился до встроенных.
- **«Авто»** (`autoModelFallbackProviderOrder`, `autoFallbackProviderIds`): порядок хранит id файлов набора вместо прежних; файловые провайдеры, которых в порядке нет, по-прежнему идут первыми, а Anthropic, OpenAI, Gemini… — на своих местах, иначе «MiniMax первым» (решение владельца 21.10) перестало бы быть правдой.
- **Эвристики по имени провайдера** (`modelRouter`, `routingCapabilityRegistry`, `modelVisionHeuristics`, `modelFamily`, `reasoningContinuity`): сравнивали `providerName.toLowerCase()` с `'anthropic'`, `'openai'`, `'gemini'`; `google-gemini` не совпал бы ни с чем. Теперь `providerVendorKey`.
- **Зрение** (`imageQAIntegration.ts`, `visionModelHelper.ts`): читали `settingsOfProvider['openAI'].apiKey` — после вырезания это `TypeError` на `undefined`, а компилятор такого не ловит (`ProviderId` — строка). Общие предикаты в `common/visionProviders.ts`; подключённость файлового провайдера — `_didFillInProviderSettings` (ключ мог прийти из окружения и в карточку не попадает).
- **Голос** (облачная диктовка Gemini) берёт ключ у провайдера `google-gemini` (`getResolvedApiKey`), а не у несуществующего `settingsOfProvider.gemini`. **Векторы** (`vibe.embeddings.provider`) принимают `openai`; прежнее `openAI` приводится.
- **Таймаут первого токена** (`aiSdkAdapter.ts`): все файловые провайдеры получали срок агрегатора; Anthropic, OpenAI, Gemini… вернулись на срок облака, а «Совместимо с OpenAI API» и Pollinations остались агрегаторами.
- **Корпоративный шлюз через окружение.** `ANTHROPIC_BASE_URL` и `OPENAI_BASE_URL` читал встроенный; теперь их читает файловый провайдер вендора, пока адрес в файле остался вендорским (`baseURLFromVendorEnv`) — адрес, переписанный в файле, сильнее окружения.
- **Ничего не висело** на причудах моделей (`resources/model-quirks.json`): правила провайдера привязаны к подстроке `openCode` и `kimi-code`, а не к вырезанным id.

## [проверка] Файл набора заменяет встроенного не полностью — что добавлено

Seeds `anthropic`, `openai`, `xai` до вырезания были **патчами** встроенных (id совпадал, `builtinProviderIdOf` приводил его к `openAI`); теперь они ОПРЕДЕЛЯЮТ провайдеров, и всё, что делал встроенный сам, должно прийти из файла или из кода.

| Что | Было у встроенного | Теперь |
|---|---|---|
| Таблицы моделей (профили Claude/GPT/Gemini) | `modelSettingsOfProvider[<id>]` | `vendorProfiles`; файловый провайдер выбирает таблицу по **вендору**: id в любом написании или родной адрес (`providerVendor.ts`) |
| Модели, которых таблица не знает | `defaultModelOptions` (инструменты через XML) | вендорская таблица, затем общий разбор по имени (`aggregatorOpenAIFallback`), как у любого файлового провайдера — инструменты включены |
| Провод | `builtinWireSdkNpm(providerName)` | то же, но по вендору |
| Ключ из окружения | `apiKeyEnvVarOfProvider` | `apiKeyEnv` в файле + `vibeEnvApiKeysContribution` |
| Поля карточки: регион, проект, ресурс, версия API, адрес, заголовки | поля встроенного | **`params`** файла (см. ниже) |
| Токен Vertex | `getGoogleApiKey()` в ветке встроенного | `"auth": "google-adc"`: та же функция в ветке файлового провайдера |
| Список моделей | вендорская функция каталога | `catalogRequestOf` по протоколу файла |
| Пользовательские модели (`addModel`) | запись в `settingsOfProvider[id].models` | `dynamicCustomModels[id]` + явный переключатель видимости |
| «Обновить каталог» | `refreshRemoteCatalog` | перечитывание файловых провайдеров |

**Что было ограничением формата и расширено.** Минимально и с тестами (`vibeProviderParams.test.ts`, `providerVendor.test.ts`):
- **`params`** — поля карточки, подставляемые в `baseURL`, `models.fetch`, значения `headers` и `query`. Значения хранятся в настройках IDE (`dynamicProviderParams`), не в файле: засеянный файл общий для всех проектов. Необязательные параметры (`optional`), заголовки одним JSON-полем (`as: "headers"`), умолчания (`default`). Без обязательного параметра провайдер **не настроен**: транспорт не строится, моделей нет.
- **`"auth": "google-adc"`** — токен Google OAuth вместо ключа. Статический ключ тут невозможен: токен живёт около часа.
- Оба расширения знает только VibeIDE. VibeIDEA прочтёт `{region}` в адресе как есть; хендофф ей положен в память (см. roadmap).

**Что осталось за форматом и сознательно не терялось.** Формат по-прежнему не умеет подстановки имени модели в адрес, поэтому Azure ходит на **v1 API** (`/openai/v1`, развёртывание — в поле `model`, ключ заголовком `api-key`), а не на `/openai/deployments/<имя>/…?api-version=…`, как прежний встроенный. Это отклонение от старого пути; оно сверено с документацией Azure и **на живом ресурсе не прогонялось** (ключа Azure нет). Прежнее поле `region` у Bedrock код отправки не читал — в параметры не переносится.

## [миграция] Что происходит у тех, кто пользовался встроенными

Перенос идёт при чтении настроек (`providerMigration.ts`, чистая функция над сырым состоянием), один раз, для всех одиннадцати:
- ключ → `dynamicProviderApiKeys[<id файла>]` (введённый у файлового провайдера не затирается);
- значения полей → `dynamicProviderParams`: регион и проект Vertex, ресурс Azure, адрес Bedrock-шлюза (к адресу без `/v1` дописывается, как делал прежний код), адрес и заголовки «Совместимо с OpenAI API». **Умолчания встроенного не переносятся** (регион `us-west2`, заголовки `{}`): человек их не вводил. Версия API Azure не переносится (файл ходит на v1);
- выбор модели по функциям и ролям → тот же `modelName` у провайдера из файла; параметры выбора и правки моделей — под новым id;
- включённые вручную модели → явные переключатели видимости; добавленные самим человеком (`custom`) → список своих моделей провайдера;
- `settingsOfProvider.<прежний id>` удаляется — **и там, где id файла тот же** (`anthropic`): запись старой формы выглядела бы заготовкой файлового провайдера;
- тем, у кого был адрес «Совместимо с OpenAI API», создаётся `~/.vibe/providers/openai-compatible.jsonc` (определение с `{endpoint}`; значения уже в параметрах), фоном после старта окна, если такого файла ещё нет.

Уведомление по-русски показывается один раз и **только тому, кто что-то делал**: ключ, значения полей, выбор, включённые или свои модели. Пустые стартовые значения есть у каждого профиля, и сообщение об их «уходе» было бы шумом. Текст прямо называет, где теперь провайдеры (Настройки → Облачные провайдеры → «Свои провайдеры») и что делать, если провайдера нет в списке.

**Не перенесено:** отчёт о расходе остаётся в журнале под прежним id (история), калибровка токенов `<прежний id>:модель` пересчитается, потоки чата со старым id продолжатся на выборе по функции. Ссылки на модель в настройках и файлах (`openAI/gpt-5`) находят провайдера из файла сами (`canonicalProviderId`).

## [риск] Комплектный слой — зачем он и чего стоит

**Проблема.** Файл набора появляется в проекте только после засева. Без него нет ни первого запуска без папки, ни окна без проекта, ни знакомства; а проект, засеянный до появления `groq.jsonc` и `mistral.jsonc`, получил бы пустой список, хотя ключ перенесён. Для Go это принято («откройте папку»), для основных провайдеров — нет.

**Решение.** Десять файлов (`BUNDLED_PROVIDER_IDS`) берутся из зашитого манифеста набора и стоят **под всеми слоями на диске** (`bundledProviders.ts`); при старте применяются синхронно, до чтения файлов, поверх кэша — иначе выбор модели Anthropic в первые мгновения считался бы выбором пропавшего провайдера и сбрасывался. Файл на диске перекрывает копию поле за полем.

**Цена.** Удаление файла провайдера копию не убирает — выключать записью `active: false` в своём `providers.json`. Остальные файлы набора (Kimi, Z.ai, Qwen…) по-прежнему только засев. И второе: проект, засеянный раньше, держит **устаревший `google-gemini.jsonc` с `active: false`** — он перекрывает включённую копию, пока человек не применит обновление окружения (команда «Показать новое в окружении из релиза»); уведомление об этом показывает сам засев при открытии проекта.

## [порядок] Интерфейс

- **Настройки → Облачные провайдеры.** Встроенные карточки сверху (MiniMax, DeepSeek, OpenCode Zen, OpenRouter, LM Router, LiteLLM), под ними блок «Свои провайдеры» со счётчиком, сворачиваемый (состояние запоминается: `CUSTOM_PROVIDERS_COLLAPSED_KEY`) и с кнопкой «Добавить провайдера». Кнопка спрашивает имя, копирует образец набора из зашитого манифеста в `.vibe/providers/<id>.jsonc` проекта (без папки — в `~/.vibe/providers/`) и открывает файл. Раньше блок файловых провайдеров стоял **над** встроенными; встроенные в свёрнутую «складку» больше не прячутся — их шесть.
- **Карточка файлового провайдера** показывает имя из файла (`name`), поля `params` (регион, проект…) над полем ключа, у Vertex вместо ключа — статус входа Google; недостающие обязательные поля названы.
- **Знакомство.** Вкладки без вырезанных: «Бесплатно» — OpenCode Zen и OpenRouter; «Платно» — MiniMax, DeepSeek, LM Router; «Облако / другое» — LiteLLM. Описание вкладки «Платно» говорит, где Anthropic, OpenAI, Gemini и остальные.

**Побочное следствие порядка «Авто»** не изменилось относительно 21.10: у пользователя с ключами MiniMax и Anthropic «Авто» берёт MiniMax первым.
