# Превью Vibe Server: выбор элемента кликом (inspect) → заготовка правки в чат

← [Knowledge Index](../README.md)

## [архитектура] Труба «страница → хром → renderer» вместо WS и main

**Контекст:** фича «клик по элементу превью → селектор+правка в чат» (2026-07-18, next; запрос двух спикеров митапа вайбкодеров — roadmap «Идеи со встречи»). Нужно было доставить событие клика из iframe-страницы превью в renderer-сервисы.

**Суть:** WS-канал live reload (`/__vibe_server_reload`) — **однонаправленный** (main только broadcast'ит; обработчиков входящих на `wss` нет), а ProxyChannel `IVibeServerMain` — без событий main→renderer. Правильная труба уже существовала: инжект-скрипт → `parent.postMessage({__vibeBrowser:…})` → webview-хром → `vscode.postMessage` → `VibeBrowserManager._onMessage`. По ней уже ходят nav/console/scroll/external — inspect поехал тем же путём (`'inspect'`/`'inspect-cancel'`), main-процесс и WS не тронуты вообще.

**Применение:** новое событие из страницы превью = три точки: `injectReloadScript.ts` (пост), хром в `_buildHtml` (ретрансляция), `_onMessage` (case + Emitter). В main лезть не надо.

## [квирк] Cross-origin: селектору — можно, скриншоту — нельзя

**Суть:** инжект-скрипт живёт в origin страницы — DOM, селекторы, outerHTML, координаты доступны без ограничений. А вот снять картинку блока хром не может: canvas-capture чужого origin в webview заблокирован (блокер VS.6). Путь для скриншота — нативный `webContents.capturePage` в electron-main + crop по rect от инжект-скрипта (координаты пересчитывать с учётом responsive-пресета превью).

**Применение:** заготовка правки едет текстом (селектор+фрагмент HTML+файл:строка) — этого достаточно агенту; скриншот — отдельная задача, не блокирующая фичу.

## [квирк] Порядок capture-слушателей: window бьёт document

**Контекст:** в инжект-скрипте уже был document-level click-listener (capture) для внешних ссылок — при активном inspect клик по `<a>` уходил бы в «открыть внешне» раньше пика.

**Суть:** capture-фаза идёт сверху вниз: `window` → `document` → … Слушатели inspect повешены на `window` (capture) — срабатывают раньше document-хендлера и глушат его `stopPropagation()`.

**Применение:** перехват «раньше всех» в инжект-скрипте — только `window` + capture; новые document-хендлеры конкуренции не выдержат.

## [правило] Селектор — кандидат, не истина; только static-runtime

**Суть:** (1) селектор строится по ЖИВОМУ DOM — на JS-мутировавших страницах `nth-of-type` может не совпасть с исходником, файл:строка ищется по якорю (id/класс/тег) и подаётся как кандидат; при SPA-fallback — пометка «предположительно». (2) В devServer/Docker инжекции нет (iframe смотрит на чужой dev-сервер), классы бывают трансформированы (CSS-модули, Tailwind JIT) — кнопка честно disabled, а не «работает иногда». (3) Классы в селекторе экранируются `CSS.escape` (иначе `md:flex` ломает селектор).
