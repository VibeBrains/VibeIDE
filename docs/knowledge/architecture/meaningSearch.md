## [архитектура] Настоящие эмбеддинги в индексе проекта

**Контекст:** 09.10.2026 гибридный поиск индекса с мая ни разу не получил вектора.
Слот `IAiEmbeddingVectorService` в VS Code заполняет Copilot, у нас его не заполнял никто.
Семантический поиск стоял на «мешке хешей» `vibeSimpleTextEmbedding` и пустом `IVectorStore`.

**Суть:**
- Источник один — `IVibeEmbeddingsService` (`common/embeddings/embeddingSource.ts`, реализация в `electron-browser/`).
  HTTP идёт в главном процессе (`vibe-channel-embeddings`): там же прокси, что у моделей, и ключ из `apiKeyEnv`
- По умолчанию Ollama с `embeddinggemma`; облако — по id провайдера, код фрагментами уходит ему.
  onnxruntime отклонён: плюс 50 МБ на платформу ради того, что Ollama уже умеет
- Источник сам регистрируется поставщиком `IAiEmbeddingVectorService`, но индекс ходит к нему напрямую:
  у общего сервиса ожидание поставщика 10 с
- Векторы — не в JSON индекса: 10k файлов дают до 80k фрагментов, JSON весил бы сотни МБ.
  Отдельный файл `codebase-index.vectors` (`VIBEVEC1`, Float32), 256 чисел (Matryoshka-обрезка + нормировка),
  до 8 фрагментов на файл, отпечаток текстов — неизменённый файл не пересчитывается
- Кандидаты по смыслу ищутся по всему индексу и сливаются с BM25 через RRF (k=60).
  Раньше векторы только перевзвешивали кандидатов BM25: файл без общих слов с запросом не находился никогда
- Секреты вырезает источник, а не каждый вызывающий: облачный провайдер получил бы их, локальный — сохранил в векторах

**Применение:**
- Новый потребитель векторов — через `IVibeEmbeddingsService` и `state.ready`, с запасным путём без векторов
- Ключ кэша запроса включает модель: смена модели не отдаёт старые векторы
- Обрезка до 256 честна только для Matryoshka-моделей (embeddinggemma, text-embedding-3) — оговорено в описании настройки
- `QUERY_TIMEOUT_MS` (150 мс) покрывает только BM25; вектор запроса считается до него
- Приватный режим «офлайн» не глушит локальную Ollama; облако без сети отказывает само

## [грабли] Загрузка модели Ollama и предложение её скачать

**Контекст:** стенд 09.10.2026, чистый профиль, Ollama без модели.

**Суть:**
- `POST /api/pull` с `stream: false` молчит до конца загрузки, а `fetch` в Node (undici) ждёт заголовков 5 минут.
  Загрузка 600 МБ обрывалась ровно на 5m0s, Ollama писала 500, наш общий тайм-аут в 60 минут до дела не доходил.
  Решение: `stream: true`, строки NDJSON складываются по слоям (`common/embeddings/ollamaPull.ts`),
  тайм-аут — по затишью, окну уходит событие `onPullProgress` на каждый целый процент
- Тостов видно не больше трёх, а обычный тост убирается по таймеру и скрытым. На запуске уведомлений шесть,
  и предложение скачать уходило в центр, не показавшись. Предложение, на которое нужен ответ, — `sticky`
- `IVibeideSettingsService.onDidChangeState` срабатывает на любое изменение любого провайдера, по нескольку раз
  в секунду. Подписка «на всё» гоняла перепроверку Ollama каждые ~5 с: подписываться на ключ того, что важно

**Применение:**
- Долгий HTTP из главного процесса — потоком: заголовки приходят сразу, тайм-аут считается по затишью
- Проверка «уведомление показано» по DOM центра ненадёжна: список виртуальный, в DOM только видимые строки
