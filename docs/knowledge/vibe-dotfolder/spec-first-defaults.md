Засев Spec-First-обвязки в `.vibe-defaults/`, сверка со сторонними фреймворками, анти-дубль нативных фич.

## [defaults] Spec-скиллы уже засеяны — добавлять надо триггер, не новые скиллы

**Контекст:** разведка курса «AI-Архитектор» (Revelux AI, alexmagnier.ru) — продаёт Spec-First (задача → PRD → код) + оркестратор с агентами-специалистами. Запрос: взять для VibeIDE и в засев `.vibe`. (2026-07-13)

**Суть:** в `.vibe-defaults/skills/` **уже** лежит зрелая Spec-First-цепочка: `spec-driven-implementation` (оркестратор) → `write-product-spec` (`PRODUCT.md`, поведение нумерованными инвариантами) → `write-tech-spec` (`TECH.md`, реализация с `файл:строка`) → `implement-specs` (сборка, «спеки и код в одном PR»). Новый `write-spec` + `templates/prd.md` были бы **дублем** — не создавать (правило «мержить, не плодить»).

**Реальный пробел** (нашёлся через `grep -rl spec-driven .vibe-defaults/rules/` → пусто): скиллы есть, но **ни одно правило не делает их рефлексом**. Добавлено `rules/spec-first.mdc` (`alwaysApply:false`; триггеры «фича/feature/реализуй»): существенная работа → спека до кода; не блокирует (приоритет пользователя выше, как в `pipeline.mdc`). Плюс тонкие скелеты `PRODUCT.skeleton.md`/`TECH.skeleton.md` в `references/` скиллов.

**Сверка со Spec Kit / Addy Osmani:** наши скиллы на уровне или чище [GitHub Spec Kit](https://github.com/zhu1090093659/spec_driven_develop) в авторинге документов (PRODUCT/TECH split, проверяемые инварианты). То, чем Spec Kit силён сверх этого — **task-трекер (MASTER.md), adaptive drift-control, кросс-сессионность** — у нас **уже закрыто нативно** (персистентные планы, tool-drift pause, авто-разведчик, чекпоинты). Поэтому в `spec-driven-implementation` добавлен явный запрет заводить параллельный MASTER.md — иначе агент, начитавшись сторонних гайдов, продублирует продукт markdown-трекером.

**Что НЕ взяли из курса:** геймификацию (XP/уровни — не для IDE), генераторы КП и «диагностические звонки» (продажи агентства, не код), их проприетарные тексты 68 артефактов (пейвол/копирайт — только идеи/структура).

**Грабля:** новые файлы в `.vibe-defaults/` попадают в засев только после `npm run gen:vibe-defaults` (ре-ген `vibeDefaultsManifest.generated.ts`). Проверка: `grep -c "<имя-файла>" <манифест>`.

**Применение:** прежде чем «добавить скилл/шаблон» по мотивам внешнего фреймворка — `grep` по `.vibe-defaults/`, нет ли уже эквивалента; недостающим часто оказывается wiring (правило-триггер), а не контент.
